# Case 目标、Gap 与必需保障

选择或重新界定 Gap 时读取。Case 目标和授权决定要完成什么；场景不变量定义责任范围，候选可来自任何真实证据；Gap 是当前目标中尚未成立的具体结果；Loop 用工作和证据改变状态，再重新选择。

## 发现问题与比较

从原任务、用户增量、相关长期预期、当前事实、执行反馈、依赖、外部条件和不变量判断综合发现问题。逐项考虑当前不变量是必需动作，业务 Gap 应说明相关 invariant_refs，但不按不变量数量生成 Gap；控制与恢复义务可以不映射业务责任。范围外问题保留提示，不转成当前 Case 必须清零的义务。

先审视 Case 内部的独立问题，再结合完整 persisted catalog 比较；列出其他 Case 均延期，不能替代当前 Case 内部的判断。已持久化的 Gap 也要重新审视边界。“只有一个已记录 Gap”和“用户授权完整实施”都不能证明该 Gap 粒度合理。只记录实际发现的 fresh candidates，不为满足数量制造候选。

开轮用现有 goal、reason、priority_basis、evidence_required 和 selection trace 明确：

- 尚未成立的具体结果、缺少什么依据或行动，以及它成立后改变什么。
- 为何当前优先：相较其他合格候选，它如何解除关键阻塞、减少重大返工或产生直接价值；用影响、风险、不确定性与依赖解释。
- 哪项证据足以接受本问题的结论。
- 已知相关问题中哪些本轮暂不解决，以及如何保留。

不变量 required 表示必须考虑，不提供固定执行顺序；threatened 也不自动压过所有其他候选。全部不变量 upheld 不替代原任务验收，项目级其他问题也不自动阻止本 Case 完成。

先依 snapshot.state_definition 检查局部前置与共享依赖。剩余未知若会改变本次外部行为、关键约束或验收标准，就先承接对应前置；否则说明局部独立依据，不以文档是否齐全阻塞推进。再在合格候选中比较推进价值。纵向对象可以是模块、业务切片或技术点；横向责任由当前不变量覆盖，两者组合界定 Gap，不要求整个 Case 同步过阶段。选择说明见 [selection-assessment.md](selection-assessment.md)。

## 独立性与粒度

正式确立前，逐项核对准备接受的重要决定：它来自明确要求、仍有效的既有约定，还是 Agent 新补充的判断；其成立条件和证据是什么；哪个未回答的问题可能改变它。条件性要求保留条件，尚未证实的假设保留为过程材料。结果目标明确，不意味着实现该目标所需的全部决定都有依据。

先判断这些依赖，再比较优先级。若另一候选正在回答本决定所需的关键问题，本决定尚不具备正式确立资格，不能以“先确定验收更重要”绕过。已有充分依据或能说明不受该未知影响的局部结论仍可推进，不设置全 Case 的取证阶段。

判断候选是否包含需要分别取舍的决定，或者某个结果成立后，应当依据新证据重新决定另一项工作。如果是，选择其中当前最关键的一项。不得用“整体实现与验证”掩盖这些独立关键问题；没有这些问题的小任务可以只有一个普通 Gap。

独立处理应说明所保护的判断：会改变后续方向、影响多个对象、需要独立取舍或授权。困难和重要性提示应收紧边界，但工作量大不等于要拆多个 Gap。仅能分别测试、涉及多个文件或多个领域，不足以要求拆分。子结果共享目标、前提和验收边界时可以合并，不能只因题材相近而合并；合并仍须遵守场景的事实顺序。为同一结论读取资料、实现、验证并同步事实载体可以同轮；低风险的已知方案不必人为增加调查、设计、实现阶段。同一 Gap 可以 partial 跨轮，不以轮数或工作量定义粒度。

例如：统一配置在多个共用入口的传递可共同证明同一个契约；若已有线程的权限回收或工具恢复仍存在独立关键不确定性，先比较是否应以真实协议证据解决该问题。页面可用不能证明线程恢复兼容，不能只因二者同属一个功能而合并。已有充分因果证据的小修复可以直接实现，不必重新创建根因调查 Gap。

共享一个标题或契约不代表共享前提。合并前检查子结果之间是否存在“先查清 A，才能决定 B”的重要依赖；存在时在取证与下游决定之间划界。常规核对、试验或低风险比较仍可服务同一既定局部结果，不要求逐条结论创建 Gap。

## 执行中重新判断

新证据改变依据时，对受影响的具体主张逐项说明：原主张及条件、新证据、仍成立或需调整或尚未知、依赖它的义务如何处理。既要看用户目标，也要看 Agent 先前补充的行为和方案；目标不变不能证明这些补充仍有效。需要调整正式预期时保留相应 Gap，在负责该结论的 Gap 中维护权威载体，之后再选择依赖它的正式兑现。若证据仅说明某条件未触发，说明适用范围即可，不制造无实质变化的预期修改轮次。

新信息用于证明当前结论时继续使用；暴露独立问题时记录事实及必要候选，不自动顺带解决。当前问题成立即提交；未成立如实 partial，fresh-read 后重选。取证若始终服务同一既定结果可以在其边界内完成；若需要另行选择的独立结果或重要决定首次具备条件，或新证据使已接受预期、关键前提、责任或验收边界需要重定，就在此处提交重选，不用探索标签代替判断。同一验收内的动作依赖就绪和约束内的方法调整可继续；重要独立因果问题按场景规则处理，不以常规排障为由包揽。新知识、本轮结束和新建 Gap 是不同事件。

若发现已持久化 Gap 过宽或前提失效，显式说明旧边界的问题及未完成义务。使用现有可信 transition 取消不再合适的 Gap，并新增有当前事实支持的结果型 Gap；在取消 reason/outcome 和新 Gap derived_from 中记录替代关系，必要时同步现有 impact 的 gap_refs。取消不是验收完成，不撤回用户需求，不丢弃未完成问题，不预测未来执行链。仅因当前 Gap 尚未完成不得取消换号。

重新界定后提交并 fresh-read，再独立选择，不在同轮以整理边界为由实施所有新 Gap。Agent 判断重新界定的必要性和义务保真；Ledger 校验引用、状态及原子提交，Runtime 不按文本、数量、时长或文件路径推断拆分。

## 完成前核对既有义务

将原 Gap 的 goal、reason、evidence_required，以及历轮接受的相关预期和保留义务，与本轮 acceptance 和证据对照。对范围或验收有变化的部分，必须说明原义务的去向：

- 已兑现：给出与原主张相称的证据。
- 条件不适用：给出证明条件未触发的事实及适用范围；没有实现某行为不构成不适用依据。
- 已调整：引用有权限、有依据的正式变更及更新后的权威事实，不能在实现 Gap 顺带改变预期。
- 未完成：保留原 Gap 的 partial，或按重新界定规则保留剩余义务及替代关系；取消或转交不算兑现。

无需重抄全部历史或新建逐项表单；未变部分可引用已有记录，变化部分必须可追溯。将对应关系写入现有 selection_assessment、事实、resolution 与 evidence；Completion Review 用同一方法核对授权目标及跨轮义务。新的验收清单、测试通过或 invariant 的总体 upheld 都不能代替这项核对。
