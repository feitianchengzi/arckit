# Case 结果验证证据归档

检查结果是否符合预期，以及保存或迁移相应验证证据前读取。本约定由 Ledger skill 维护、Agent 执行；不增加 Runtime 路由、事实分类推断或新的状态协议。

## 用途边界

本目录管理“结果是否符合预期”的验证证据。先判断本次活动的目的，再确定产物归属，不按截图、日志或 trace 等文件类型统一收纳。

对照明确预期检查实现、设计或修复结果，保留通过、失败及限制的记录。失败的验证结果同样留在 evidence；持久引用的来源必须具备相应保留期限。

## 选择载体

1. 先确认需要证明的主张及已有证据。源码、可重复测试、正式定义文档和受支持的持久宿主引用足够时直接引用，不复制它们，不强制生成实施报告或独立自查文件。
2. 只有需要独立留存的 Case 结果验证产物才新增文件，例如预期与实际的对照、测试运行结果、截图、验证限制或无法由已有载体表达的复核依据。稳定产品、交互、视觉和技术预期继续由对应正式载体维护。
3. 新增文件统一放在项目根目录下的 `arckit/cases/evidence/<case-id>/`。使用 trusted Case 创建回执中的完整 canonical Case id，不使用标题或自行预测编号。按实际需要建目录，不预建空目录或固定报告套件。
4. 尚未建立 Case 时，结果验证输出暂存操作系统临时目录；成为 Case 持久证据前，先取得真实 Case id，再将必要且脱敏的结果归档。临时路径不能提交为持久 evidence。

## 结果验证上下文与核验闭环

entry 由同一 Agent 在结果验证前明确以下上下文，所选领域能力和工具沿用；这是执行约定，不增加 schema、skill 隐式调用或 Runtime 参数协议。

- **主张与依据**：要验证什么、依据哪项明确预期、需要哪些观察；不为了生成文件而取证。
- **归属与输出**：已有可信 Case 时，本次验证文件写入 `arckit/cases/evidence/<case-id>/<run>/`；`<run>` 使用时间或其他不冲突标识，仅按需创建。无 Case 时用独立系统临时目录，不伪造 Case id、不为存放文件创建 Case。
- **执行与读取**：配置工具的输出参数或环境变量后再运行，记录命令、被验证版本、必要环境和场景。实际读取日志/报告或打开截图，对照预期说明观测、差异和限制；文件生成成功不代表验证通过，静态图像不能证明未执行的行为。
- **保留与引用**：读取确认后仅保留支撑符合性结论或复核所需的结果；引用记录验证对象、条件和结论，可并入已有记录，不强制另写报告。未读取的产物标记为未核验；失败证据不能被成功重跑静默覆盖。已经被状态或文档引用的证据不能随临时清理删除。

用于结果验证的截图、录屏、日志、trace、测试报告和运行快照遵守同一规则。原型、测试源码、测试夹具、人工维护的预期基线和用户明确要求交付的图片继续归所属载体管理；正式产物不能运行时依赖本地 Case 证据。将运行结果采纳为长期基线或正式素材时，明确用途变化及授权依据，再维护目标载体。

新建或修改结果验证脚本时，使运行输出目录可由调用者指定；复用脚本保留在源码所属位置，不硬编码某个 Case、某轮目录或向源码旁写入截图/日志的默认值。没有指定输出位置时使用临时目录，并回报实际位置。既有工具只能写固定位置时，优先使用隔离工作目录，随后读取并归档必要结果、清理本轮生成的临时副本；不覆盖或清理用户已有文件。不能满足时明确报告限制，不能悄悄把运行产物变成正式资产。

证据在本项目默认属于本地执行数据，现有 `/arckit/cases/` Git 忽略规则覆盖其目录；归档不等于上传、备份或跨机器可用。跨机器交接需要接收方可访问的持久证据或可重现步骤，不能把仅本机存在的路径宣称为已共享证据。

## 组织与引用

- `<case-id>` 目录随 Case 关闭保留，不在 active/closed 之间移动；跨 Case 复用时直接引用原证据。
- 文件名表达实际验证对象或用途；多轮结果需要区分时使用已知 Gap id、时间或明确版本，已被接受状态引用的结果不得覆盖成另一轮结果。
- 报告只保留必要的结论、执行条件、验证范围、结果和限制，并链接底层证据。代码或报告的存在本身不能证明测试通过。
- 提交前确认文件存在、引用可解析、证据内容与主张一致。引用使用相对项目根目录的路径；必要时补充版本或内容摘要以明确对应实现。
- 一次性 transition 输入、缓存、完整对话转储、凭据及无关原始数据不归档；持久结果只保留必要内容并脱敏。宿主审计记录按 transition transport 契约使用持久 opaque ref。
- 需要持久保留的 Case 结果验证证据统一归入此目录，不另建顶层证据目录。

## 历史证据与迁移

新增归档约定不追溯改写已接受的历史事实。迁移前查清 Case、Project、Iteration、历史 Round 和普通文档的引用，并确认可信接口能否保持历史语义及引用可达性；不能直接批量替换 canonical ledger 文本。

尚无适用的可信迁移能力时，保留仍被引用的旧文件，报告迁移缺口；新证据使用新目录。未被任何状态或文档引用的旧产物可在核实归属后移动到对应真实 Case 目录。只有迁移后的全部引用可达、内容保持一致且不破坏历史审计时，才能移除旧位置。
