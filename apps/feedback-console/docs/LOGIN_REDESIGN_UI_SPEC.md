# 登录流程重设计 - UI 设计规范文档

## 📌 设计概览

本文档详细描述了基于验证码登录的新认证流程UI设计规范，包括页面布局、组件设计、交互流程和视觉规范。

---

## 🎯 设计目标

1. **简化登录流程**：移除密码输入，使用验证码登录
2. **统一注册登录**：登录时自动注册，无需独立注册页面
3. **引导新用户**：首次登录后引导设置用户名和头像
4. **优化体验**：清晰的状态反馈和错误提示

---

## 📱 页面结构

### 1️⃣ 登录页面（重设计）

#### 页面布局
```
┌─────────────────────────────────────────┐
│                                         │
│            🔷 Logo/Title                │
│         待办管理系统                      │
│      使用验证码快速登录                    │
│                                         │
│  ┌───────────────────────────────────┐ │
│  │                                   │ │
│  │  📧/📱 用户名                      │ │
│  │  ┌─────────────────────────────┐ │ │
│  │  │ 请输入邮箱或手机号            │ │ │
│  │  └─────────────────────────────┘ │ │
│  │     ℹ️ 支持邮箱和手机号登录        │ │
│  │                                   │ │
│  │  🔐 验证码                         │ │
│  │  ┌──────────────┐  ┌───────────┐ │ │
│  │  │ 请输入验证码  │  │ 发送验证码 │ │ │
│  │  └──────────────┘  └───────────┘ │ │
│  │     ℹ️ 60秒后可重新发送            │ │
│  │                                   │ │
│  │  [     立即登录     ]              │ │
│  │                                   │ │
│  └───────────────────────────────────┘ │
│                                         │
│     💡 新用户将自动创建账户              │
│                                         │
└─────────────────────────────────────────┘
```

#### 字段说明

**1. 用户名输入框**
- **Label**: "邮箱/手机号"
- **Placeholder**: "请输入邮箱或手机号"
- **验证规则**:
  - 邮箱格式：`/^[^\s@]+@[^\s@]+\.[^\s@]+$/`
  - 手机号格式：`/^1[3-9]\d{9}$/` (中国大陆)
- **自动识别**: 前端智能识别输入类型（email/phone）
- **Helper Text**: "支持邮箱和手机号登录"

**2. 发送验证码按钮**
- **默认状态**: "发送验证码"（蓝色按钮）
- **倒计时状态**: "60秒后重新发送"（灰色禁用）
- **发送中状态**: "发送中..." + loading图标
- **错误重试**: "重新发送"（黄色警示色）

**3. 验证码输入框**
- **Label**: "验证码"
- **Placeholder**: "请输入6位验证码"
- **格式**: 6位数字
- **自动聚焦**: 发送验证码成功后自动聚焦
- **Helper Text**: 倒计时提示 "60秒后可重新发送"

**4. 登录按钮**
- **文本**: "立即登录"
- **加载状态**: "登录中..." + loading动画
- **禁用条件**: 用户名为空 或 验证码未输入

#### 状态设计

**正常流程**:
1. 用户输入邮箱/手机号
2. 点击"发送验证码" → 按钮禁用，显示倒计时
3. 输入验证码
4. 点击"立即登录" → 按钮loading
5. 登录成功 → 跳转或弹出设置对话框

**错误处理**:
- 用户名格式错误 → 红色边框 + 错误提示
- 验证码发送失败 → Toast提示 + 按钮变为"重新发送"
- 验证码错误 → 红色边框 + 错误提示"验证码错误，请重新输入"
- 验证码过期 → 提示"验证码已过期，请重新获取"

### 2️⃣ 首次登录设置对话框（新增）

#### 对话框布局
```
┌─────────────────────────────────────────┐
│  欢迎使用待办管理系统！ 🎉                │
│  完善你的个人信息                          │
│                          [跳过] [稍后设置]│
│  ───────────────────────────────────    │
│                                         │
│  👤 用户名 *必填                          │
│  ┌─────────────────────────────────┐   │
│  │ 请输入用户名（2-20字符）          │   │
│  └─────────────────────────────────┘   │
│                                         │
│  📷 头像（可选）                          │
│  ┌─────┐                               │
│  │     │  [上传头像]                    │
│  │ 🧑  │  支持 JPG、PNG，不超过 200KB   │
│  │     │  建议尺寸：50x50                │
│  └─────┘                               │
│                                         │
│  ───────────────────────────────────    │
│                 [完成设置]               │
└─────────────────────────────────────────┘
```

#### 字段说明

**1. 用户名输入**
- **必填**: 是
- **验证规则**: 2-20个字符，支持中英文、数字、下划线
- **实时验证**: 显示字符计数 "12/20"
- **错误提示**: "用户名长度为2-20个字符"

**2. 头像上传**
- **可选**: 是
- **预览**: 圆形头像预览（100x100px显示）
- **限制**: 
  - 格式：JPG、PNG、GIF
  - 大小：最大 200KB
  - 建议尺寸：50x50px
- **默认头像**: 使用 DiceBear API 生成
- **上传方式**: 
  - 点击上传按钮
  - 拖拽到预览区域

**3. 操作按钮**
- **跳过**: 右上角，关闭对话框，使用默认设置
- **稍后设置**: 右上角，关闭对话框，可在设置页修改
- **完成设置**: 主按钮，保存并关闭

#### 交互设计

**弹出时机**:
- 登录成功后检测用户是否设置过用户名
- 如果 `username === null`，弹出对话框

**关闭行为**:
- 点击"跳过"/"稍后设置" → 使用邮箱/手机号前缀作为临时用户名
- 点击"完成设置" → 调用API保存，成功后跳转主页
- 对话框外点击不关闭（模态对话框）

## 🔄 交互流程图

### 完整登录流程

```
开始
  ↓
检查本地Token
  ├─ 有效 → 直接进入应用
  └─ 无效/不存在
      ↓
显示登录页面
  ↓
用户输入邮箱/手机号
  ↓
前端验证格式
  ├─ 无效 → 显示错误提示
  └─ 有效
      ↓
点击"发送验证码"
  ↓
调用网关发送验证码API
  ├─ 失败 → Toast提示 + 显示"重新发送"按钮
  └─ 成功
      ↓
开始60秒倒计时
验证码输入框自动聚焦
  ↓
用户输入验证码
  ↓
点击"立即登录"
  ↓
调用网关登录API
  ├─ 失败 → 显示错误提示
  └─ 成功
      ↓
保存Tokens到LocalStorage
      ↓
检查用户是否设置过用户名
      ├─ 已设置 → 跳转到主页
      └─ 未设置
          ↓
弹出首次设置对话框
          ↓
用户输入用户名和头像（可选）
          ↓
调用TODO后端创建用户API
          ├─ 失败 → 显示错误提示
          └─ 成功
              ↓
保存用户信息到Store
              ↓
跳转到主页
```

### 验证码倒计时逻辑

```
点击"发送验证码"
  ↓
禁用按钮
显示"发送中..."
  ↓
API调用成功
  ↓
开始60秒倒计时
按钮文字："60秒后重新发送"
  ↓
每秒更新：59、58、57...
  ↓
倒计时结束
  ↓
启用按钮
按钮文字："重新发送"
```

## ♿ 无障碍设计

### 键盘导航

```
Tab 顺序:
1. 邮箱/手机号输入框
2. 发送验证码按钮
3. 验证码输入框
4. 登录按钮
```

### ARIA 标签

```html
<!-- 输入框 -->
<input
  aria-label="邮箱或手机号"
  aria-required="true"
  aria-invalid="false"
  aria-describedby="username-error"
/>

<!-- 错误提示 -->
<div
  id="username-error"
  role="alert"
  aria-live="polite"
>
  请输入有效的邮箱或手机号
</div>

<!-- 验证码按钮 -->
<button
  aria-label="发送验证码"
  aria-disabled="false"
>
  发送验证码
</button>
```

### 屏幕阅读器支持

- 所有输入框必须有明确的label
- 错误信息使用 `role="alert"` 和 `aria-live="polite"`
- 加载状态使用 `aria-busy="true"`
- 对话框使用 `role="dialog"` 和 `aria-modal="true"`

## 🧪 测试场景

### 正常流程测试

1. ✅ 输入有效邮箱 → 发送验证码 → 输入正确验证码 → 登录成功
2. ✅ 输入有效手机号 → 发送验证码 → 输入正确验证码 → 登录成功
3. ✅ 首次登录 → 弹出设置对话框 → 输入用户名 → 完成设置

### 异常流程测试

1. ❌ 输入无效邮箱格式 → 显示错误提示
2. ❌ 输入无效手机号格式 → 显示错误提示
3. ❌ 验证码未输入 → 登录按钮禁用
4. ❌ 输入错误验证码 → 显示错误提示
5. ❌ 验证码过期 → 提示重新获取
6. ⏱️ 60秒内重复点击发送验证码 → 按钮禁用
7. ❌ 网络错误 → Toast提示 + 重试按钮

### 边界情况测试

1. 🔄 Token自动刷新：Token过期前调用刷新接口
2. 📱 响应式：在不同屏幕尺寸下测试布局
3. ⌨️ 键盘导航：使用Tab键测试完整流程
4. 🎯 并发：多次快速点击按钮的防抖处理
