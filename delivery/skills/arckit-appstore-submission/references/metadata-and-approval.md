# 资料、商业决定与确认

## 语言、地区与发布

- 从目标构建对应源码的 String Catalog、资源本地化、Info.plist/归档证据提取实际支持语言；排除依赖库语言与空占位。与已有 ASC locales 对照，按官方支持表映射语言/地区变体。
- 应用 UI 语言与商店 locale 分开记录。商店不支持的语言保留明确回退；不因缺某个翻译阻断全球地区本身，也不宣称已有不存在的 UI 翻译。现有商店语言不自动删除，缺少依据时询问。
- 默认选择全部当前地区及未来新增地区。查询实时地区目录与限制，不硬编码数量。全球目标不代表所有地区实际可售；资质/协议或地域限制如实报告，不能静默排除地区以通过检查。
- 首次建立全球范围可在送审摘要集中确认。已上线应用的地区变化可能立即影响现有版本，执行前明确展示增加/移除地区及线上影响并确认。
- 首次默认提出 MANUAL；用户既有明确发布策略可沿用，在摘要中展示。AUTO/定时发布也是对外发布决定，需要明确确认。skill 终点仍是送审。

## 收费

免费或付费需用户明确选择，可复用同一应用未撤回的明确决定；后台现状只作参考。付费需要基准地区、价格点和生效时间。默认可提出 Apple 自动换算其他地区价格，须确认并回读。免费指下载免费，不能据此删除、修改或忽略现有 IAP/订阅。

询问收费时继续独立的素材/资料准备，不能默认免费。付款协议、银行、税务由有权限的人填写/接受；Agent 定位缺项，不代签或猜填。

## 必需资料检查

逐项读取后台必填状态与本次适用项；API/schema/后台要求变化时以当前官方资料为准。

| 项目 | 自动工作 | 人工判断或动作 |
| --- | --- | --- |
| 名称、副标题、描述、关键词、宣传文本、更新说明、分类、版权 | 消费素材文案并核对功能与字段；需新增/修改商店文案时交给 assets，分类/版权由送审方核对 | 缺少命名/归属事实或新宣传表述在最终摘要确认 |
| 截图/预览 | 复用或通过 assets 补齐各语言素材，送审方检查覆盖与后台处理状态 | 首次视觉方向；必要素材授权/人工截图 |
| 支持 URL、隐私政策、营销 URL | 校验可访问性和适用语言；可准备文案 | 缺少真实公开页面或归属时提供内容由用户发布/确认，不能虚构 URL |
| 隐私标签、SDK 数据收集、tracking、隐私清单 | 核对代码/SDK/现有声明并列差异 | 未知后台数据用途、组织政策等声明事实 |
| 年龄分级、内容权利、地区资质/交易者信息 | 根据功能和现有资料提出带依据建议 | 无法证明的事实、法定身份/证明材料、协议 |
| 加密/出口合规 | 检查实现和 build 声明；复用已确认结论 | 证据不足或需要文件/批准的情况，不盲设豁免 |
| 审核账号、联系信息、Notes | 检查登录路径和步骤，生成清晰说明 | 私人信息、有效可用账号/验证码安排；秘密走受控本机文件或 UI |
| IAP/订阅 | 查询适用项目、关联状态、商品审核素材和当前首送规则 | 商业条款、售价、权益事实及同批提交项目 |

首次完整准备；后续只更新受影响内容，但仍核对最新必填项和已知拒审原因。首次各类型内购/订阅的关联要求必须按当前 Apple 规则检查；不要以已有 app 上架推断内购均可独立送审。

## 写入与确认时机

1. 用户请求送审即授权只读检查、本地素材制作及范围内可编辑版本草稿准备。仅咨询/仅检查则不写远端。
2. 先准备可审阅值，再处理未知事实。应用级共享字段、宣传文本、价格、地区等可能立即影响线上或其他平台；写前展示具体差异和影响并获得批准，不能把它们当普通版本草稿。
3. 最终确认之前，必须完成全部可自动准备项；有不可忽略阻塞就报告阻塞而非请求“带病提交”。
4. 最终摘要包括 app/团队/平台、版本/buildId、语言和截图预览、全球范围及限制、免费/付费与价格安排、隐私/分级/加密/权利变化、审核访问是否准备、IAP 项目、发布方式。
5. 确认来自用户对具体摘要的批准。此前只说“提交审核”不替代这份具体摘要确认；已有完全相同摘要的明确批准继续有效。
6. 提交前回读核对；关键对象/声明/项目/价格/地区/发布方式变化，只对变化重新确认。纯执行重试不重复询问已获授权，但未知结果必须先对账。
