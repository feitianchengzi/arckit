# 真实截图采集与制作

## 输入与真实 UI

以目标构建对应的已实现功能、语言、设备类型和真实截图为依据。来自送审任务时与固定 build 对齐；独立素材任务使用已确认的源码/归档/用户指定版本，不要求 TestFlight 或 Apple 连接。

生产优先级：有效已有素材 → 项目现成截图自动化/UI tests → 目标版本模拟器/真机或 macOS 应用窗口采集 → 项目真实 View 的可验证渲染 → 人工拍摄。使用 mock/demo 数据仅限真实页面及已存在入口；新增业务代码、demo 或深链需要明确授权。

iOS 按实际支持的 iPhone/iPad 设备族准备所需 screenshot display types；macOS 采集真实 Mac 窗口/界面，按 Mac screenshot 要求输出，不套用 iPhone 尺寸或设备框。动态读取官方截图规格及后台必需槽位，不硬编码某代设备尺寸。原始文件与成品分开保存。

自动采集失败时先说明具体限制，给出 manual-capture-guide.md：页面/状态、版本、语言、设备/分辨率、文件命名、保存目录和检查方法；等待用户截图后继续制作。用户明确要求手动时直接采用手动；无需固定的模式选择提问。

## 视觉方向与图层

复用已有确认风格。新风格先制作一张可审阅样图，用户确认后锁定背景、屏幕容器、字体和位置，再扩展全套。设备/窗口容器应符合平台，也可以采用清晰的无框真实 UI 布局。

背景、设备/窗口容器、标题、真实 UI、标注、必要脱敏层分别保存。修改局部仅调整对应图层，不因换页面重绘已确认版式。按当前工具能力选择确定性排版或适用图像工具；生成装饰不能代替真实 UI。

截图主体必须显示真实 App in use，禁止用概念图/虚构界面充当应用截图。真实用户隐私使用测试数据或最小脱敏；第三方版权不明时先核对权利，必要局部遮挡需保留真实结构和功能状态，遮挡不等于取得内容授权。无法真实展示且满足权利要求时阻塞。

每张图一个真实卖点，标题不遮挡 UI。各语言独立导出，保留 UI 原语言与标题语言记录；不把翻译标题伪称应用支持该语言。

## 采集与质量检查

模拟器可用 `xcrun simctl io <udid> screenshot <path>`；macOS 使用授权的应用窗口截图工具。点击前校准坐标/窗口尺寸，点击后用缩略图确认状态，避免无界识图和点击。缩略图用于导航与 contact sheet；最终成品抽检原图，必要文字细节放大检查。

使用可用工具读取实际图片尺寸，例如 `sips -g pixelWidth -g pixelHeight <file>`。校验 PNG/JPG 格式、设备要求、数量、色彩/透明度限制、尺寸、文字溢出、UI 裁切、页面真实性和各语言完整性。截图缺失只能报告 awaiting_manual_screenshots 或 blocked_missing_screenshots，不能以清单代替图片完成。

预览视频仅在用户请求时制作：使用对应版本真实录屏，按当前官方规格检查时长、尺寸、音视频编码和语言；实际文件缺失时记录阻塞。视频不代替所需截图。素材生产不上传后台。

官方尺寸、数量、格式限制在执行时核对：
- https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/
- https://developer.apple.com/app-store/review/guidelines/#accurate-metadata
