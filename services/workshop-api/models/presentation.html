团队共享任务系统

数据模型设计

采用项目成员表直接管理权限
去除团队概念的冗余设计

数据库：PostgreSQL | 用户识别：网关UUID

核心数据表

users

  • ID (主键)
  • UUID (网关提供)
  • Username
  • Avatar
  • CreatedAt
  • UpdatedAt

projects

  • ID (主键)
  • Name
  • GitURL
  • CreatorID
  • CreatedAt
  • UpdatedAt

project_members

  • ID (主键)
  • ProjectID
  • UserID
  • Role (角色)
  • CreatedAt
  • UpdatedAt

tasks

  • ID (主键)
  • ProjectID
  • FatherID (父任务)
  • Content
  • State
  • CreatorID
  • ExecutorID
  • 时间戳字段

数据关系图

users ←→ projects (多对多，通过 project_members，包含角色)
         ↓
      tasks

核心关系：
• 用户 ↔ 项目：通过 project_members 表关联
• 项目 → 任务：一对多关系
• 任务 → 任务：父子层级关系（自引用）
设计亮点：去除团队表，直接用项目成员表管理权限，简化数据模型

角色与权限

项目成员角色

Owner Admin Member

权限规则

任务创建权限：所有项目成员都可以创建任务
任务修改权限：
  • Owner / Admin：可以修改任意任务
  • Member：只能修改自己创建或分配给自己执行的任务

任务状态

Pending In Progress Completed Cancelled Blocked

场景一：创建新项目

步骤1：获取用户信息

  1. 从网关Header获取用户UUID（X-User-ID）
  2. 使用UUID查询用户
  3. 用户不存在则使用网关UUID创建新用户

步骤2：创建项目和成员（事务）

  1. 创建项目（projects 表）
  2. 将创建者加入项目成员（project_members 表，role=owner）
  3. 事务保证：任何步骤失败，全部回滚
事务保证：创建项目和添加成员必须在同一事务中完成，确保数据一致性

场景二：邀请成员加入项目

流程

  1. 获取被邀请用户的UUID（由邀请者提供或从Header获取）
  2. 使用UUID查询用户，不存在则使用提供的UUID创建新用户
  3. 将用户加入项目成员（project_members 表）
防重复机制：通过唯一约束 UNIQUE(project_id, user_id) 防止同一用户重复加入同一项目
用户自动创建：被邀请用户不存在时自动创建，降低加入门槛

场景三：创建任务和权限控制

任务创建

  1. 验证用户是项目成员（通过 project_members 表）
  2. 插入 tasks 表
  3. 设置创建者和项目关联

权限判断逻辑

1. 查询用户在项目中的角色 SELECT role FROM project_members WHERE project_id = ? AND user_id = ? 2. 根据角色判断权限 IF role == 'owner' OR role == 'admin' → 可以修改任意任务 ELSE IF role == 'member' → 检查任务 creator_id == user_id → 检查任务 executor_id == user_id → 只有满足条件才能修改

简化查询

简化流程

提高性能

数据保留策略

重要原则：即使用户离职或被删除，关联的外键ID仍然保留

保留的字段

  • projects.creator_id - 项目创建者ID
  • tasks.creator_id - 任务创建者ID
  • tasks.executor_id - 任务执行者ID

设计原因

历史完整性

保证记录完整

数据分析

便于审计追踪

数据安全

避免级联删除

建议：使用软删除（status字段）而非物理删除，查询时需要处理用户可能不存在的情况

网关集成

Header信息

X-User-ID // 用户UUID（必需，网关提供） X-User-Username // 用户名 X-User-AppID // 应用ID X-User-SessionID // 会话ID

用户识别流程

  1. 网关验证用户身份后，在Header中传递 X-User-ID
  2. 业务服务从Header获取UUID
  3. 使用UUID查询用户，不存在则创建（使用网关提供的UUID）
  4. 后续操作使用用户ID进行关联
关键点：用户UUID由网关统一管理，业务服务直接使用网关提供的UUID，确保用户标识的一致性
