# 智能客服与外部 SDK 验证记录

验证日期：2026-10-28。使用当前工作区代码、隔离 PostgreSQL 数据库、OpenHands 和真实 DeepSeek 调用。本记录对应本地隔离验证，未部署生产。

## 已实现

- 多轮澄清持久化，合并位置、现象、期望、步骤、环境、影响，以及频率、业务目标、替代办法等辅助字段。
- 模型新增信息须有客户原话片段；服务端计算缺失项与可确认状态。高置信度不再等于问题已解决。
- 澄清中的补充消息不再匹配本地固定提交引导，避免保存草稿内的关键词截断多轮对话。
- 澄清提示采用服务端校验后的状态，最多追问两项，阻止模型在缺少有效字段时误称信息齐备。
- 客户可编辑草稿、显式标记辅助信息待核实；编辑后必须重新确认。结构化建卡及追加接口拒绝未经确认或缺少必要信息的提交。
- 创建反馈时关联原客服对话及其消息。已有反馈追加信息，不因再次澄清自动创建新卡片。
- SDK WebSocket 按客户所有权过滤，只推送变更 ID；不推送其他客户正文。修复应用子协议协商，并在凭证到期时断开。

## 质量判断与未覆盖范围

核心链路已在真实 HTTP、WebSocket 和模型调用层验证，但不能承诺模型每轮均完整提取：新需求场景曾漏提取诉求类型、使用场景，亦出现重复追问。客户确认表单可补齐或纠正；有的三轮样本自动达到待确认状态，有的仍需客户补齐字段。结构化信息用于辅助团队判断，不能自动当作已核实事实、已接受需求或排期决定。原话片段匹配只能证明出处，不能证明语义完全正确。

- 生产版 SDK 已在外部宿主浏览器中验证澄清更正、确认建卡、状态查询、刷新后查询与继续补充；不等同于真实生产网关验收。
- OSS/STS 未配置，附件上传策略返回配置错误，未验证真实上传和产物存储。
- 本地向量服务不可用；文档命中及真实模型读取 README 已验证，未证明向量语义检索质量。
- 管理控制台严格类型检查与生产构建已通过。
- API 使用隔离数据；测试模型 Key 仅在测试项目中加密配置，明文初始化脚本已清理。

## 新需求澄清补充

按 request_type 区分故障与新需求。新需求核心收集目标用户、模块、需求描述、使用场景、期望结果、业务目标和痛点；当前流程、影响、频率、预期收益、替代方案和约束须收集或由客户明确标为待确认。新增规则已通过后端及 SDK 回归；该版本需求专用模型行为仍需结合实际业务知识持续评估。

## 用户如何应用

接入方按 [外部集成指南](feedback-sdk-external-integration.md) 配置项目知识、OpenHands、生产网关和 Session。宿主后端保管长期凭证，前端 iframe/WebView 只接收短期 Session，处理刷新事件与未读通知。

客户打开客服 → 获取资料解答 → 未解决时在同一会话多轮补充 → 核对/编辑结构化草稿和待核实项 → 明确确认并提交 → 在“我的反馈”继续沟通与查看处理状态。

团队结合实际现象、期望、复现条件、影响、业务目标及替代办法判断需求价值和证据完整度，再决定受理、补充澄清或转待办。任务推进驱动客户反馈状态，正式交付接口回写结果。
