## 一、创意概述

### 核心想法
构建一个智能反馈处理平台，连接"用户反馈提交"和"AI Agent自动实施"两个环节。产品通过AI理解自然语言反馈，进行智能分级、优先级排序和产品方向守护，最终输出结构化需求文档供执行平台（AI Agent）自动实施。核心价值在于：让用户诉求被及时理解和响应（数天内而非数月），同时保持产品方向可控。

### 目标用户
1. **首要用户**：自己（小型软件开发创业公司，维护多款产品）
2. **次要用户**：个人开发者和中小型开发团队（1-10人）
3. **特征**：时间资源有限、反馈积压严重、希望提升用户满意度、愿意尝试AI工具

### 核心价值主张
**为开发者**：将反馈处理效率提升70%，从"每周只能处理5个反馈"到"AI自动处理35个+人工审核5个"，让1个人干3个人的活。

**为用户**：反馈响应时间从数月缩短到数天，看到自己的建议快速落地，提升参与感和满意度。

**差异化**：首个打通"反馈理解→需求生成→执行对接"全流程的AI驱动产品，聚焦在反馈处理环节（而非代码实施），职责清晰、风险可控。

## 二、核心假设清单

### 假设 1（核心假设）- 技术可行性
**假设内容**：AI（大模型）能够准确理解用户的自然语言反馈，并生成结构化的可执行需求文档（用户故事+验收标准）。在人类专家必要的参与下（审核有争议的反馈），结合AI辅助分析能力，开发者能够达到产品演进方向和用户个性化需求满足的平衡。

**验证标准**：
- AI对反馈的理解准确率 ≥ 85%（用户确认理解卡片的通过率）
- 产品契合度分析准确率 ≥ 80%（开发者认同AI建议的比例）
- 简单/中等复杂度反馈的需求文档生成成功率 ≥ 90%

**为什么核心**：如果AI无法准确理解反馈和守护产品方向，后续一切都不成立。

### 假设 2 - 价值主张
**假设内容**：目标用户（个人开发者/中小团队）的核心诉求是"反馈被及时满足"和"保持产品方向可控"，愿意为此付出合理的配置成本（10-30分钟初始配置+每周1-2小时审核）。

**验证标准**：
- 用户愿意嵌入SDK（集成门槛可接受）
- 开发者每周实际审核时间 ≤ 2小时
- 用户满意度（反馈响应及时性）提升 ≥ 50%

### 假设 3 - 三方协作模型
**假设内容**：通过清晰的角色分工（用户提交+AI分析+开发者决策），能够在"自动化效率"和"人类控制权"之间找到最优平衡点。

**验证标准**：
- 用户反馈提交完成率 ≥ 80%（不会因为流程复杂而放弃）
- 开发者对AI建议的采纳率在50-80%之间（过低说明AI无用，过高说明失去控制）
- 产品功能数量增长的同时，产品方向一致性评分保持 ≥ 4/5分

## 四、竞品与市场分析

### 现有解决方案

#### 方案 1：传统用户反馈工具
- **类型**: SaaS工具，如Canny、Uservoice、ProductBoard
- **特点**: 成熟的反馈收集、投票、优先级排序机制；侧重需求管理和用户沟通
- **优势**: 
  - 功能完善（路线图、用户分层、数据分析）
  - 用户体验好（公开反馈社区、透明度高）
  - 与项目管理工具集成（Jira、Trello）
- **劣势**: 
  - 反馈到实现的路径完全依赖人工，周期长（通常数周到数月）
  - 无AI理解和分析能力，开发者需要手动阅读每条反馈
  - 无法自动生成结构化需求文档

#### 方案 2：AI辅助开发工具
- **类型**: 代码生成工具，如GitHub Copilot、Cursor、Replit Agent
- **特点**: AI强大的代码生成能力，提升开发效率
- **优势**: 
  - AI生成代码质量高，开发者体验好
  - 支持自然语言描述需求
  - 集成在开发环境中，无缝衔接
- **劣势**: 
  - 需要开发者手动处理用户反馈，转化为开发任务（缺少反馈处理环节）
  - 无产品方向守护机制，依赖开发者判断
  - 面向开发者，终端用户无法直接参与

#### 方案 3：低代码/无代码平台
- **类型**: 可视化开发平台，如Bubble、Retool、Webflow
- **特点**: 非技术用户也能快速实现功能
- **优势**: 
  - 降低开发门槛，快速原型验证
  - 适合简单业务逻辑
- **劣势**: 
  - 灵活性受限，复杂逻辑难以实现
  - 没有自动化反馈处理能力
  - 需要用户学习平台语法/操作

### 差异化机会

**我们的独特定位**：
1. **全流程打通**：首个将"用户反馈收集 → AI理解分析 → 结构化需求输出 → 执行平台对接"全流程自动化的产品
2. **职责边界清晰**：聚焦反馈处理环节，不负责代码实施（降低技术风险和复杂度）
3. **三方协作模型**：用户、开发者、AI角色分工明确，平衡效率和控制权
4. **智能分级体系**：三维分级（技术复杂度+产品契合度+用户价值），而非简单的优先级排序
5. **产品方向守护**：AI辅助判断反馈与路线图的契合度，帮助开发者避免功能膨胀

**竞争优势来源**：
- 现有反馈工具（Canny等）**无AI能力**，依赖人工处理
- AI开发工具（Copilot等）**缺少反馈收集和产品分析**，只解决代码生成
- 我们填补了两者之间的空白，成为连接用户和AI Agent的智能桥梁

**潜在风险**：
- Canny等反馈工具可能快速集成AI能力（他们有用户基础）
- GitHub等大厂可能推出类似产品（他们有AI技术和生态）
- **应对策略**：快速验证MVP，建立先发优势；聚焦垂直场景（自己的产品类型），积累领域知识

## 五、最小可验证产品（MVP）

> **调整说明**：基于产品边界明确（聚焦反馈处理环节）和三方协作模型，MVP设计围绕核心闭环展开。

### MVP 核心功能

#### 1. 用户侧SDK（嵌入产品中）- P1核心
**功能描述**：
- 反馈提交组件：支持文字描述+截图上传，5秒完成提交
- AI理解确认：用户提交后，AI自动生成"理解卡片"（提炼痛点、期望、场景），用户确认或修正
- 反馈状态追踪：已提交 → AI分析中 → 开发评估中 → 开发中 → 已上线，透明化流程
- 简化投票功能：为其他用户反馈点赞，辅助优先级排序

**验证目标**：
- 集成门槛 ≤ 5分钟（npm安装+2行代码）
- 用户反馈提交完成率 ≥ 80%
- AI理解准确率 ≥ 85%（用户确认通过率）

**技术方案**：
- 前端：轻量级React组件（< 50KB），支持Web和移动端
- 集成方式：`<FeedbackWidget projectId="xxx" />`
- 备选方案：Chrome插件（无代码集成，通过浏览器扩展嵌入）

#### 2. 开发者侧管理后台 - P1核心
**功能描述**：
- **反馈看板**：按分级展示（简单/中等/复杂），按优先级排序（P1/P2/P3），支持筛选和搜索
- **AI分析结果展示**：每条反馈显示"理解卡片"、三维评分（技术复杂度/产品契合度/用户价值）、AI建议（接受/调整/拒绝）
- **产品路线图配置**：上传/编辑产品路线图文档（Markdown），定义核心原则（如"保持简洁"），AI基于此进行契合度分析
- **审核工作流**：
  - 一键接受AI建议（生成结构化需求JSON，发送到执行平台）
  - 推翻AI建议（修改分级/优先级，或直接拒绝）
  - 查看AI推理过程（为什么给出这个建议？）
- **执行状态追踪**：实时显示执行平台的反馈（开发中/已完成/失败），查看日志

**验证目标**：
- 开发者每周审核时间 ≤ 2小时
- 对AI建议的采纳率在50-80%之间
- 产品契合度分析准确率 ≥ 80%

**技术方案**：
- 前端：Next.js + Tailwind CSS，响应式设计
- 权限：支持多用户（团队协作延后到V2）

#### 3. 与任务执行平台对接 - P1核心
**功能描述**：
- **标准化需求输出**：生成JSON格式的需求文档（包含用户故事、验收标准、影响模块、设计约束等）
- **执行状态回调接收**：接收执行平台的Webhook回调（开始执行/执行完成/失败/需人工介入）
- **日志查看**：展示执行平台返回的日志，方便排查问题

**验证目标**：
- 需求文档生成成功率 ≥ 90%（对简单/中等复杂度反馈）
- 执行平台对接成功率 100%（无协议错误）

**技术方案**：
- 输出格式：JSON Schema（详见"协议设计"章节）
- 对接方式：RESTful API + Webhook回调
- 初期对接目标：自己的任务驱动执行平台

#### 4. AI核心引擎（后台服务）- P1核心
**功能描述**：
- **自然语言理解**：解析用户反馈，提取关键要素（痛点、期望、场景、情绪）
- **智能分级**：三维评分
  - 技术复杂度：简单（UI/文案）/中等（单一功能）/复杂（架构级）
  - 产品契合度：基于路线图和核心原则，计算语义相似度（0-1分）
  - 用户价值：影响面（有多少用户需要）× 紧迫性（有多急）
- **需求文档生成**：输出结构化JSON（用户故事+验收标准+技术建议）
- **产品方向守护**：标记"有争议"的反馈（契合度 < 0.6），强制人工审核

**验证目标**：
- 所有核心能力的准确率（见假设1）

**技术方案**：
- 大模型：Claude 3.5 Sonnet / GPT-4（基于成本和准确率选择）
- 向量数据库：存储路线图和历史反馈，用于语义相似度计算
- 提示词工程：精心设计Prompt，包含少样本示例

### MVP 不包含（延后到V2）
- 复杂的数据分析和报表（如反馈趋势、用户满意度）
- 多团队协作功能（权限管理、团队看板）
- 高级自定义规则引擎（用户自定义分级逻辑）
- 公开反馈社区（用户之间的讨论和投票）
- 多渠道反馈收集（邮件、Slack、Discord集成）

## 七、风险与挑战

### 关键风险

#### 1. 技术风险：AI核心能力不达标
**风险描述**：AI理解准确率或产品契合度分析准确率低于预期（< 80%），导致用户不信任、开发者需要大量修正，失去自动化价值。

**应对策略**：
- **提前验证**：开发SDK前先验证AI引擎，用50-100条真实反馈测试
- **提示词优化**：投入足够时间进行Prompt工程，参考Chain-of-Thought等技术
- **人工标注**：准备200-500条高质量标注数据，用于Few-shot学习或微调
- **备选模型**：测试多个大模型（Claude/GPT-4/Gemini），选择准确率最高的
- **降级方案**：如果AI准确率不足，先提供"AI辅助+人工主导"模式（AI只提供建议，不做决策）

#### 2. 产品风险：用户不愿意提交反馈
**风险描述**：SDK集成后，用户实际使用率低（< 10%），原因可能是：流程复杂、不信任会被处理、隐私担忧。

**应对策略**：
- **极简体验**：反馈提交 ≤ 3步（描述 → 确认理解 → 提交），不强制登录
- **即时反馈**：AI理解卡片即时生成（< 3秒），让用户感知到"被理解"
- **透明化**：清晰展示反馈处理状态，定期通知用户进展（"你的反馈已被采纳，预计本周上线"）
- **激励机制**（V2考虑）：反馈被采纳的用户获得感谢、徽章或优先体验权
- **隐私保护**：明确告知用户反馈仅用于产品改进，支持匿名提交

#### 3. 商业风险：市场接受度不确定
**风险描述**：目标用户（个人开发者/中小团队）对AI驱动的反馈系统接受度低，或不愿意为此付费。

**应对策略**：
- **免费MVP**：前3个月对外部用户免费，积累用户和数据
- **价值量化**：提供清晰的ROI计算（"节省每周X小时 = 每月节省$Y成本"）
- **逐步付费**：先证明价值（处理100条反馈后），再提供付费计划
- **定价策略**：基于用量（每月反馈数）而非固定费用，降低尝试门槛

#### 4. 竞争风险：大厂快速跟进
**风险描述**：Canny、GitHub等大厂快速集成AI能力，凭借用户基础和资源优势碾压我们。

**应对策略**：
- **速度优势**：快速验证MVP（3个月），建立先发优势
- **垂直深耕**：聚焦特定产品类型（如开发者工具、SaaS），积累领域知识（大厂做通用方案）
- **开放生态**：提供API和Webhook，方便集成到其他工具（Canny等可能成为合作伙伴而非竞争对手）
- **差异化**：强化"产品方向守护"能力（这是Canny等工具缺少的）

### 未解决的问题

1. **AI产品契合度分析的技术实现路径**：
   - 如何将产品路线图（自然语言Markdown）转化为可计算的语义向量？
   - 如何定义"产品核心原则"的权重？
   - 需要进一步的技术调研和原型验证
   
2. **执行平台的能力边界**：
   - 现有任务驱动执行平台能处理多复杂的需求？
   - 如果执行失败率 > 20%，用户体验会严重受损
   - 需要与执行平台团队充分沟通，明确协议和边界
   
3. **定价模型**：
   - 按反馈数量收费（如$0.5/条）？
   - 按座位数收费（如$29/月/开发者）？
   - 按产品数收费（如$99/月/产品）？
   - 需要根据MVP数据和用户反馈确定
   
4. **多产品类型的适配性**：
   - MVP聚焦自己的产品（开发者工具类），但未来要支持其他类型（电商、内容平台等）
   - 不同产品类型的反馈特征差异大（如电商关注物流、内容平台关注推荐算法）
   - 需要积累不同类型产品的数据，优化AI模型

## 八、探索记录

### 2026-02-04 - 创意探索对话记录

**对话要点**：
1. **初始创意**：用户反馈直接驱动AI自动开发，一周内发布
2. **第一轮模拟**（支持率57.1%）：
   - 正方用户认可速度价值，但反方用户担心质量、产品方向失控、适用场景有限
   - 主要问题：全自动化风险高、产品边界不清晰
3. **关键调整**：
   - 明确产品边界：聚焦"反馈处理环节"（理解+分级+需求生成），不负责代码实施
   - 从"全自动"调整为"智能分级处理"（简单反馈自动化，复杂反馈人工主导）
   - 增加"产品方向守护"功能（AI分析契合度，人类最终决策）
   - 不限定垂直场景，但重点考虑技术复杂度问题
4. **第二轮模拟**（支持率83.3%）：
   - 原质疑的技术负责人转为支持（职责清晰、风险可控）
   - 三方协作模型获广泛认可
   - 仅剩的反方用户顾虑是技术细节（AI准确率），可通过实践解决

**用户研究发现**：
- **核心痛点**：反馈积压严重（200+条）、开发资源紧张（1-2人团队）、用户满意度低（响应慢）
- **核心诉求**：快速响应（数天而非数月）、保持产品方向可控、减少人工工作量
- **接受条件**：AI准确率 ≥ 80%、集成门槛低（< 5分钟）、人类保持决策权

**关键决策**：
1. **产品定位**：智能反馈处理平台（而非自动化开发平台）
2. **三方协作模型**：用户（自然语言提交）+ AI（理解+分析+建议）+ 开发者（审核+决策）
3. **MVP范围**：用户SDK + 管理后台 + 执行平台对接
4. **首批用户**：自己的多款产品（降低风险，快速迭代）
