## 一、技术方案

### 1.1 核心目标

验证 arc 的需求开发 loop（coding agent 接需求后自主开发到达成）能在真实客户的真实代码仓库上端到端跑通到可交付产物。

### 1.2 架构分层

```
┌─────────────────────────────────────────────────────────────┐
│  反馈层（SDK）                                                │
│  智能客服 = Agent + LLM + 两层知识库检索                       │
│    ├─ Agent 接收问题 → 检索知识库 → LLM 生成回复 → 直接回复客户  │
│    └─ Agent 判断需要更多信息 → 追问收集 → 创建 Feedback         │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  治理层（workshop-api + feedback-console）                    │
│  分诊（AI 辅助 + 人工确认）                                    │
│    ├─ typeA 直接回复（question/consultation）                  │
│    └─ typeB 转需求（issue/suggestion）                        │
│         ├─ triage 门控：role 兜底（owner/admin）               │
│         ├─ ConvertFeedbackToTask → Task                      │
│         └─ FeedbackTaskLink 追溯                              │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  执行层（runtime arcorbit）                                   │
│  task-source-adapter 拉取 Task                               │
│    → 桥1：Task → Case（Gap.derived_from=customer-feedback:<id>）│
│    → Gap-driven Loop（起 Codex 线程 → 推进 → Git 收尾）        │
│    → 桥2：closeout → 进展草稿 message（pending_review）        │
│    → 桥3：用户询问 → turn/steer 注入同一线程                    │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  交付层（产物交付，部署不在本期）                                │
│  Task accepted → 构建产物 → artifact_url 回写                  │
│    → 通知客户交付完成                                          │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 关键设计决策

| 决策项 | 结论 | 理由 |
|--------|------|------|
| 代码语义检索选型 | 轻量代码 RAG（tree-sitter + BGE-M3 + pgvector） | 不引入 Sourcegraph/OpenGrok，智能客服是 RAG 不是符号导航 |
| 向量存储 | 复用 WeKnora 的 pgvector 实例（独立 schema） | 避免多部署一套向量服务，schema 隔离不破坏边界 |
| 置信度阈值 | 初期人工拍 0.75，取 max(hit.score × weight) | 无标注集标定，保守策略 |
| capabilities | 试点不建，role 兜底 | 单客户试点，capabilities 是过度设计 |
| 部署边界 | arckit 外部，产物交付而非部署 | delivery 是决策区不是工作流环节 |
| 桥3 硬关联门控 | 同 feedback_id 才注入 | 守 Runtime 策略中性，避免上下文污染 |

### 1.4 智能客服 Agent 设计

| 能力 | 实现方式 |
|------|----------|
| 理解问题 | LLM 解析用户意图 |
| 检索知识 | Agent 调用工具检索代码/文档/FAQ |
| 生成回复 | LLM 基于检索结果生成自然语言回复 |
| 多轮对话 | Agent 维护对话历史上下文 |
| 主动追问 | Agent 判断信息不足时主动询问 |

### 1.5 三桥设计

| 桥 | 连接 | 实现 |
|----|------|------|
| 桥1 | Task → Case | Gap.derived_from 加 `customer-feedback:<feedback_id>`，FeedbackTaskLink 追溯 |
| 桥2 | closeout → 进展草稿 | runtime closeout 后调 workshop-api 创建 FeedbackMessage(state=pending_review) |
| 桥3 | 用户询问 → steer | workshop-api WebSocket 事件 → runtime 检测活跃 Case → turn/steer 注入 |

### 1.5 数据模型扩展

| 扩展 | 表/字段 | 用途 |
|------|--------|------|
| knowledge_workspaces | 新表 | workspace 与项目绑定 |
| knowledge_sources | 新表 | 知识源管理 |
| code_index.code_chunks | 新 schema | 代码语义分块 |
| openhands_agents | 新表 | OpenHands Agent 配置 |
| customer_code_repos | 新表 | 客户代码仓库 |
| tasks.artifact_url | 新字段 | 产物交付回写 |
| tasks.source_feedback_id | 新字段 | 桥1 追溯 |
| project_members.capabilities | 新字段 | 治理配置（预留） |
| feedback_messages.state | 新字段 | 草稿状态（pending_review/sent） |

## 四、可实现的业务链路

### 4.1 客户侧完整链路

```
┌──────────────────────────────────────────────────────────────┐
│  1. 客户打开 SDK 对话                                          │
│     ↓                                                        │
│  2. 智能客服追问收集（位置/现象/期望）                             │
│     ↓                                                        │
│  3. 信息完整 → 呈现结构化结果 → 确认提交                          │
│     ↓                                                        │
│  4. 创建 Feedback（status=pending, triage_status=pending）     │
│     ↓                                                        │
│  5. 查看"我的反馈" → 状态时间线 + 进展确认                        │
│     ↓                                                        │
│  6. 处理中可追问 → 同 feedback_id 注入活跃 Case                  │
│     ↓                                                        │
│  7. 收到交付完成通知 + 产物指向                                   │
└──────────────────────────────────────────────────────────────┘
```

### 4.2 内部侧完整链路

```
┌──────────────────────────────────────────────────────────────┐
│  1. 收到新 Feedback 通知 → 推送给 owner/admin                   │
│     ↓                                                        │
│  2. AI 分诊辅助展示（去噪/分类/优先级建议）                       │
│     ↓                                                        │
│  3. 分诊决策（role 门控）→ 做（转 Task）/ 不做（回复说明）          │
│     ↓                                                        │
│  4. ConvertFeedbackToTask → 创建 Task（state=pending）         │
│     ↓                                                        │
│  5. runtime 拉取 Task → workspace 绑客户代码目录                 │
│     ↓                                                        │
│  6. 桥1：Task → Case（Gap.derived_from=customer-feedback:<id>）│
│     ↓                                                        │
│  7. 起 Codex 线程（$using-arckit）→ Gap-by-Gap 推进             │
│     ↓                                                        │
│  8. Git 收尾 → 桥2：closeout → 进展草稿（pending_review）       │
│     ↓                                                        │
│  9. 处理人确认草稿 → 发送给客户                                  │
│     ↓                                                        │
│  10. 验收 accept → 构建产物 → artifact_url 回写                 │
│     ↓                                                        │
│  11. 通知客户交付完成                                           │
└──────────────────────────────────────────────────────────────┘
```

### 4.3 智能客服 Agent 链路

```
┌──────────────────────────────────────────────────────────────┐
│  客户提问                                                      │
│     ↓                                                        │
│  Agent 接收问题                                                │
│     ↓                                                        │
│  Agent 执行工具调用：                                           │
│    ├─ search_customer_code(query)  → 检索客户代码仓库           │
│    ├─ search_customer_docs(query)  → 检索项目文档               │
│    └─ search_product_knowledge(query) → 检索产品FAQ/spec       │
│     ↓                                                        │
│  Agent 将检索结果 + 问题 → LLM 生成回复                          │
│     ↓                                                        │
│  LLM 回复（含来源标注）→ 直接发送给客户                           │
│                                                              │
│  若 Agent 判断信息不足：                                        │
│    → 追问收集 → 创建 Feedback                                   │
└──────────────────────────────────────────────────────────────┘
```

**Agent 工具定义：**

```json
{
  "tools": [
    {
      "name": "search_customer_code",
      "description": "搜索客户代码仓库，查找相关代码实现"
    },
    {
      "name": "search_customer_docs",
      "description": "搜索项目文档（spec、设计、变更记录）"
    },
    {
      "name": "search_product_knowledge",
      "description": "搜索产品知识库（arckit facts、FAQ）"
    }
  ]
}
```

### 4.4 代码索引链路

```
┌──────────────────────────────────────────────────────────────┐
│  管理员添加代码知识源（仓库地址 + 分支）                          │
│     ↓                                                        │
│  触发首次索引                                                   │
│     ↓                                                        │
│  文件遍历 → 符号检测（Go/JS/TS/Python）                          │
│     ↓                                                        │
│  按符号边界分块（函数/类/方法粒度）                                │
│     ↓                                                        │
│  批量获取 embedding（BGE-M3，有降级）                            │
│     ↓                                                        │
│  写入 pgvector（独立 schema）                                   │
│     ↓                                                        │
│  检索时：向量相似度搜索 + SQL LIKE 兜底                           │
└──────────────────────────────────────────────────────────────┘
```

### 4.5 产物交付链路

```
┌──────────────────────────────────────────────────────────────┐
│  Task 验收 accept                                             │
│     ↓                                                        │
│  触发构建（TriggerBuildHandler）                                │
│     ↓                                                        │
│  本地打包生成产物                                               │
│     ↓                                                        │
│  产物地址回写 Task（artifact_url）                               │
│     ↓                                                        │
│  Feedback status → completed                                  │
│     ↓                                                        │
│  自动通知客户交付完成（autoNotifyDelivery）                       │
└──────────────────────────────────────────────────────────────┘
```
