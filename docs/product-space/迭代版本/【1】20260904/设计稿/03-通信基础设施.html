桥1 · Task→Case 追溯 缺失

依赖：无。第二批。

桥2 · 进展草稿回写 缺失

closeout 只 Git 收尾，不回写草稿 FeedbackMessage；草稿无 state 字段。

  • FeedbackMessage 加 state(draft/sent) migration
  • closeout 扩展回写草稿 system 消息
  • 草稿并入 Feedback 详情对话面板（已落点）

依赖：双向通信 + state 字段。第三批。

桥3 · 追问 steer 核心缺失

work-sync onInvalidate 只刷新 snapshot，无"客户消息→活跃 Case steer"路由。

  • runtime 监听 FeedbackMessage 事件
  • 硬关联门控：derived_from 含同 feedback_id 才注入
  • 依赖桥1追溯链路打通后才能路由

依赖：双向通信 + 桥1。第三批。

关键发现：设计稿原把桥2/桥3 描述为"接通即可"，代码核实 runtime 与 workshop-api 之间是单向拉取模式 + 仅刷新 snapshot 的 WebSocket，三个桥依赖的双向通道完全不存在。建议在第一批（triage + capabilities）之后、桥1/2/3 之前，插入双向通信基础设施步骤：runtime→workshop-api 回写能力 + runtime 监听 WS 事件路由 + FeedbackMessage state 字段。
