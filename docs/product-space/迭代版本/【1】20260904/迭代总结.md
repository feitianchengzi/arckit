# 客户支持通道迭代总结（迭代【1】20260904）

> 本文档是"客户支持通道"迭代的需求实现总结,综合 PRD 目标、工程落地现状、本轮(2026-09-23)收尾改动,作为该迭代的权威收口文档。详细工程交接见 `implementation-handoff.md`,技术方案见 `openhands-integration-plan.md` 与 `智能客服Agent-LLM技术方案.md`。

## 1. 迭代目标

打通"客户反馈→智能客服→分诊→Task→Codex loop→进展草稿→验收→产物交付"全链路,验证 arc 的需求开发 loop 能在真实客户的真实代码仓库上端到端跑到可交付产物。本期不做独立客服系统,而是给已有开发 loop 接一个**对客入口**(智能客服 + 反馈 SDK)和一个**对客出口**(产物交付)。

- **关联需求**:US-01 ~ US-09
- **功能集**:F-01 ~ F-10(见 `customer-support-prd.md`)
- **状态**:代码完成,待生产部署

## 2. 架构分层

```
反馈层   SDK 对话式反馈 / 我的反馈 / 智能客服问答  (packages/feedback-sdk-web)
治理层   分诊门控 / 三桥(Feedback↔Task↔Case) / 草稿确认  (services/workshop-api)
执行层   Task 7 态机 / Gap-driven Loop / Codex 线程贯穿  (runtime/arcorbit)
交付层   验收→构建→artifact_url 回写→客户通知  (services/workshop-api)
```

智能客服 = Agent + LLM + 两层检索(本地代码搜索 + OpenHands Agent)。代码语义检索采用轻量 RAG(tree-sitter + BGE-M3 + pgvector 独立 schema),不引入 Sourcegraph。置信度阈值 0.75,capabilities 试点不建用 role 兜底。

### 3.3 本轮(2026-09-23)收尾改动
本轮在"代码完成待部署"基础上,按 TDD 推进四项收尾:

1. **移除智能客服转人工入口(仅前端)**:删除 `AgentChatPanel` 的转人工按钮/handler/状态/文案与 `escalateFeedbackV2`,对话窗口不再有转人工入口;后端 `EscalateFeedbackHandler` 与未解决判定逻辑保留(可能被分诊复用)。
2. **补齐后端 V2 WS 通道**:新增 `ConnectFeedbackSDKWebsocket`,SDK 通过 WebSocket subprotocol `nebula-auth.<fbs_ token>` 携带 session token,workshop-api 自验证(`verifyFeedbackSessionToken`)解析 project scope 后加入 `realtime.DefaultHub` 房间。修复了此前 SDK realtime 连 `/workshop/v1/feedback/.../ws`(后端无此路由、404 死循环重连)的废代码问题,使客服回复 `feedback.message.created` 能实时推送至 SDK。
3. **修复 SDK Agent API session 模式阻断 bug**:`sendAgentMessage`/`getAgentConversations`/`getAgentConversationMessages` 此前直接调 `currentDirectAPIKeyContext()` 取 apiKey,在 session 模式抛错;改走 `requestJson` 双路径后 session 模式智能客服可用。**并补注册 session 级别 agent 路由**(`AgentMessageFromSession` 等 4 个 handler,鉴权用 feedback session scope),修复此前 session 模式 SDK 调 `/workshop/v2/feedback/feedbacks/:id/agent-message` 后端 404 的真实遗漏。
4. **打通客服回复→客户面板消息显示与通知**:
   - SDK `FeedbackConversationPanel` 加自动滚动 + `refreshKey`(实时事件命中时重拉消息)。
   - `SDKStatusPage` 实时事件命中展开项时递增该项 refreshKey。
   - Desktop renderer `renderFeedbackConversation` 加自动滚动,`onWorkSyncEvent` 命中当前反馈时刷新会话+滚动,未命中/不在反馈页时 toast 通知 + unread badge。

### 3.4 SDK 封装升级(面向外部客户)
- **i18n**:内置 zh-CN + en-US 双语,轻量 `t()` 实现,覆盖全部生产可见组件(AgentChatPanel/FeedbackConversationPanel/SDKChatPage/SDKStatusPage/SDKSubmitPage/FeedbackShell/FeedbackListStep/FeedbackSubmitStep/StatusTimeline/FeedbackMessageAttachment),`configure({ locale })` / `window.FeedbackSDK.setLocale()` 切换。
- **网关 URL / parent origins 运行时可配**:移除硬编码生产域名 fallback,`gatewayUrl` 未配置时报明确错误;`parentOrigins` 支持运行时配置。
- **示例去硬编码**:iOS 示例移除硬编码 apiKey/projectId,改占位符 + 文档说明。
- **客户集成文档**:新增 `docs/workshop/feedback-sdk-external-integration.md`,覆盖 iframe/WebView 集成、bridge API、postMessage 协议、鉴权模式、V2 WS、安全要点。
- **npm 化**:经评估不纳入本轮——SDK 现为 iframe/WebView 集成,外部客户封装不需要 npm 包,npm 化(双构建目标 + 类型定义)的回归风险大于边际价值,待确认"客户在自有 React 应用直接 import 组件"的真实诉求再投入。

### 3.5 智能客服图片附件(session 模式,本期新增)
- **前端**:`AgentChatPanel` 支持图片选择/预览/上传(复用 `uploadFeedbackImageV2`)/发送;`sendAgentMessage` 增加 `attachments` 参数。
- **后端**:`AgentMessageFromSession`(session 模式)接收图片 attachments 落库(metadata jsonb);`processWithAgent` 透传图片 URL;`ohSendMessageWithImages` 按 OpenAI 多模态格式构造 text + image_url content。
- **多 LLM provider 可切换**:OpenHands 已天然支持(环境变量 `LLM_API_KEY`/`LLM_MODEL`/`LLM_BASE_URL` + per-agent `LLMModel`),无需新建 provider 抽象。`AGENT_VISION_ENABLED` 开关控制是否传图:默认关(纯文本模型不传图,避免报错),切换多模态模型后置 true,Agent 真实看图。
- **多模态 URL 对接**:前端传 object_key,后端 vision 开启时需将 object_key 转为可访问 URL 传 LLM(后端当前未引 aliyun OSS Go SDK,此对接列为切换多模态时的后续完善项)。

## 4. 客户身份与反馈分类(封装要点)

- **客户身份**:`project_id`(哪个客户/产品)+ `custom_user_id`(该客户下哪个用户,业务稳定 ID ≤128 字符,非 PII)。session 模式由 `fbs_` token 签名保证不可伪造;apiKey 模式靠 apiKey 项目归属 + 落库 `requireCustomerFeedbackAccess` 校验。
- **反馈分类**:AI 分诊 `analyzeFeedback`(提交后异步触发)产出三元组——`issueType`(bug/feature/question/other,关键词启发式)+ `priority`(P1/P2/P3)+ `actionability`(可直接行动/需补充信息/需评估/需确认),写入 `feedback.data.triage`。与流程 `status`(8 态)、受理 `triage_status`、消息 `message_type`、消息 `sender_type` 是五个并列维度。
