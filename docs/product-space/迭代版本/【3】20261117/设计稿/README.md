# 直接反馈体验优化 · 交互设计稿

打开 [feedback-direct.html](feedback-direct.html)。无需构建、网络或后端依赖。背景为「云协作」外部业务产品示例，右侧为可收起的 SDK 浮层；本稿聚焦「仍未解决 / 直接反馈」表单形态与需求提交通道，不重复呈现【2】稿的完整答疑与生命周期能力。

## 三档方案

页面顶部切换档位，三档共用同一宿主、对话剧本与建卡流程，差异集中在表单形态与「我的反馈」类型展示：

| 档位 | 定位 | 核心差异 |
| --- | --- | --- |
| A · 当前版本 | 现状还原 | 三术语框全必填、无 placeholder、与对话脱节、需求归为「其他」、列表无类型徽标 |
| B · P0 优化 | 文案与衔接 | 对话已分析时预填核对优先；手填表单换用户语言 + 示例引导；「不确定」可降级；列表类型徽标与筛选 |
| C · P2 单框+结构化 | 体验升级 | 一段话描述 → Agent 整理 → 按类型预填核对（问题/需求字段组）；保留原样提交与手填降级 |

每档的改动清单实时显示在档位切换器下方，表单内说明与降级文案对应方案文档 §4。

## 点击评审路径

**最快路径：一键演示。** 方案栏内「一键演示」三个按钮自动走到当前档位的关键帧——先点「▶ 功能建议怎么提交」，即可直接看到需求链路的视觉效果（三档各不相同）：

- A 档：停在空白三术语框，表单内红色「现状断点」提示——对话已识别为需求，提交却归为「一般反馈」。
- B 档：停在需求字段组预填核对，头部紫色「需求 · 功能建议」徽标。
- C 档：自动填入示例并触发整理，停在需求字段组核对，含「类型由分析判定」提示。

手动逐步评审路径：

1. 选档位 A → 右下角打开面板 → 点「导出报表提示没有权限」→ 等待客服回复与分析引导 → 点「仍未解决，提交反馈」→ 观察：**空白三术语框、全必填、对话内容被丢弃** → 填三框 + 勾选 → 提交 → 「我的反馈」：**无类型徽标、类型筛选禁用**。
2. 切档位 B（流程自动重置）→ 重复提问 → 点「仍未解决」→ 观察：**已预填的核对表单**（可编辑，含「改为直接填写」）→ 切到手填 → 观察：用户语言 label、每框示例、「不确定，由团队补充」勾选、快捷场景预填 → 提交（仅一个必填框 + 确认勾选）→ 「我的反馈」：**类型徽标 + 类型筛选可用**，可切「需求」验证筛选。
3. 切档位 C → 点「我想提出一个功能建议」→ 点「仍未解决」→ 观察：**单框自然语言输入** → 输入含「希望/建议」的文字 → 点「整理为结构化信息」→ 观察：分析中状态 → 预填核对表单显示**需求字段组**与「类型由分析判定」提示 → 确认建卡 → 「我的反馈」出现「需求」徽标。
4. C 档再走「直接原样提交」：不整理直接建卡，标注「待团队分析」；表单内降级说明指明模型不可用时回落 B 档手填。
5. 档位切换、新咨询、已解答分支均可重复体验；A/B/C 状态互不串档。

## 边界

- 宿主、对话、Agent 分析、建卡与列表均为本地模拟，不连接后端或真实模型；类型判定用关键词规则仅模拟分析过程，不作为生产方案。
- 日期基准 2026-11-17；反馈与草稿不持久化，刷新即重置。
- 本稿只覆盖直接反馈通道与列表类型展示；【2】稿的答疑来源、历史、流转、结论等能力不在本稿重复。
- 类型徽标颜色、字段文案为评审样式，最终以设计令牌与 i18n 落地为准。

验证中修复一处真实缺陷：inline handler 直接写 `form['x']=…` 会被 `textarea.form`（null）遮蔽导致表单无法输入，浏览器与 jsdom 同样报错；已统一改为 `setField` 等函数调用。

需求链路视觉强化（同轮补充）：分析引导条与核对表单头部增加类型徽标（紫色「需求 · 功能建议」/ 橙色「问题」）；A 档需求场景显示红色「现状断点」提示；方案栏增加「一键演示」直达关键帧。
