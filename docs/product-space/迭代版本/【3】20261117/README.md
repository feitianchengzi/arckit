# 【3】直接反馈体验优化：问题反馈降门槛与需求提交通道

## 背景

「仍未解决 / 直接反馈」是智能客服的逃生通道。评审反馈集中在两点：三个结构化输入框（问题位置 / 实际现象 / 期望结果）对用户是内部术语，理解门槛高；当前只实现问题反馈，用户想提功能建议时没有清晰入口，通道会把一切归为「其他」。

本迭代不新增系统边界：仍属【2】定义的外部业务系统集成 SDK 能力，只优化直接反馈表单的输入体验、与对话上下文的衔接，以及需求在提交、列表、管理端的类型感知。

## 核心结论

1. 设计稿【2】本就带字段引导语，工程实现丢失了 placeholder——先修回归。
2. 最严重断点是与对话上下文脱节：客服已分析出的信息被丢弃，用户重填空白表单。
3. 需求路径已存在于对话流（Agent 自主分类 + 需求字段组），缺的是直接反馈通道、列表徽标与管理端的类型消费。
4. 对话流程的既定约束「类型由 Agent 分析、不询问客户」不被推翻；直接反馈通道是否允许客户自报类型，列为待拍板项（方案文档 §6）。

## 优先级

- P0（纯前端，半天）：恢复 placeholder、用户语言 label、必填放宽为「不确定」降级、预填核对衔接、说明文案改写。
- P1（1–2 天）：我的反馈类型徽标与筛选、入口需求文案、管理端 `request_type` 分流。
- P2（需决策）：单框自然语言 + 机器结构化核对（推荐复用会话分析链路的 B2），手填表单保留为模型不可用时的降级。
