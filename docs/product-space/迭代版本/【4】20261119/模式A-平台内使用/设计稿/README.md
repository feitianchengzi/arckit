# 模式A · 平台内使用 · 交互设计稿

打开 [squeeze-flow.html](squeeze-flow.html)。单文件、零依赖、双击可开，无需构建、网络或后端依赖。本稿已按交接文档 §6.3 重写为**复刻 ArcOrbit 桌面端真实外壳**的形态：内联 `visual-tokens.css` 令牌与 `styles.css` 组件类名，语义与真实 Work / Feedback 页一一对应。背景为示例项目「云协作 · 导出权限」，覆盖「反馈 → 挤压区 → **开启讨论 → 多数决确认 → 摘要 → 待办 → 风险门禁/执行 → Agent 提问**」全链路。

## 结构基线：讨论门槛 + 详情/沟通空间职责分离 + 多数决

已拍板的三条产品规则（方案文档 §3 约束 6/7）：

| 规则 | 内容 |
| --- | --- |
| **默认无讨论区** | 反馈进入的待办默认**未开启讨论**：详情没有讨论状态区域，只有「开启讨论」主按钮（徽标「未讨论」） |
| **职责分离** | 开启后详情回显**摘要卡**（徽标/议题/最近 1 条观点；有结论时为结论一行 + `task.decision` 回写说明 + Agent 过程摘要）+「进入沟通空间」；议题/观点/草案/投票/全文全过程在**沟通空间**（侧滑一等视图） |
| **多数决确认** | 参与者 = 人类用户（**Agent 常驻但不计入分母**）；参与者栏**默认显示参与成员头像**，点「＋ 添加成员」弹出**项目成员选择器**（仅列已加入本项目的成员，已在讨论中的禁用并标「已参与」），点选即入列（入分母 + 站内通知），非参与者可「加入讨论」；**起草结论草案（起草人自动赞成）→ 赞成 > n/2 → 任一参与者显性点「通过结论」；单人参与者提交即通过**；通过后回写 `task.decision`、离开挤压区、出拆解草稿，Agent **异步生成过程摘要（不阻塞流转）** |
| **未讨论风险门禁** | 未开启讨论的任务**可直接变更状态**，但目标为执行/验收时弹**阻断式「未经讨论决策」风险确认**；进入待办、标记阻塞不拦 |

## 界面结构（复刻真实外壳）

- **左侧栏**：12 项主导航，Work、Feedback 为可用页；挤压区条数回写 Today 徽标。
- **Work 页**：控制轨（首位「挤压区」chip + 七态 + 搜索 + 筛选）+ 左表格（讨论徽标列）+ 右详情。
- **详情（状态与依据）**：attention 提问条 → 身份区 → 上下文事实 → 任务详情 → **讨论区（未开启 = 仅「开启讨论」；已开启 = 摘要卡 + 进入沟通空间）** → 拆解草稿 → 子任务树 → **状态流转（进入待办/开始执行/标记阻塞 + 风险确认面板）** → Agent 执行上下文折叠视图。
- **沟通空间** `#reviewSlide`（640px 右侧面板，头部带任务上下文副标题）：**参与者栏 = 头像栈 + 分母计数 + 「＋ 添加成员」/「加入讨论」**，点「＋」弹出项目成员选择器下拉（点选入列）→ 分节视图：`议题` / `观点`（左侧头像 + 气泡式消息时间线，Agent 气泡蓝底、头像深色）/ `Agent 提问` / `结论草案与投票`（草案卡 + **赞成/反对进度条** + 投票 + 过半后「通过结论」）/ `结论与确认`（结论卡 + 确认统计 + 过程摘要）/ `系统事件` → 底部发言框。
- **Feedback 页**：FB-105 默认选中为演示入口，「进入挤压区」回 Work。
- **评审路径浮层** `#reviewPath`：默认折叠，含身份切换（王珂/林晓/Agent）、模拟提问、重置、事件日志。**无演示条**。

## 手动逐步评审路径

1. 初始：挤压区 = 2（T-1041、T-1042「未讨论」），七态合计 = 8；T-1041 详情**只有「开启讨论」**，无讨论状态区域。
2. 点「开启讨论」→ 沟通空间打开：参与者 = [王珂]（开启者自动入列）、**Agent 初步分析**已写入、事件 `discussion.opened` + `agent.preliminary_analysis`。
3. 切身份 **Agent**：无起草/投票/添加按钮，提示「不计入投票分母」，仍可发观点；切回王珂。
4. 切**林晓**（未入列）→ 显示「加入讨论」；切回王珂，参与者栏点**「＋ 添加成员」**→ 弹出项目成员选择器（4 名项目成员、头像 + 角色，王珂已参与禁用）→ **点选「林晓」**→ 入列，分母 = 2（事件 `participant.added`，选择器自动关闭）。
5. 王珂**起草结论草案** → 提交后自动记赞成 **1/2**，显示「未超过半数，暂不能通过」，无通过按钮。
6. 切林晓 → **投赞成** → **2/2** 过半 → 出现「**通过结论**」→ 点击 → 结论生效：离开挤压区（zone 2→1）、回写 `task.decision`、拆解草稿出现、事件 `discussion.approved`。
7. 等待约 1 秒 → **Agent 过程摘要**生成（详情摘要卡 + 沟通空间均展示；期间显示「生成中…（不阻塞流转）」）。
8. 关闭沟通空间 → 详情确认拆解草稿 → 3 子任务；「进入待办」→ pending → 「开始执行」→ **已开启讨论不弹风险** → in_progress。
9. 「模拟 Agent 提问」→ 详情 attention 条 → 回复关闭；执行上下文含 `task.decision` 一行，**不含观点全文与过程摘要**。
10. 点表格讨论徽标 → 直达沟通空间（第二入口）。
11. **单人路径**：切 pending chip → T-1039 → 开启讨论（分母 1）→ 起草提交 → **立即通过**（无通过按钮，统计 1/1）。
12. **风险门禁**：回挤压区 → T-1042（未讨论）→ 点「开始执行」→ 弹「**未经讨论决策**」→ 返回则状态不变 → 再次确认 → 落 in_progress（事件 `task.state_changed`）。
13. Feedback 页 FB-105「进入挤压区」→ 回 Work，新卡片徽标「未讨论」，`card.squeezed`。
14. 「重置演示」→ 全部复位。

## 边界

- 全部为本地模拟，不连接后端/模型；投票、通知、摘要生成为交互触发 + 定时模拟。
- 本稿**复刻桌面端外壳与类名**，Web 落地按落点表分端实现到 `todo-web`。
- 日期基准 2026-11-19；刷新即重置；无演示条，引导在默认折叠的 `#reviewPath`。
- 只覆盖模式A 站内链路；PaaS 事件面见 [../../模式B-PaaS数据驱动/设计稿/](../../模式B-PaaS数据驱动/设计稿/)。
- 沟通空间 P0 为「现有评论流升格侧滑」，是否与反馈会话统一原语见方案文档 §6 待拍板项 6；多数决机制已拍板（§6 项 7）。
