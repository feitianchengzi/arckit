本稿聚焦 Work 挤压区与 Feedback 链路；点击侧栏 Work / Feedback 继续评审。

沟通空间

过程性行为：议题 / 观点 / 结论；结论回写为待办处理依据

评审路径
  1. Work 页控制轨：首位「挤压区」chip + 七态 chips；挤压区是面板状态段，不进七态计数。
  2. 反馈进入的待办默认未开启讨论：详情只有「开启讨论」入口，无讨论状态区域（徽标「未讨论」）。
  3. 点「开启讨论」→ 进入沟通空间，Agent 常驻并自动给出初步分析；参与者栏默认显示参与成员头像，点「＋ 添加成员」从项目成员选择器中点选（计入投票分母）。
  4. 成员起草结论草案 → 多人需超过半数赞成（Agent 不计入分母）→ 显性「通过结论」；单人参与者提交即通过。
  5. 通过后：结论回写 task.decision、卡片离开挤压区、拆解草稿出现，Agent 异步生成过程摘要（不阻塞流转）。
  6. 详情状态流转：进入待办 → 开始执行；未开启讨论的任务直接执行会弹「未经讨论决策」风险确认。
  7. 「模拟 Agent 提问」→ 详情 attention 提问条；回复后关闭。
  8. 执行上下文只读 task.decision 一行；讨论全文、观点与过程摘要均不注入。
  9. Feedback 页 FB-105「进入挤压区」→ 回到 Work 新卡片，形成完整链路。
