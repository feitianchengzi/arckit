# 模式B · PaaS 数据驱动 · 交互设计稿

打开 [paas-integration.html](paas-integration.html)。无需构建、网络或后端依赖。背景为外部系统「Acme 数据平台」——一个不打开平台 UI、只把 Arckit 当 PaaS 消费的第三方工作台；本稿覆盖「订阅配置 → Webhook 事件日志 → API 调试台 → 外部 BI 看板」四段，不重复模式A 站内链路的交互细节。**事件源是服务端既有的 `project_events`（事务内写入），本稿的推流模拟其对外投递层**——实现属后续 P1，契约见 [../PaaS集成方案.md](../PaaS集成方案.md) §4.2（含与既有事件名的映射表）。

## 界面结构

- **顶部**：标题 + 一键演示按钮 + 事件计数。
- **左栏**：外部系统导航（订阅配置 / 事件日志 / API 调试台 / BI 看板），底部标注「外部视角 · 未登录平台」。
- **主区四段**：
  1. **订阅配置**：Webhook 端点、订阅事件类型（共享 README §7 六类）、签名密钥、投递语义说明。
  2. **事件日志**：收到的事件流，逐条可展开 payload JSON（含 `event_id` / 签名头 / 投递尝试），可标记失败重试。
  3. **API 调试台**：选择 endpoint 与 apikey scope（`read` / `write` / `discussion`），发送后显示 mock 响应——含 scope 越权 403 演示。
  4. **BI 看板**：消费事件聚合出的卡片进区数、决策通过数、拆解子任务数、Agent 提问数、状态跃迁数与漏斗条。

## 手动逐步评审路径

1. 打开「订阅配置」→ 填端点、勾选全部六类事件、复制签名密钥 → 点「保存订阅」→ 观察：**订阅成功回执 + 投递语义说明**（至少一次、HMAC-SHA256、`event_id` 幂等、退避重试、死信）。
2. 点「模拟模式A 全链路推流」→ 切「事件日志」→ 观察：**`card.squeezed` → `discussion.opinion_added` → `discussion.decided` → `task.decomposed` → `agent.question_raised` → `task.state_changed` 依次到达**，每条带 `event_id`、时间、`200 OK · attempt 1`。
3. 展开 `discussion.decided` 的 payload → 观察：**`decision{verdict, rationale}` + `discussion_digest` + 项目/仓库上下文**——与模式A 卡片上下文面板逐字段对应。
4. 展开 `agent.question_raised` → 观察：**`question` 与 `blocked_on`**，对应外部 @ 责任人/值班告警场景。
5. 切「API 调试台」→ 选 `GET /tasks/456/context`、scope=`read` → 发送 → 观察：**返回上下文 + 讨论结构摘要（无全文）**；scope 切到 `discussion` 再发 → 可读讨论全文；用 `write` scope 调 `DELETE /tasks/456` → 观察：**403 越权拒绝**。
6. 切「BI 看板」→ 观察：**数字与漏斗已按收到的事件聚合**（外部数据驱动不依赖平台 UI）。
7. 点「演示投递失败重试」→ 观察：**失败 → attempt 递增 → 最终 200**，死信入口提示。
8. 刷新页面重置；演示可重复点击。

## 边界

- 端点、事件、响应、看板均为本地模拟，不发出真实网络请求；payload 结构以 [../PaaS集成方案.md](../PaaS集成方案.md) §4.2 契约为准，实现属后续 P1 迭代。
- 事件源（模式A 交互）在本稿中以「推流按钮」代指，站内链路见 [../../模式A-平台内使用/设计稿/](../../模式A-平台内使用/设计稿/)。
- 日期基准 2026-11-19；配置与事件不持久化，刷新即重置。
- 签名算法、退避参数、看板样式为评审示意，最终以工程契约为准。
