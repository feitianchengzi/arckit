# 外部系统集成：智能客服与反馈交互设计稿

打开 [feedback-web.html](feedback-web.html)。无需构建、网络或后端依赖。背景为“云协作”外部业务产品示例，右侧为可收起的SDK浮层，并非独立客服系统。

## 两项使命

1. 智能客服：基于产品仓库答疑，支持文字/图片/音频输入；未解决时由Agent自主分析Bug与需求，按不同字段收集，客户核对确认后创建内部反馈卡片。
2. 我的反馈：搜索与时间筛选、查看完整咨询及双向沟通、结构化内容、卡片客户可见流转、处理结论、交付和验收；可持续补充原卡片。

## 点击评审路径

- 点击“如何导出月度报表？”：查看有出处的回答、来源说明、“已解答”分支，不建卡。
- 点击“操作异常”或“体验图片说明”：Agent自主分析 → 查看Bug字段 → 填入示例 → 勾选确认 → 创建卡片 → 查看生命周期。
- 新咨询 → 功能建议 → Agent自主分析 → 查看目标用户、场景、目标、痛点、替代办法等需求分析字段 → 核对建卡。
- 类型由Agent自主判断，不提供分类选择或切换按钮；可返回继续咨询、纠正事实并由Agent重新分析；缺少信息不能提交，编辑后撤销确认。示例填充仅用于体验。
- 我的反馈：关键词、时间、状态筛选；加载更多；查看已提交信息；查看内部人员回复；发送补充文字或图片。
- 查看待验收卡片：交付说明 → 确认验收 → 状态更新。查看暂不采纳卡片：决定依据、替代方案、补充请求复核。
- 收起、重新打开面板；切换宽面板；手机窗口全屏；重置演示数据。

## 边界

仓库引用和回答均为固定示例，不读取真实仓库；真实图片可本地选择、预览与发送，但不进行实际模型理解；语音为显式状态演示，不采集麦克风、不播放原音。内部卡片创建、流转及回复是本地模拟，不连接内部系统。日期基准固定2026-10-29。

反馈和补充保存至localStorage，咨询及草稿按原型咨询编号保存至localStorage（仅演示环境，不等同真实身份隔离）。点击左下角“重置演示”可恢复初始示例。正式版需补齐宿主Session、真实仓库检索和媒体模型、内部卡片契约、消息幂等、未读及状态事件同步。反馈一对多的内部任务关系仍由内部系统拥有，不向客户暴露私密流程。

## 验证记录

Chromium已验证：有来源的答疑及无需建卡结束、Bug与需求两条收集建卡流程、缺项拦截、编辑撤销确认、原卡片补充、流转查看及验收。两类卡片均创建成功，运行时无脚本错误；390px视口无横向溢出，桌面及手机截图已检查。

分类交互已修订：不询问“Bug还是功能”，无类型选择或切换按钮；事实不足时继续询问具体操作、现象与期望。原型关键词规则仅模拟Agent分析过程，不作为生产方案。

## 投产交互补齐（2026-10-30）

- “咨询历史”展示当前客户尚未提交的咨询；点击恢复对话、结构化草稿及待发送文字。创建新咨询保留旧咨询，历史弹层可返回当前咨询；暂无记录显示明确空态。已提交的咨询从独立咨询历史移出，在“我的反馈”中继续沟通，避免重复建卡。
- 工程历史读取失败保留当前对话并提供重试；不把失败显示成空历史。历史切换时先加载目标数据，成功后再替换内容；新咨询、切换咨询前若有未发送内容需用户确认处理，不静默丢弃。原型数据为本地模拟，服务失败话术由工程测试验证。
- 语音入口为“语音输入”，采集后转成可编辑文字，客户点击发送才提交。取消恢复原草稿，失败保留已有文字；不发送音频附件。原型明确提供转写示例，不采集真实语音；工程使用浏览器识别，不支持时如实提示。
- 删除工程额外加入的“AI 回答请核对 · 正式进展以处理团队发布内容为准”泛化页脚。咨询失败、反馈提交成功、待受理、处理结论等事实在对应状态准确表达，不以免责声明代替链路处理。
- 端到端验收须涵盖：提问 → 历史恢复 → 继续澄清 → 核对提交 → 我的反馈 → 团队回复 → 正式结论 → 验收/复核，以及网络失败、重试和重复操作。

### 咨询历史状态与操作契约

| 状态/操作 | 客户看到的结果 | 数据与提交边界 |
| --- | --- | --- |
| 打开历史 | 展示加载态；成功后展示咨询时间和当前项 | 仅当前项目/客户的独立会话，不展示他人内容 |
| 历史为空 | 暂无咨询历史，可返回或开始新咨询 | 不创建空会话 |
| 历史失败 | 历史暂时无法加载，可重试 | 保留当前对话，不伪装为空列表 |
| 选择历史 | 加载成功后恢复消息和结构化事实 | 清除上一咨询核对结果，防止将旧草稿提交到新会话 |
| 存在未发送内容 | 先确认是否放弃当前未发送文字/图片 | 取消切换时完整保留，确认切换才清理 |
| 继续咨询 | 新消息追加到选中会话 | 不新建反馈；使用原会话 ID |
| 新咨询 | 显示新的空白输入区 | 旧咨询可从历史恢复；第一条发送成功才落会话 |
| 核对提交成功 | 显示真实反馈编号并可进入详情 | 独立咨询关联反馈，只创建一次；原记录进入我的反馈 |
| 提交失败 | 保留核对信息及会话，可重试 | 不展示成功、不编造反馈编号 |
| 已提交后的继续操作 | 前往对应反馈或开始新咨询 | 不继续向已转换的独立会话发消息 |
| 服务不可用 | 清楚提示稍后重试 | 不显示虚构答案、伪转写、已转人工或已建卡 |

咨询历史展示方式以 HTML 设计稿为准：以整个宿主视口为参照居中弹窗展示（560px 宽、27px 内边距、16px 圆角、全屏模糊遮罩），不在消息区内插入列表；底部提供“返回咨询”“前往我的反馈”，选择记录成功后关闭弹窗，返回原聊天区域。支持点击遮罩或 Esc 返回，返回时保留当前咨询和草稿。加载、失败重试、空状态均在弹窗内展示。


## 全量缺口补齐设计契约（2026-10-30）

- 智能客服始终提供“仍未解决 / 直接反馈”，服务不可用不阻断真实反馈。点击进入手动事实表单，收集位置、现象、期望，允许补充截图；不要求客户猜测 Bug/需求类型，不伪造模型分析。核对后显式提交，失败保留草稿，成功进入真实反馈详情。无会话也可提交；有会话仅在服务端权限校验及事务关联成功后表示已关联。
- 咨询回答下提供“已解答”“仍未解决”：已解答展示结束状态和新咨询操作，未解决进入人工填写事实或继续咨询；均不自动创建反馈。代码/文档引用只有服务端提供真实来源时展示；未提供时不显示虚构出处。
- 草稿按网关、项目和客户作用域隔离；每个咨询保留未发送文字、已上传图片及客户编辑后的结构化字段，关闭/重开或切换后恢复。确认状态不持久化，恢复后重新核对。身份变更清空当前界面并重新加载目标客户数据，不回显上一客户内容。仅切换 token 刷新且客户不变时保留草稿。
- 咨询历史采用分页卡片，服务端返回真实首条客户消息摘要，不为标题读取每条完整会话。加载更多、失败重试、空态在现有560px弹窗内展示；消息分页可加载更早记录，保持时间顺序。
- 反馈详情在沟通/流转/结论上方提供“已提交信息”，展示客户实际提交字段、待确认项和原始描述，不以当前模型推断覆盖提交快照。
- 知识源配置按来源类型明确可用能力：代码仓库才走仓库索引；尚无导入实现的来源显示不可用及原因，不标记同步成功。项目目录缺失或多仓库覆盖不完整必须明确失败，禁止自动回退无关共享目录。索引状态只依据本次真实执行结果更新。
- 语音继续采用采集→可编辑文字→手动发送；不支持的浏览器如实提示可改用文字。不伪装已有跨浏览器供应商转写能力。

### 咨询草稿与自主反馈补齐契约（2026-10-30）

- 客户身份和项目是草稿隔离边界；每条咨询分别保存未发送文字、已上传附件对象引用和客户编辑的结构化信息。关闭后重新打开恢复原草稿；提交成功清理该咨询草稿。身份切换不显示上一客户内容，凭证刷新不清空同一客户草稿。
- 上传尚未完成的本地文件不能伪装为可恢复附件；关闭后提示重新选择。恢复附件不持久化临时签名 URL，按对象权限重新访问。
- 新咨询与历史切换保留旧咨询草稿；已有未发送内容时仍确认后切换，取消则保持原界面。核对确认状态不跨打开/咨询切换恢复，需要重新确认。
- 咨询历史采用服务端分页摘要，仅在选择一条时读取正文；提供“加载更多咨询”，不得为生成标题拉取所有咨询全文。
- 回答后提供“已解答”和“仍未解决，提交反馈”：前者明确结束当前答疑但不创建卡片，可继续提问；后者进入客户自主填写核对路径，客服不可用时也可使用。所有建卡仍须客户确认，不将本地结束标记表示为团队处理完成。

文档依据展示：仅展示后端从当前项目公开产品文档中核验后的来源。回复下方提供可展开的“查看文档依据”，显示文档路径、行范围和原文摘要；没有核验来源不创建来源标签。历史咨询恢复同样展示已保存的来源。原文按纯文本显示，不执行 HTML，也不将本地仓库路径直接作为外部链接。
