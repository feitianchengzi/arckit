# 【2】工程落地说明

本迭代已进入工程实现；原型仍是设计依据，不作为真实模型效果或上线证明。实现沿用外部系统集成的 SDK，V1 保持兼容，V2 提供“智能客服／我的反馈”两项入口。

新版 SDK 的视觉与交互基准为 [`设计稿/feedback-web.html`](./设计稿/feedback-web.html) 中的右侧“帮助与反馈”面板：桌面端窄面板及宽面板、移动端全屏、独立滚动内容与底部输入区。背景“云协作”是示例宿主，不属于 SDK；生产页面保留真实接口、身份校验和业务确认，不采用原型的模拟回答、示例记录或演示状态。

## 语音交互修订

当前产品语音入口按语音转文字输入实现：采集语音、转写进入输入框、客户编辑确认后按文字发送。不上传录音附件或自动发送识别结果；原型中的录音试听交互不再作为该入口的实现依据。浏览器不支持识别或识别失败时如实提示并保留文字草稿。服务端原生音频附件接口保留兼容，不等于当前 SDK 的语音输入流程。

## 已实现范围

- SDK：仓库答疑入口、咨询历史／新咨询、图片上传预览、语音转可编辑文字、手动发送及取消、Agent 自主分类后的结构化事实核对、明确确认后建卡。
- 原生音频理解适配器：真实音频经服务器解码与时长校验后输入音频模型；保留转写与观察供核对。未配置时明确失败，不伪装成已理解。
- 我的反馈：服务端搜索问题／沟通／正式结论，状态、提交／最近沟通日期筛选，完整分页沟通，原卡片持续补充，流转及结论详情、历史结论、验收与复核。
- 内部反馈台：统一沟通历史及媒体，正式结论发布、版本与客户响应；结论发布和客户验收不越过原任务状态机。
- 服务端：项目与客户隔离、历史对象权限检查、临时媒体访问地址、消息重试事务回执、结论乐观版本控制及客户响应幂等。

## DDD 与 TDD 落点

智能客服媒体规则与反馈生命周期规则分别进入 `services/workshop-api/domain/support`、`domain/feedback`；HTTP／模型／对象存储适配器留在外层。前端 `domain` 处理日期边界、核对状态及媒体约束，应用组件编排咨询、确认和原卡片跟进。

测试以可观察的业务不变量推进：图片首轮和续轮不得丢失、客户不能读取其他客户媒体、模型未配置不得谎称理解、实际语音超过60秒必须拒绝、同一消息重试不重复持久化、同一咨询确认不重复建卡、旧结论不得新验收、未完成任务不得因交付通知而完成。不是复制原型的固定回答或关键词分类。

已完成 SDK 69 项、内部反馈台 10 项单元／组件测试及两端严格类型检查、生产构建。后端全量 `go test -race ./... -count=1` 已通过，事务与权限测试使用一次性 PostgreSQL schema，包含实际音频解码与60秒边界验证。构建后的 SDK 已用 Chromium 在桌面及390px移动端验证图片预览移除、反馈搜索、详情切换、流转、结论和验收确认交互；该浏览器验证使用模拟 HTTP 契约，页面无运行错误或横向溢出。

## 补齐前审计记录（2026-10-30，历史快照）

以下记录补齐前发现的问题，处置结果见文末；不代表当前代码仍保留这些缺口。

### 已确认的功能与边界缺口

| 优先级 | 缺口 | 代码事实及影响 |
| --- | --- | --- |
| P1 | 客服不可用时的独立反馈入口 | SDKSupportPage 仅在 structured 存在时展示核对建卡；初始咨询失败或服务不可用且无结构化内容时，只有重试，没有独立填写并确认提交的入口。不能用虚假回答替代，应先补设计，再实现人工填写路径。 |
| P1 | 项目知识工作区隔离 | resolveProjectWorkspaceDir 仅选择一个仓库，无项目目录时回退共享 OH 工作区；多仓库覆盖与缺失时拒绝使用无关目录尚未闭环。存在跨项目错误答疑风险，需在实际部署中验证目录内容及隔离。 |
| P1 | 知识源同步状态真实性 | ReindexKnowledgeSourceHandler 在没有仓库时仍标记 synced；FAQ/文档等来源未按自身类型走独立导入流程，而是统一触发项目仓库索引。状态不能作为知识已可用的可靠证据。 |
| P1 | SDK 原地切换客户身份 | Todo 宿主通过销毁 iframe 隔离账号；但 SDKSupportPage 的 configured 监听只刷新列表等状态，AgentChatPanel 不因配置身份变更重新加载并清空当前内容。其他宿主原地 configure 切换身份时可能残留旧客户界面；后端权限校验不能替代前端清理。 |
| P2 | 咨询草稿恢复 | 历史恢复读取消息中模型生成的 summary；客户编辑的字段、未发送文字/图片未按咨询持久化。关闭 iframe 后丢失，与原型及设计说明的恢复描述仍有差异。 |
| P2 | 已提交信息展示 | 反馈详情已有沟通、流转、结论，但没有独立展示已提交结构化字段的区域；消息中的格式化正文不能完整替代字段核对视图。 |
| P2 | 已解答与未解决分支 | 新版聊天组件没有设计稿的明确“已解答”结束分支，也没有始终可操作的“仍未解决/提交反馈”入口，主要依赖模型返回 need_collect/clarification。来源也未作为独立可核验引用契约呈现。 |
| P2 | 历史查询规模 | 独立咨询与消息接口未分页，前端打开历史时对每条咨询额外读取完整消息生成标题；历史增长时会并发拉取大量无关正文，需列表摘要与分页契约。 |

以上需按设计先行的要求补齐状态和交互，再落实工程与回归。当前咨询历史弹窗和头部图标样式修复，不代表其他页面或业务分支已全部验收。

### 已实现但有明确限制

- 语音为浏览器 SpeechRecognition/webkitSpeechRecognition，不是所有浏览器、WebView 均可用；不支持时真实提示，尚无跨浏览器统一转写实现。
- Todo 当前仍为 API Key 接入；Session 模式不能仅靠前端切换配置替代宿主服务端的签发及刷新流程。API Key 模式不建立实时 WebSocket，使用30秒轮询。
- 客户与团队消息、正式结论、验收和复核均已有对应工程；真实 OSS、模型、网关及内部处理账号的完整闭环尚未在本轮复核中验证。

### 本轮验证

SDK 100 项测试、Todo 17 项测试、后端 go test ./handler 通过。上述通过结果仅证明现有测试覆盖的行为，不覆盖真实供应商质量、实际环境权限以及完整生产闭环。Todo 严格类型检查仍有前述既有错误，不能据此宣称全仓严格检查通过。


## 本轮开发落地结果（2026-10-30）

上述八项缺口已按设计契约完成工程处置：

| 缺口 | 当前实现 |
| --- | --- |
| 独立反馈 | 不依赖 AI 的事实表单、图片、明确确认、真实提交及失败重试；稳定请求回执避免重复建卡。 |
| 工作区隔离 | 禁止共享目录回退；按项目建立受控多仓库工作区，缺失仓库直接失败。部署必须显式挂载对应路径。 |
| 知识状态 | 仓库来源精确匹配 URL/分支，真实扫描失败不能标记成功；FAQ、文档、公共知识导入尚不支持，明确拒绝而不伪装同步。 |
| 身份切换 | 项目/客户变更清空并重建界面；请求中途切换身份不重放旧客户请求，同客户刷新 Session 可保持状态。 |
| 草稿恢复 | 按身份/咨询保存文字、已上传图片引用、核对字段与已解答状态；恢复后重新确认，未上传文件提示重选，不持久化签名 URL。 |
| 提交快照 | 详情单独显示已提交事实、未知项及原始说明，失败可重试。 |
| 已解答及依据 | 提供已解答、仍未解决/直接反馈分支；引用由服务端核对真实文档行号和内容，无依据不展示虚假来源。 |
| 历史规模 | 咨询摘要和消息均分页；列表不再逐项拉取全文，旧消息按需加载。 |

SDK 全量 115 项测试、Todo 17 项测试通过；SDK 严格类型检查与生产构建、Todo 生产构建通过。后端使用独立临时 PostgreSQL 实例执行全量 race 测试，覆盖客户隔离、历史分页、反馈重试幂等和真实文档依据等。Todo 既有严格类型错误不据此宣布消除。

本地浏览器验证独立反馈在身份失效时仍可填写，表单模式独立呈现并隐藏咨询输入区，错误如实显示。本轮浏览器预览使用无真实访问权限的身份，不能作为真实提交成功或供应商联调证据。

当前未部署、未提交 Git。FAQ/文档/公共知识导入适配器、跨浏览器统一语音转写尚非已实现能力；真实网关、OSS、模型及处理团队账号的生产闭环仍需实际环境验收。这些限制不能表述为只剩部署配置。
