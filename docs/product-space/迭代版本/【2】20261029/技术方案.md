# 【2】智能客服与反馈技术方案

核对日期：2026-11-09。描述当前源码实现、配置责任与验收边界；不将本地临时适配器当作交付能力。整体组件及链路见[技术架构](技术架构.md)，操作命令见[发布手册](生产上线依赖与发布操作手册.md)。

## 1. 接入与身份

推荐使用短期 Session：外部宿主后端持有长期 API Key，从已登录用户推导稳定客户 ID，向网关调用 `POST /workshop/v2/apikey/feedback-sessions`。Console 通过 JWT 调用 `POST /workshop/v2/user/feedback-sessions`。SDK 获得短期 `fbs_` token 后访问 `/workshop/v2/feedback/*`。

生产 HTTP 业务中间件不直接把 Bearer token 当作有效客户范围；网关必须验证签名、过期时间、issuer/audience，清除外部伪造身份头，再以内部共享密钥注入受信的项目、客户及会话 ID。只有 API 在线、SDK 配了 Bearer、签发成功仍不够，缺少网关范围注入会返回 401。WebSocket 另有服务端 token 校验路径，不据此推断普通 HTTP 已支持直连。

宿主收到 `ready` 后发送 configure/open；收到 refresh-session 后换发同一客户的新 token。每个消息同时校验 origin 和窗口引用。切换客户需清理原界面及作用域，不能只更换 token 字符串。生产白名单在 SDK 构建前配置；开发态允许本地来源不等于生产授权。

## 2. URL、SDK 与版本配置

| 配置 | 含义 | 注意点 |
| --- | --- | --- |
| `VITE_API_URL` | Console V1 基址 | 例如 `https://api.example.com/workshop/v1` |
| `VITE_WORKSHOP_V2_API_URL` | Console V2 基址 | 可为完整地址或同源 `/workshop/v2`；当前解析为浏览器绝对地址，避免 Axios 追加到 V1 |
| `VITE_FEEDBACK_SDK_PROJECT_ID` | Console 产品自反馈项目 | 不等于当前浏览的任意业务项目；必须存在且与自反馈服务端配置一致 |
| `VITE_FEEDBACK_V2_PROJECT_IDS` | Console V2 项目集合 | 至少包含自反馈目标项目，按灰度选择其他项目 |
| `VITE_FEEDBACK_SDK_URL` | 宿主嵌入入口 | 实际 alias/文件可达，HTTPS origin 正确 |
| `VITE_FEEDBACK_GATEWAY_URL` | Console 注入 SDK 的 API 网关 | 当前默认是固定公网网关；自建环境应显式设置，不能认为会从 `VITE_API_URL` 自动推导 |
| `VITE_SDK_PARENT_ORIGINS` | SDK 信任的生产宿主 origin | 逗号分隔，精确协议/域名/端口 |

根相对 URL 在 Axios 中仍可能附加到实例 `baseURL`。因此 V2 客户端统一解析完整 URL，保持共享鉴权、刷新和响应处理；不为个别接口硬编码重复前缀，也不修改网关来容忍错误路径。回归覆盖反馈列表和 Session 创建，预期不存在 `/workshop/v1/workshop/v2/`。

产品名称 V3 不改变 `feedbackV2Enabled`、V2 路由或 V1/V2 兼容合约。SDK `3.x` release 如沿用现有协议，发布 manifest 仍填写实际兼容的 `v1,v2`，不要仅为名称增加未经验证的合约。

## 3. 模型与项目知识

DeepSeek 文字模型配置为 `llm_model=deepseek/deepseek-chat`、`llm_base_url=https://api.deepseek.com`。项目模型 Key 由项目配置接口加密保存；配置响应仅提供是否配置及来源，不回显明文。项目 Key 优先，未配置时使用服务级 `LLM_API_KEY`；项目 Key 解密失败不是自动回退理由。

`OPENHANDS_CONFIG_ENCRYPTION_KEY` 由运维稳定保管。丢失或随重部署更换会使原项目 Key 无法解密。OpenHands 会话认证使用另一套密钥，不能把供应商 Key 填进 `api_key` 字段；供应商 Key 对应 `llm_api_key`。每次创建 Agent 会话下传模型配置，仅给容器设置模型环境变量不代表请求已配置。

文字模型能力不等于视觉能力：仅配置 DeepSeek 文字答疑不能宣布图片已理解。图片理解须另验模型原生能力、视觉开关与签名 URL 可达性。当前 SDK 语音是浏览器转文字并手动发送，不依赖原生音频模型；兼容音频附件接口另需原生音频模型和 ffmpeg/ffprobe。

知识就绪分三层验证：

1. 项目配置：`customer_code_repos` 有正确源、分支及同步结果，所有仓库为 `ready`。
2. 执行路径：API 与 OpenHands 同时能访问所传绝对目录；单仓库目录不等于 `OH_REPO_ROOT` 或共享 `OH_WORKSPACE_DIR`；多仓库链接均可解析。
3. 真实问答：提交仅靠仓库可回答的问题，核对结果与来源；问候白名单、health 200、同步请求已受理均不足以证明这一层。

配置及同步接口使用 V2 user 前缀：`projects/:id/code-repo`、`code-repos`、`code-repos/:repoId/sync`、`openhands-config`、`openhands-health`。保存后异步同步，继续查看实际状态及失败原因；不得把桌面 Runtime 的项目目录绑定当作客服知识源。

## 4. 媒体、事实、幂等与正式处理

- 上传先获得服务端限定客户前缀的 OSS 策略；发送只携对象引用及元信息，不接受任意公网 URL 冒充附件。历史访问重新鉴权并签发短期地址，不持久化临时 URL。
- Agent 判断 Bug/需求并收集事实，客户不承担分类职责。用户编辑事实撤销旧确认；只有核对确认后才建卡。模型生成的转写与观察是待核对材料。
- 发送使用稳定 `client_message_id`，建卡使用稳定 `client_request_id`；相同作用域、相同负载重试复用原结果，改变事实不能借旧回执覆盖。会话关联须在权限检查及事务内完成。
- 客户补充、团队回复沿用原反馈；正式结论版本与客户响应独立记录，不能用模型答复替代团队授权发布，不能因发送交付通知静默完成任务。
- 未实现的 FAQ/独立文档/公共知识导入、统一跨浏览器语音识别保持明确不可用边界。

## 5. 时间数据升级

新 Agent 表字段使用 `timestamptz`，旧表升级由 `database.Migrate` 中的 `migrateAgentTimestamps` 执行：检查当前 schema 中实际无时区列，要求 `LEGACY_AGENT_TIMEZONE`，按 `AT TIME ZONE` 转换，重复执行不再次偏移。

迁移负责人先核实旧服务写入时区、服务器/容器变化和样本时间，再选择原时区；不是选择期望显示的时区。历史统一为 UTC 才填写 `UTC`，统一为北京时间才填写 `Asia/Shanghai`。混合来源先备份、停写、按有证据的记录范围归一化后迁移；不得默认所有历史属于同一时区。

本次本地库出现混合写入：本机 Go 写入的 8 条消息及 3 个会话按日志核对校正，既有更早记录未统一平移；随后升级字段。该记录范围仅是本地修复事实，不是生产修数脚本。生产需独立审计。

迁移后 API 返回带偏移的 ISO 时间，浏览器按本地时区格式化。不得再在前端统一减八小时；那会破坏已经正确的反馈消息与其他时区客户。回归使用真实 PostgreSQL，验证时刻、重复迁移、UTC 读取、新记录和缺少原时区时失败；见 [时区回归测试](../../../../services/workshop-api/database/agent_timestamp_test.go)。

## 6. Markdown 与详情导航

SDK 两类会话复用 `MessageContent`，助手正文使用 `react-markdown`；Console 统一沟通页同步渲染。保留标题、列表、加粗、行内/块代码和链接语义，适配窄面板长文；跳过原始 HTML，过滤危险协议，外链带 `noopener noreferrer`。客户原文、已提交事实及引用摘录按纯文本显示，避免修改客户陈述。

「我的反馈」详情 Tab 在既有 `.sdk-workarea` 滚动容器内使用 `position: sticky; top: 0`，不透明背景及高于输入栏的层级；横向留白随窄屏内边距调整。只固定三个详情 Tab，不改变咨询/反馈导航或业务状态。实际滚动、深色、窄/宽面板和 Tab 点击仍应列入真实宿主验收。
