# State Driven Loop 隔离评估场景

供能力维护者评估 `using-arckit` 与 `arckit-development-ledger`，不属于技能运行时输入。结构测试不能证明 Agent 已按方法执行；观察过程和结果，不以 Gap 数量、文件数或全部 upheld 作为通过指标。

## 场景

| 输入 | 观察要求 |
| --- | --- |
| 已有复杂原型，要求新入口、旧入口保留和会话恢复 | 在 Case 内比较独立关键问题，不能把最终交付整体装进一个实施 Gap；按当前定义显式考虑不变量 |
| 小型共享配置，调用链和方案已经明确 | 不按文件、入口或能否单独测试机械拆碎；允许同一结论的实现、验证和事实同步同轮 |
| 执行中出现一个独立关键不确定性，已有 Gap 过宽 | 区分当前结论所需信息与独立问题；必要时可信重新界定，保留所有未完成义务，fresh-read 重选 |
| 新反证否定既有完成主张，另一问题已经修复 | 读取当前不变量定义，重审所有实际相关责任；不以局部修复或测试总数覆盖其他未决主张 |
| 替换模板数量、名称、顺序和定义；另有外部依赖阻塞 | 依据当前 State 动态理解，旧提示词不预设语义；外部问题不必伪装成不变量问题才能被处理 |

每个场景保存用户任务、开轮、工具轨迹、transition、closeout 和 fresh-read。核对目标关系、选择理由、具体证据、未决保留与事实载体更新；区分方法问题、执行偏差和协议问题。不得因为已知某轮有 bug 就要求所有不变量同时降级。


## 执行边界

验证 Loop 如何使用专业能力时补充以下场景（不修改专业 skills 的方法）：

- 选定 Gap 只要求根因判断，所选专业能力还包含后续修复流程：Loop 按当前完成条件收口，不因能力包含更多步骤而扩大目标；保留结论与未完成义务，必要方法与边界冲突时明确报告。
- 用户待解决的故障直接原因已有可信证据且预期有效：允许直接修复；直接原因未知时先完成诊断，提交并 fresh-read 后再选择处置，不合并未知诊断与依赖它的修复。
- Definition skill 不需要更新文档：不能把其 `not_applicable` 直接映射成 Case 不变量不适用，也不能以文档已更新代替判断。
- 当前不变量条文很长，且名称、数量、顺序不同于先前版本：Agent 根据入口读取当前事实源，不依赖 prompt 内预设条文或状态转储。
- 恢复线程时历史计划未全部实现：从源记录区分计划、实际接受变化和未完成义务；场景报告不能替代 Ledger 事实。

在 `mktemp -d` 创建的独立工作区运行目标 skills，只允许修改隔离 repo 和证据目录，不写真实项目、安装副本或外部系统。保存实际执行证据后再判断结果；场景存在不表示已经验证通过。

## 选择机制回归场景

以下是隔离行为验证输入，不代表已执行通过：

| 场景 | 观察重点 |
| --- | --- |
| 维护 skill 的指令、脚本与模板 | 识别为实现载体，区分文件完成、生效与行为验证 |
| 必须运行实验才能决定方案 | 强制先探索；负结果可完成探索，未回答未知则 partial；不抢先正式采用 |
| 原型可用，正式预期尚未接受 | 先建立相关预期，再重选兑现；允许复用原型但重新验收 |
| A 模块预期齐备，B 尚待澄清 | 只按实际共享依赖判断 A 资格，不设置全 Case 阶段屏障 |
| 多个紧密相关的小型预期调整 | 可合并共同验收，不混入正式兑现；重要独立取舍单独处理 |
| 修复所需预期有效，原因已知 | 直接实现，不强制重复定义与诊断 |
| human 问题与独立 agent Gap 同时存在 | 保留全部候选，Agent 判断是否可继续独立工作 |
| 仅授权探索或文档定义 | Review 按授权范围闭合，不扩张到完整产品实施 |


## 结果边界与上下文复用

| 场景 | 观察重点 |
| --- | --- |
| 已定约束内比较批次参数，首轮只取得部分实验数据 | 可以续做同一个技术决定，不因曾标探索强制换 Gap；如果实验推翻架构前提则重新选择 |
| 连续多轮维护同一 skill | 引用已接受的稳定上下文，逐轮更新结果、前置与验收；生效方式变化时重写上下文 |
| 大实现工作前提已定，与一个小但影响多处的权限取舍并存 | 按推进价值与决定影响选择，不按文件数量、陌生程度或耗时拆分 |

## 仅依赖 skill 内容的概念与边界

业务项目可提供用户要求、有效规范和源码；Agent 的机制依据仅限目标 skills 及其明确依赖的随包资料，不注入本仓库 spec/tech 或历史讨论。这些场景是验证输入，不代表已实际运行。

| 场景 | 观察重点 |
| --- | --- |
| 十万条订单导出，可行性影响方案；已有权限、视觉与任务框架 | 能沿读取入口找到随包示例，区分实验观察、正式预期与兑现；负实验结果不自动降低要求，也不照抄示例的阶段顺序 |
| 接口完成后开始联调；在未改变约定的前提下调整内部批次 | 继续同一验收结果，不因动作首次可做或实现手段变化重选 |
| 实现中的普通测试失败；另一分支证据推翻共享权限前提 | 前者可在当前 Gap 定位修正；后者保存证据重选，不把两者都当普通排障或都拆为诊断 Gap |
| 用户报告未知按钮故障；另一分支已提供可靠直接原因 | 未知时诊断后重选；已知且预期有效时直接修复，不重复定义或调查 |
