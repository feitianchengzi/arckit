# 原型消费与跨域同步

visual 独立维护策略、Tokens、组件和主题；interaction 的完整可操作原型应用这些规范。没有适用规范时原型采用极简线框，有规范时不能以“交互与视觉分离”为由忽略规范。

更新既有项目时同时核对 CONVENTIONS；仅同步与已授权变更冲突的旧条款，保留项目特有约束，不覆盖整份规范。

## 输入与输出

输入包括原型引用的规范版本、缺少的组件/状态、已确认设计依据。判断是已有规范可覆盖、规范投影补充，还是需要探索的新方向。输出具体规范路径、主题、变更及受影响原型，不替 interaction 决定业务行为。

## 消费约定

- 可提供从 Tokens/主题到 CSS 变量的可重复映射；记录来源和生成/读取方式。映射不成为第二份手工维护的数值事实。
- 不把页面专属布局强行变成全局组件规则。组件规范保留语义、变体、尺寸、状态与 token_refs。
- 业务页面视觉验证使用 interaction 正式或候选原型；visual 的 style-preview 负责系统组件及主题预览。

## 变更检查

1. 读取索引和已有关系，查找消费该规范的原型和映射。
2. 同步本域的 brief、Tokens、组件、主题和预览；记录破坏性 token 改名、状态和尺寸变化。
3. 回传受影响 interaction 路径、重建映射方法和需要检查的布局/状态。跨域写入由具备授权的 Agent 明确接续，不隐式导入或调用其他 skill。
4. 未完成原型更新时列出待同步项；候选依赖旧基线时标记过时或提出重基线需求，不能静默改变对比条件。


交接不构成强制阶段或人工等待。同一 Agent 可在当前授权和 selected gap 内显式使用 interaction 完成同一结论的原型同步；新发现的独立取舍回传 Agent 决定。仅缺少同步动作不能被描述为新的审美批准需求。
