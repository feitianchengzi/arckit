# 视觉探索与采纳

## 落点与输入

视觉候选位于 `arckit/visual/_explorations/<topic>/`，包含 `exploration.md` 和 `options/<name>/` 下按需建立的候选 brief、Tokens、组件、主题和样式预览。探索索引独立，正式 INDEX 只链接探索入口。
读取现有正式策略、用户方向及相关交互任务。无正式策略时允许在候选中提出明确标识的假设，不能为生成预览先写成正式品牌事实。

## 比较

记录问题、范围、固定条件、基线路径及版本/内容摘要、候选意图与入口、权衡和待决定项。没有基线时写明尚无及输入来源。状态采用候选 / 已采纳 / 部分采纳 / 未采纳 / 已过时。
固定交互和样本内容比较视觉方向；需要业务页面验证时向 interaction 提供候选规范路径，由其建立候选页面，不在 visual 另养正式业务页面。联合探索的比较与采纳记录选一个主题文件为主，另一侧引用，无隐藏 skill 调用。

## 采纳

1. 读取用户明确选择或已有授权，不重复要求批准；没有依据时交付比较材料并列待决定项，不自行批准审美。
2. 检查基线是否变化，变更影响候选时标记过时并核对，不能覆盖新的正式规则。
3. 支持整案或部分采纳，记录来源、采纳部分、未采纳部分、依据和正式目标。
4. 更新正式 brief、Tokens、组件、主题和预览，解决组合后色彩角色、字号、密度及状态冲突。正式规范自身完整，不能让使用者继续拼装多个候选。
5. 将具体视觉变更与影响范围交接给 interaction，同步原型后检查完整体验。尚未同步的明确列出，不称全部完成。
6. 探索记录保留选择依据；正式正文只描述有效预期。候选不因被实现而自动获选，正式规范不因上线停止维护。

纯探索不更新正式 feature-matrix。对开放问题只回传结果，managed-case 由当前 Agent 汇总，不由本 skill 写 Case。


## 结果与执行边界

按 [设计产物结果契约](../../_arckit_shared/design-result-contract.md) 返回结果。仅要求制作和比较时，候选已完成但尚未采纳不构成本轮人工阻塞；要求采纳时才按当前必要决定报告 needs_human。跨域交接不强制另开执行者、轮次或 gap，同一 Agent 可在当前授权与目标内使用两种能力同步同一结论。
