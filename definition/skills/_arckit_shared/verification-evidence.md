# 验证产物与证据

检查结果是否符合预期、生成相应验证文件前读取。异常跟进和根因定位属于诊断，沿用 debug skill 的 `arckit/debug/` 约定，不受本节输出重定向和清理规则管辖。区分维护的设计产物、可复用验证源码与本次运行证据；候选原型和人工维护的预期仍属于设计域，截图/日志等运行结果不因位于设计目录而成为正式事实。

- 接收当前 Agent 已明确的待验证主张、输出目录和保留方式；有可信 Case 时使用 `arckit/cases/evidence/<case-id>/<run>/`，复用 entry 已确定的本轮位置。没有 Case 的 standalone 工作使用独立系统临时目录，不为取证创建 Case，也不依赖安装或调用 entry skill。
- 运行前配置验证工具输出位置；新建或修改的验证脚本支持调用者指定目录，未指定时输出到临时目录并回报路径。原型/验证源码保留在设计域，运行产物不默认写回正式页面或 `_explorations/`。工具限制应在执行前处理或报告。
- 实际打开截图、读取报告并对照适用的预期，记录观察、差异和未验证项；生成文件或断言通过不代替视觉核验，截图不替代行为验证。
- 仅保留复核结论需要的证据，沿用已有记录表达验证条件、结果及引用。无 Case 的临时路径不作为持久证据提交；后续取得可信 Case 时再归档必要结果。已被引用的证据不覆盖、不随临时清理删除。
- 用户明确要求的交付图片或经确认的测试基线按正式资产维护；设计源码不依赖执行证据目录。不得仅为清理产物而迁移既有引用，历史迁移需保持引用和语义可达。
