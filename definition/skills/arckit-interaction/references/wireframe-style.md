# 原型呈现与视觉应用

## 选择依据

制作原型前查找 `arckit/visual/INDEX.md`、适用 brief、Tokens、组件和主题；记录具体来源路径和版本/内容摘要。存在多个产品或主题时按目标页面确认适用范围，不能只凭目录存在采用。

- 无适用规范：使用根目录 `wireframe-style.css` 的灰度、边框和结构，允许本地交互脚本；不自行决定品牌方向。
- 有正式规范：按规范应用色彩角色、字体、间距、密度、组件状态和主题；线框 CSS 仅作为可选布局基础，不能强制覆盖视觉规范。
- 规范部分缺失：有定义部分照用，缺失部分沿用可解释的现有规则并列缺口；需要新增视觉取舍时形成候选，不宣称已确认。
- 视觉探索：可用候选主题/组件，必须位于探索区，引用候选来源，不能覆盖正式 Tokens。

## 样式资源

页面可有 `prototype.css`、`prototype.js` 和场景资源；共享原型资源放 interaction 的 `_shared/`。视觉 Tokens/主题源仍在 visual；可读取或生成供浏览器使用的 CSS 变量映射，记录来源、生成方式、更新方式及主题。生成文件不独立手改数值。映射只解决呈现，不引入第二套视觉决策。
共享资源先搜索复用再扩展；通用组件样式与页面布局分开。可使用现有项目工具，不为简单原型引入无必要的构建或框架。记录启动方式和依赖，默认可本地预览。

## 连续体验

使用语义 HTML 和必要 data-kit 标注，不强制 `.wireframe-canvas > .device-frame` 或 `<details>`。设备框可用于预览，但不是产品界面的一部分。弹层按预期范围实际显示，可用 dialog/fixed/局部绝对定位；检查滚动、层叠和焦点，不用静态弹窗占位替代行为。
状态可经正常路径或独立场景工具触发。工具中标明样本与模拟边界，产品区域保持目标体验，不添加无关演示按钮。

## 变更影响

交互新增组件/状态时检查视觉覆盖并交接缺口；视觉更新时依据引用关系列受影响原型，重建映射后检查布局、状态和主题。候选基线受影响则标记过时或明确重基线，不静默改变比较条件。
