# ArcOrbit 项目事情台 · V2

打开 [index.html](index.html)。无需构建或服务，可直接在浏览器使用。

本稿是独立交互原型。数据、Agent 回应和 Auto 进展均在浏览器中模拟，不连接 Workshop、Codex、Runtime、仓库或外部平台。产品页面移除了演示标识和演示控制；这些边界集中在本说明中。语音按钮禁用，不访问麦克风。

## 与上一版的关系

上一版完整保留于 [unified-work-exploration](../unified-work-exploration/index.html)。本版使用独立目录、静态资源和浏览器存储键 `arcorbit-project-desk-v2`，不读取或覆盖旧版的体验数据。

## 新布局

- 左侧：项目导航、跨项目事情入口、项目资料、执行设置。
- 中间：同一件事情的主工作区域。默认显示事情详情；主动点击“协作消息”“查看消息”“先分析”或“暂停并讨论”后，在中间区域内弹出消息层，保留下面的详情；关闭或按 Esc 返回原位置。
- 右侧：事情列表、状态和其他筛选、搜索、底部固定的发起入口。打开中间消息层时，列表仍可见并可切换事情；切换事情会收起消息层。
- 列表项为 44px 紧凑单行，标题与状态同行；长标题省略，悬停或辅助技术可读取完整标题、项目和编号。跨项目范围在行内补充项目缩写。
- 中间底部：属于当前事情的固定输入区域，详情与消息共用同一草稿。
- 760px 及以下：右侧列表收起，通过顶部“事情列表”打开；选择后返回主内容。消息层始终限制在中间内容区域，不覆盖左侧项目导航或右侧列表。

事情详情的次级视图包含概览、资料与协作、成果与验收、活动；属性从标题附近打开紧凑面板。消息层使用紧凑标题、执行操作与输入框。详情顶部压缩为元信息、标题与操作以及轻量内容导航，移除了“事情详情／协作消息”切换栏。没有单独的 Chat / Automation 导航。

## 可体验的路径

1. ArcOrbit → #102“整理离线恢复方案” → 先分析。消息出现在中间，右侧列表保留。关闭消息层查看分析与目标，再开始 Auto。
2. ArcOrbit → #101“优化事情列表的键盘导航” → 开始 Auto。若 #102 正在相同工作区执行，则 #101 排队。
3. Feedback → #103“修复反馈图片加载” → 补充要求，或“暂停并讨论”。前者继续执行、下一步采用补充；后者暂停后在中间交流，再显式继续 Auto。
4. “发起事情” → 选择项目并发送首条内容。创建一件执行人为自己的待评审事情，进入中间的协作消息。后续输入继续归属同一件事情。
5. Workshop Todo → #104 → 在详情中处理决定，或先进入中间消息讨论。决定提交后继续原 Auto。
6. ArcOrbit → #105 → 检查成果、提出验收问题、标记解决和验收。评论、属性和其他状态修改也可操作。
7. 在任一事情中留下草稿，切换详情／消息、切换事情再返回，检查草稿保持。刷新后默认回到详情，事情与草稿仍保留。

Auto 每 15 秒读取一条对应事情的本地场景记录，更新进展、消息和结果；完成由该场景的明确结果表达，与计划条目数量无关。它不抢走当前选中事情或主动打开消息。处于讨论、暂停、等待决定的事情不会被这个计时器恢复。输入法正在组合文字时暂不刷新。

## 本轮范围

本轮检验布局、焦点、协作连续性与接近产品的表达。项目资源中的入口只提供相关事情导航，并未实现真实专业工作台。模型选择为本地偏好；结果与执行记录来自本机模拟。线程身份、状态恢复和幂等仅用于表达候选交互，不证明生产后端契约成立。

消息默认隐藏沿用之前的方向。中间详情在消息弹出时保持原位置并暂停交互，右侧列表继续可操作；关闭后恢复原详情。发起并交流、先分析、暂停并讨论属于用户主动进入交流的动作；单纯在详情中追加要求不会自动切换到消息页。

执行人保持为人。Auto 是推进方式，不改变执行人；发起新的待评审事情也不等于允许自动领取。停止执行保留事情状态，不能冒充完成或取消。

本版未修改生产代码或正式 `arckit/interaction/` 规格。页面文字中的完成、保存、执行仅对应本原型内部的本机状态。

## 详情内容优化（2026-09-16）

本次继续优化 V2；之前的三方案探索目录保持不变，不修改正式交互规格或生产功能。

- 概览：目标正文、共用完成标准、当前进展、按需展开的当前计划、已采纳约定、阶段成果和子事情。需要决定、暂停、排队、阻塞、完成与验收使用不同提示。
- 属性：标题区保留负责人、优先级、状态；小面板查看项目、父事情、执行模式等信息，进入现有编辑表单。未提供时间的数据不编造时间。
- 资料与协作：可添加文本或链接资料、预览和移除；加入/移出后续上下文；添加、编辑和采纳约定；保留评论。评论可先放入 Agent 输入框，再由用户发送。
- 成果与验收：分析阶段即可查看方案，支持手动添加文本或链接成果；完成标准与概览共用。完成后逐项勾选检查，有未解决问题或未确认标准时不能验收；目标变化会撤销检查勾选。已验收标准只读。
- 活动：按执行、决定与要求、协作、成果与验收筛选；新操作保存本地时间和来源。旧记录显示“时间未记录”，不伪造完整历史。有关联消息的记录可打开中间消息层并定位高亮。
- 消息：逐条提供“保存为约定”，可修改、保留为建议或明确采纳；关闭弹层回到原详情位置。

建议体验：

1. #101：编辑标准 → 资料与协作添加留言 → 保存为约定并采纳 → 回概览检查同步；还可添加子事情。
2. #102：未开始 Auto 时进入成果页查看离线恢复方案初稿；先分析后将消息保存为约定，再从来源返回消息。
3. Feedback #103：查看正在处理的工作和排查记录，补充要求或暂停讨论。
4. Workshop Todo #104：直接作出决定，随后在共同约定和活动中检查记录。
5. #105：打开成果与检查记录 → 逐项确认标准 → 提出并处理验收问题 → 验收通过。

`detail-content.js` 保存本地样本和页面投影，`detail-content.css` 管理新增内容样式；旧 V2 数据补齐新增字段，保留原任务、草稿与消息。新增事情没有自动填充假资料或检查证据。

能力边界：这里的文档正文、阶段结果、检查证据、上下文成员与活动事件全部是可操作的本地原型数据，不读取真实仓库，不触发真实 Agent，也不证明资料已经被模型读取。新增资料与成果支持文本/链接内容，没有实现文件上传和外部链接抓取。成果的版本为本地展示字段，没有真实版本快照和修改归属验证。检查勾选与约定采纳规则是本次候选交互，尚未写入生产验收契约。

## 当前工作与可变计划（2026-09-16）

删除所有自动填充的三步模板及 `step / plan.length` 完成判断。概览在目标后优先呈现当前工作、已取得的进展、尚待解决的问题和下一步。需要用户决定、外部条件或暂停恢复时仍使用顶部关注提示。没有进展事实时不填充“已完成”列表。

当前计划属于可选内容：#102 的方案讨论没有固定计划；#103 有针对图片问题的四项安排，可展开查看和调整。通过“调整安排”修改下一步及可选计划，清空计划后收起该区域。下一步不等于整个事情的完成率，计划项也不作为已经完成的证据。

- Auto 中：保存后显示待生效安排，当前工作保留；下一边界采用新安排并记录活动。
- 暂停中：保存安排后仍暂停，需要明确继续 Auto。
- 普通讨论/新事情：不自动产生通用计划，也不因没有计划而直接完成。
- 旧 V2 数据迁移：删除旧版自动生成的计划与步骤计数；保留事情、消息、草稿、资料、约定及验收数据。

`work-progress.js` 是交互原型的本地场景投影。预置事情使用不同的观察记录序列，普通新事情保留待明确的工作状态。用户改变安排后，停止继续播放旧场景结果；真实的语义重规划及后续执行尚未接入。Chat 补充按原有规则接收，并在概览保留最近采用的说明；不假装在浏览器实现任意自然语言推理。

## 列表与全局入口收敛

事情列表顶部压缩为两行：第一行“事情 + 数量 + 状态筛选 + 更多筛选”，第二行搜索；删除重复的项目名。列表项继续保持 44px 单行，底部让给列表滚动区域。

右上角的运行状态是可点击按钮，显示所有项目在此设备的执行、排队和需要处理的数量。点击展开概览，优先呈现需要决定、暂停恢复或等待条件的事情；点选事情切到所属项目与详情，并清除阻碍定位的筛选。面板支持外部点击、再次点击按钮和 Esc 关闭，后台刷新时保持展开。空闲时可以进入执行设置。

发起事情固定在右侧列表底部，右上角不再重复提供；与中间输入区域都使用底部操作位置。窄窗口通过“事情列表”打开列表抽屉，再从底部发起。列表筛选、搜索和关闭入口保持可用。
