# ArcOrbit：基于现有服务的 Product 与 Today

探索稿，供评审。所有数据、Agent、仓库提交、消息发送和业务操作均为本地模拟；没有连接真实服务。

打开 [index.html](index.html)。无需构建；本版使用独立的浏览器存储，不覆盖上一版草稿。

## 本轮结论

Product 和 Today 的主要体验可以基于现有待办/反馈服务器、GitHub 仓库以及 ArcOrbit 本机能力完成。需要新增客户端投影、Agent 工具和 Git 资料协作适配；本轮不增加服务端数据模型或接口。

| 内容 | 保存或读取位置 | 交互变化 |
| --- | --- | --- |
| 产品名称、组织、成员、仓库关联 | 现有 Workshop Project | Product 复用共享项目身份 |
| 理念、产品说明、核心资产 | 原有仓库文档 | 编辑先留本机，查看差异并提交后才共享 |
| 迭代名称、目标与历史计划 | 仓库中的计划文档 | 先保存草稿，单独确认提交 |
| 迭代关联工作与进度 | 现有待办 tags / state | 显式标签筛选，新迭代不自动归入旧工作 |
| 版本记录 | GitHub Releases | 计划、待办验收、版本发布分别呈现 |
| Today 人工责任 | 原 Work / Chat / Automation 与恢复对象 | 回到来源处理，成功后重新聚合 |
| Today 反馈新消息 | 当前用户反馈通知 | 查看与回复，未读与问题解决分开 |
| 空白 Idea、对话、编辑草稿、执行现场 | 当前设备 | 显示“仅此设备”，不承诺团队同步 |

不展示缺少来源的线上健康、增长、营收、渠道归因或跨设备运行总量。不用 GitHub Issues 再复制一份待办。复杂排期和独立云端迭代管理暂不纳入本稿。

详细能力判断、源码证据、数据边界与官方资料见 [backend-fit.md](backend-fit.md)。

## 页面与导航

原有 PERSONAL 的 Today / Chat，PRODUCT LIFECYCLE 的 Idea / Work / Automation / Release / Operations / Feedback，以及 ORGANIZATION 的 Organization / Engineering 均保留。Product 新增目录与产品详情，不整合或替换阶段页面。

Product 详情：总览、理念、版本迭代、核心资产、产品关系。产品协作按需展开；独立添加 Idea 页面仍以左侧可操作内容配合右侧 Chat 形态的对话。

Today：左侧展示“需要我处理”和“反馈新消息”；右侧展示“在此设备继续”和本机项目连接。按产品筛选，但不另建任务、消息或完成状态。完整的生产 Today 配置台与责任操作台继续保留，本稿仅演示聚合与跳转。

Lifecycle 目标页明确标注跳转示意，范围携带产品 id；从迭代进入 Work 还携带具体标签。切换产品清除旧标签范围；返回产品恢复资产页签。阶段摘要来自同一份演示状态。

## 推荐体验

1. Today：查看两条示例责任、两条反馈新消息，以及本机 Idea 草稿。
2. 团队反馈台 → Work → 验收通过 → Today：验收责任消失，反馈新消息仍保留。
3. 反馈新消息 → 查看并回复 → 标为已读：回到 Today，未读减少；任务与反馈进展不被清空。
4. Product → 轻记账 → 理念：直接修改，或点击“让 Agent 整理理念草稿”。采用建议后仍可编辑；“查看并提交”展示差异。
5. 确认提交（模拟）：资料状态成为“仓库资料已同步”。这与关联项目、关联仓库是不同结果。
6. 版本迭代 → 设定新迭代：新标签暂时没有工作。进入本迭代待办为空，查看项目全部待办，再显式关联到当前迭代；返回后进度更新。
7. 周末去哪：资料与对话仅在本机。可以完善理念，也可从“继续接入”创建不带仓库的共享项目，再关联已有仓库。
8. 演示选项：模拟来源不可用、资料分支不可写、仓库新版本或目录连接失败。草稿与最近记录保留，恢复后继续。

## Agent 与确定性能力

Agent 理解已有仓库和产品资料、提出目标与标签方案、整理草稿，并调用客户端提供的业务与 Git 工具。界面编辑和 Agent 修改作用于同一草稿，操作与输出可在协作区查看。原型的 Agent 只是预设建议和规则模拟。

客户端负责项目/通知/任务读取、权限校验、原对象写入、标签过滤、差异、失败状态、去重与源结果刷新；没有服务端 Product 或 Today 新对象。仓库同步需要遵守实际权限、资料分支与 PR 规则；本版只模拟直接可写分支和写入受阻，不模拟审批。

共享项目与本机 Idea 用显式映射衔接。无文件夹时 Agent 工作目录仍由 ArcOrbit 管理；材料目录、本机执行目录和资料仓库权限分别确认。

## 模拟边界

- localStorage 只承担原型存储；不代表现有服务已经增加这些能力。
- 每个示例项目用一条待办演示状态回流、标签过滤和关联反馈；不是完整任务列表实现。
- 资料冲突演示单字段人工选择；生产需要实际文件差异、版本校验与 Git 冲突处理。
- 固定资料路径只作为说明，真实整合优先发现并沿用仓库既有文档。
- “本机项目连接”只做查看/接入入口；完整 Setup、授权和 Runtime 资格仍由现有能力管理。
- 原型没有修改正式导航、服务端、生产代码或 canonical interaction/spec/tech。

## 验证与预览

验证范围：草稿/共享分离、提交失败保留、权限受阻、冲突核对、Agent 建议与直接编辑联动、迭代标签隔离与回流、验收责任消失、反馈已读/回复、来源不可用、刷新恢复、六个 Lifecycle 导航、空白/文件夹接入，以及 760px 布局。Electron 浏览器检查全部通过，刷新后数据保留，三张关键页在 760px 下无横向溢出，错误级控制台日志为 0。未验证真实后端、GitHub 写入或 Codex。
