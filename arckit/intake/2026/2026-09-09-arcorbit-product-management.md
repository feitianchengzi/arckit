# ArcOrbit Product 管理：已确认输入

来源：用户当前会话，2026-09-09。用途：保存实施目标和明确约束，不代表现有功能已经实现。

用户要求以 Product 为持续推进对象，完整实施 state-driven loop。

- 新增 Product 列表和详情，保留已有 Product Lifecycle 独立页面。
- Idea 是产品起点；独立 Idea 列表与添加页。添加支持文件夹（代码、设计材料）和无文件夹空白起点。
- 添加页同时提供可操作界面与对话，复用 Chat 消息列表和输入框；两种输入维护同一份内容，允许人确认修改。
- 尽量由集成在 ArcOrbit 内的 Agent 完成理解、计划和执行；代码承担确定性读写、校验、权限和恢复。底层能力可跨场景复用，UI 专注场景。
- 只使用已有 Workshop 待办/反馈服务器及 GitHub 仓库，不新增服务端模型或接口。
- 业务服务器持有 Project 身份、组织成员、仓库地址、待办与反馈；产品状态、理念和核心资产考虑通过本地 Git 仓库管理，再经 GitHub 与成员同步。
- 产品状态是明确维护的事实，不由任务活动推断；具体枚举和维护契约由实施过程合理收敛。
- 仓库资料必须有明确读写规范和维护 skill；尽量复用已有规范与技能，避免平行事实源。
- 本机持有目录绑定、对话、执行现场、草稿和未同步修改；空白 Idea 可先本机保存，不要求用户提前提供开发目录。
- Today 聚合当前用户需要处理的事项，支持反馈新消息和本机续接，并提供添加 Idea 入口；保留既有人工责任和配置工作台的完整能力。
- 明确排除：本轮不新增产品迭代管理或发布能力；不改动底层 ledger 为维持既有协议所需的 Iteration 对象。
- 原型是探索材料，其中迭代、发布和按活动推断项目状态的旧内容已被后续用户指令取代。

## 用户补充：Idea 存储与完成条件

- 未完成 Idea 录入的临时记录仅存本机，必须明确提示状态。
- 正式录入完成必须拥有 GitHub 仓库和对应本地工作目录。
- 正式 Idea 资料与产品资料共同存放在仓库 `arckit/product/` 下，通过 GitHub 同步。
- Idea 列表从本机临时记录和当前产品集关联的本地项目目录共同恢复。
- 本补充取代“远端项目关联即可完成录入”和“本机库长期存储全部正式 Idea”的设计；尚未完成部分仍可保存和恢复。
