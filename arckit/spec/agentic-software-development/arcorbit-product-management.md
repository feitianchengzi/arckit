# ArcOrbit Product 管理与 Idea 接入

## 产品目标与范围

用户围绕 Product 持续管理产品。Product 目录与详情提供长期上下文，原 Product Lifecycle 独立页面承载具体工作。现有 Workshop Project 提供共享身份；业务服务器不新增 Product、Idea、状态或资产接口。

本能力包括 Product 目录/详情、Idea 目录/独立添加页、产品状态、理念与核心资产、Agent 协作、仓库同步和 Today 入口。产品迭代管理与发布不属于本能力；底层 ledger 的既有 Project/Iteration/Case/Loop 协议继续有效。

## 身份和来源

- 共享产品以现有可访问 Workshop Project id 关联，名称、组织、成员和 Git 地址由业务服务器提供。
- 未完成 Idea 以稳定 id 保存在本机临时库，显示“录入未完成 · 仅本机”。正式 Idea 的 id 与资料位于关联项目目录的 `arckit/product/record.json`；本机只保留会话、绑定与同步控制，不保留另一份正式事实。
- Git URL 相同不自动合并两个业务项目。本地目录不作为跨设备共享身份。
- 用户可关联已有项目，也可确认后使用现有接口创建项目；已有成功结果落盘后继续未完成部分，重试不再次创建。
- 远端创建响应丢失时保留“结果待核对”，查询项目并由用户关联确定结果，不自动重放不具备幂等键的创建请求。
- 没有仓库的共享项目仍可使用 Work 和 Feedback；没有远程项目的 Idea 只在当前设备保存。

## 产品状态与资产

产品状态是人工声明或用户采纳的 Agent 建议，取值为探索中、推进中、暂停、归档；没有有效记录时显示“尚未设置”。接入成功、存在待办、执行活动、代码提交均不自动赋值。

状态变化只改变产品管理事实，不改变 Work state、Automation participation、活动执行或成员权限。暂停与归档仍可查看和恢复；它们不删除任何对象。

产品状态、产品说明、理念、目标用户、原则和核心资产引用由版本化仓库协议保存。原有 spec、interaction、visual、tech 文档作为权威正文被引用，不复制平行内容。业务 Project 身份与 Arckit 软件开发控制状态分开，产品业务状态不覆盖 ledger advancement。

界面和 Agent 通过同一维护契约读写资产。明确字段直接编辑；语义整理由 Agent 通过维护 skill 完成。新材料中的推测是建议，未经采纳不成为产品状态或长期定义。未知协议、不合法文件和引用冲突显示可恢复问题，不以默认值覆盖已有资料。

## Product 页面

Product 目录包含全部可访问项目和当前设备临时 Idea，支持搜索、状态筛选和添加 Idea。不因项目未绑定本地目录或任务同步失败而隐藏项目。

详情包括总览、理念、核心资产和项目关系。摘要注明待办/反馈/本机执行来源，提供原页面入口；不创建第二份待办或独立验收状态。状态和共享资料显示来源与同步状态。

从产品进入 Work、Automation、Feedback 或 Organization 携带产品身份；原页面仍能切换范围。返回产品恢复浏览上下文。目录纯查看不触发 Setup 安装或自动执行。

## Idea 添加

Idea 列表从当前账号的本机临时记录和当前产品集关联的本地项目目录共同恢复；按仓库记录中的稳定 Idea id 去重，临时与正式记录重复时以已验证的正式记录为准。未绑定目录、目录丢失和资料损坏明确显示，不能伪装为空列表。

添加 Idea 是独立页面；用户选择文件夹或直接创建空白起点。文件夹可含代码、原型或设计材料。原材料路径与正式开发路径分别管理，不隐式搬移或上传材料。

ArcOrbit 为每个 Idea 准备应用私有的 Agent 工作环境；无用户文件夹也能保存和协作。选择材料只授予显式材料范围的访问，不授予任意设备文件访问。工作环境准备失败保留 Idea 并显示恢复入口。

页面同时展示可编辑产品内容和基于现有 Conversation Surface 的对话/输入框。对话输入、输出、工具活动、权限与停止行为完整可见。场景会话独立于普通 Chat 与 Automation 的线程/控制；自由 Chat 原有能力保持不变。

Agent 能读取已授权材料、整理内容、提出状态与项目归属/仓库/目录方案。确定性业务工具负责实际动作。用户能直接修改字段、采纳建议、确认接入、停止、返回和继续；已开始的手动编辑不被迟到建议覆盖。

接入前展示当前项目归属、项目名称、已有/新建 GitHub 仓库主体与名称、成员关系及目录选择。ArcOrbit 组织权限和 GitHub 主体权限分别校验。邀请不等于立即建立成员关系；所有外部变更都反馈实际结果。

正式录入完成必须同时具备可访问共享项目、GitHub 仓库、对应本地 Git 工作目录和成功写入的正式 Idea 记录。可沿用已有仓库或经已认证 GitHub 能力创建仓库；空白起点由 ArcOrbit 在确认后准备正式目录。仓库或目录未就绪时仍属于“录入未完成”，即使远端项目创建已成功。

正式资料落盘并能重新读取后才移除临时事实；中断恢复不会丢失或重复创建 Idea。完成录入与已共享分开显示，Git 推送尚未成功时标记“已录入 · 待共享”。

## 保存与同步

本机草稿、写入本地仓库、提交与共享同步是不同结果。用户看见本次差异和作用范围；只处理本次产品资料，不夹带工作区中的代码改动。同步遵守已有 Git 身份和分支权限，不收集或写入仓库凭据。

采用明确的仓库资料分支作为共享来源。远端更新先读取并比较，本机有冲突时保留双方并要求选择或通过 Agent 辅助解决；不得静默覆盖。失败保留草稿与已有提交，重试复用结果。未合并到共享来源的变更仍标记待共享。

其他成员更新仓库后读取同一管理记录。Git 同步只保证已共享资料，不同步 ArcOrbit 本机对话、目录绑定、执行现场或临时草稿。

## Today

Today 继续保留人工责任与项目配置两个工作台模式，保留跨项目责任强制显现、原位操作和恢复语义。

Today 增加添加 Idea 入口，以及与责任列表分开的反馈新消息和本机 Idea 续接区。通知不是任务责任；新消息来自当前用户可访问的 Feedback 通知，成功读取消息后才清除未读。续接区仅列出本机未完成 Idea 接入与产品编辑草稿，不显示普通待办或完成历史。

业务处理仍回到原 Work/Feedback/Chat/Automation 对象，来源确认后重新聚合；没有单独 Today 完成字段。来源不可用保留最近记录并标记未知，不声称全部完成；本机草稿仍可编辑。

## 验收口径

- 未配置产品状态的共享项目不显示推断的推进状态；显式状态更新不会改变任务或执行控制。
- 空白和文件夹 Idea 均能本机暂存与重启恢复；正式完成必须有 GitHub 仓库、本地工作目录及 `arckit/product/` 记录。删除设备临时库后仍能从产品集关联目录恢复正式 Idea；会话和执行现场保持本机。
- 用户与 Agent 共用产品资产协议和写入边界；过期 revision、越界路径、不支持协议和错误内容不能损坏原资料。
- 创建/关联已有项目和仓库、部分成功恢复明确区分；无幂等能力的响应未知不得重复创建。
- 仓库同步可在两个独立 checkout 中验证；冲突、权限失败和未共享状态可见，其他文件不被提交。
- Product 与 Today 结果从原来源回流，原 Lifecycle、普通 Chat、Automation 和 Setup 行为保持有效。
- 本能力 UI 不包含产品迭代、版本记录或发布操作。

## Idea 接入主线

选择文件夹即创建本机草稿并发起一次可见的 Agent 整理请求；界面提前说明将读取材料。打开旧记录不重新发起。空白起点先要求一句想法，再由 Agent 整理；用户也可直接填写接入方案。

主界面优先展示当前阶段、已识别内容、可编辑接入方案和唯一主要动作；理念、原则与资产引用折叠为可选完善。阶段包括待描述、正在理解、待补充、待确认、正在接入、失败/中断和已录入。阶段来自当前会话、方案校验和实际回执，不从 Agent 自称完成推导。

Agent 可以读取可访问项目/组织候选、已关联成员、材料清单、材料目录 Git 状态及 GitHub 账号/组织候选。GitHub 查询失败是局部未知，不阻断文本整理。已有仓库关系由真实检测提供，Agent 提出关联建议，不自行决定组织归属。PNG/JPEG/WebP 以图片输入供模型理解；无法理解的设计源文件显示限制并可请用户提供导出图或说明，不声称已阅读。

Agent 的资料与方案建议进入可编辑业务字段，并标注依据；人可以改后保存整体结果，无需阅读 JSON、先整体采纳再重写或分别保存多份方案。正在编辑时新建议保留为候选并显示明确合并动作，不静默覆盖。发送对话前保存当前编辑，使 Agent 读取到同一事实；只有有效建议修订可以被保存，过期时提供保留手工改动并重新整理的恢复操作。

缺少必需信息时按字段显示原因，并让人直接选择或继续对话。确认区展示项目、组织、仓库和正式目录的业务摘要；确认后优先交给 Agent 执行同一精确方案。Agent 不可用时保留清晰的直接执行入口。外部变更仍需要一次明确确认；失败只继续未完成部分，未知创建结果必须核对。

验收从首次用户路径开始：选择真实材料后无需输入技术指令即可看到整理活动；模拟 Agent 必须根据提供的材料/候选实际产生方案；人可改建议、回答缺失选择、确认并看到正式结果。另覆盖空白、Agent 不可用、图片材料、晚到建议、重开不重发和部分失败。真实模型/窗口的验证情况与代码测试分开陈述。

## Agent 与应用的职责边界

Agent 负责理解材料、环境探索、故障诊断、比较候选、提出接入计划，并在取得具体确认后推进执行。ArcOrbit 提供真实项目事实、受授权能力、可编辑结果、确认校验、持久记录与执行回执。快捷检测失败不终止 Agent 的探索能力，也不代替 Agent 推断根因；应用不把环境诊断编码成固定语义流程。

Idea 场景允许 Agent 使用 Codex 原生命令做只读环境探索；材料工具仍是材料正文与图片的首选读取入口。探索范围是所选材料、相关 Git 元数据与工具安装信息，不读取无关项目或凭据正文。原生命令的执行环境及沙箱与业务工具分开标识；命令成功只证明该次实际执行，不自动证明业务工具可用或取得远端写权限。

原生探索默认只读、无网络；超出沙箱的请求沿用可见 Chat 审批。应用不得以提示词声明冒充操作系统级读取隔离。创建项目/仓库、搬移目录、正式保存与共享仍服从业务入口的精确确认及回执，不因打开原生命令而得到默示授权。

环境检查提供检测时间、执行来源、命令、实际程序路径、检查目录、退出码或启动错误码、超时及脱敏摘要。未知保持未知：程序未找到、执行失败、认证被拒绝与组织清单失败分别呈现，只有认证证据支持时才引导登录。部分失败保留其他已验证事实，Git 根查询、路径核对与 origin 查询分别可追溯。

业务检测与正式执行共用工具发现及环境配置；应用补齐已知安装目录属于确定性能力准备，探索策略与下一步选择仍由 Agent 决定。失败结果不是永久状态，显式重新检查返回新结果；Agent 对缓存先看检测时间，需要时重新验证。旧会话继续使用原生能力与原有动态工具，不为升级工具声明丢弃对话或另建隐藏线程。

验收覆盖缺失 PATH、绝对路径可执行、启动错误与非零退出、超时、Git 部分成功、认证与组织部分失败、敏感输出脱敏，以及同一会话中的失败后继续探索。检测与正式执行的环境一致性、原生只读沙箱传递及既有确认/存储回归分别有证据；工具契约测试不冒充真实模型探索质量或实际账号权限验收。

## 正式目录与共同语义

正式工作目录由用户决定：沿用材料目录，或选择另一文件夹作为关联 GitHub 的本地仓库。应用私有 Agent 工作区仅承载会话，不能作为正式源码的默认目标。另一位置可以是已有对应仓库或空目录；空目录准备仓库后复制材料，保留来源，不覆盖不同内容，不携带原 .git、依赖缓存或凭据。冲突明确指出路径并保留未完成状态。复制、Git 提交和推送分别反馈，正式接入不会自动提交或上传源码。历史未完成 managed 方案撤销旧确认并要求用户重新选择；已正式绑定的项目不自动搬迁。

界面与 Agent 共用字段语义：正式目录的选项、当前选择、实际路径、材料处理及可执行动作；Workshop 组织与 GitHub 主体分别说明。Agent 用当前上下文回答“这里/这个选项是否合适”，不从私有 cwd 猜测源码目标。人保存和发消息前同步编辑，Agent 提案须采纳，外部执行须匹配最新确认。共享管理记录不代表代码或资产正文已上传。
