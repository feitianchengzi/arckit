# ArcOrbit 项目事情台

## 范围与归属

项目事情台是登录与必要环境准备后的主体工作入口，围绕项目与事情组织工作。旧业务页面保留独立实现，由主导航“更多页面”打开二级菜单访问。新页面不复制原型样本、定时推进或假成果；读写真实业务服务。

事情、负责人、协作会话与执行方式相互独立。首条新对话创建当前用户负责的待评审事情，并关联持续协作会话；创建与发送失败可重试且不重复创建。开始 Auto、暂停、继续和恢复保持事情身份与已有会话关联。普通讨论不自动领取任务。

## 应用壳与过渡

主导航呈现全部事情、需要我关注、真实项目列表和一个旧页面总入口。旧入口完整覆盖 Today、Chat、Product、Idea、Work、Automation、Release、Operations、Feedback、Organization、Engineering。选择旧入口打开原业务页面；用户可随时回到事情台。登录、账号设置、Setup、反馈中心和本机连接能力保持可达，旧页面业务实现保持不变。

## 事情浏览

左侧项目、中间详情、右侧事情列表组成稳定工作空间。列表标题和状态/更多筛选共用第一行，搜索位于第二行；行高紧凑，标题和状态单行显示，长标题省略并可读完整文本。项目、状态、搜索、执行人、优先级可组合筛选。列表底部固定唯一的“发起事情”。

右上角运行状态显示所有项目本设备的执行、排队和需要处理数量。点击打开非模态概览，优先显示待决定、暂停、外部等待及恢复问题；点选后清除阻碍定位的筛选并进入对应项目与事情。空闲状态可进入执行设置。关闭、外部点击与 Esc 只关闭此面板，后台刷新不抢选中事情。

## 详情与交流

标题区域紧凑呈现编号、项目、负责人、优先级、状态及有限主动作。属性面板查看完整字段并进入编辑。目标正文保留 Markdown；显示标题由内容派生。状态采用服务端七状态，执行模式另外呈现。

四个内容入口为概览、资料与协作、成果与验收、活动。消息默认隐藏，中间底部输入属于当前事情。查看消息、先分析、暂停并讨论和首条新对话主动打开中间消息层；右侧列表仍可操作。关闭/Esc 恢复原内容入口及阅读位置；切换事情收起消息，草稿按事情保留。

概览显示目标、当前工作、已有进展、剩余问题、下一步、完成标准、已采纳约定、阶段成果与子事情。Agent 判断标明来源，不替代服务器状态。计划仅在有真实数据时出现，允许修改或清空，不预设三步，不以计划数量推断完成。

资料与协作区分参考资料、共同约定和参与者留言。資料可添加文本、链接或附件，具有来源与上下文引用状态。消息/评论可保存为待确认约定，明确采纳后同步概览；从来源可以定位消息。评论交给 Agent 时先进入输入框，由用户发送。资料已加入不等于模型已读取。

成果在分析和执行中即可出现。成果清单引用可打开的具体内容，保留来源和版本；检查证据标明范围与结果。完成标准与概览共用，完成后逐项确认；目标变化使相关确认过时。尚有未解决验收问题或未确认标准时不能验收。验收问题独立于源事情状态，完成状态保持且沿用协作关联。已验收只读检查结论，不提供新增问题入口。

活动显示有来源的目标/属性变更、约定、执行控制、成果、检查与验收事件。事件带操作者、时间及关联来源，可按类别筛选并进入相关消息。没有可靠历史时不伪造完整时间线。消息、团队评论与运行事件保留各自可见性和语义。

## 执行与恢复

直接 Auto 与先分析再 Auto 共用事情身份；执行资格由当前业务规则决定，不因打开页面自动授权。补充要求显示已接收/待生效/已采用，运行中追加不自动暂停。暂停请求与已经暂停区分，暂停后讨论不自动继续。排队、停止、恢复、外部条件与需要决定均有对应动作与错误反馈。

UI 与 Agent 的业务操作遵循同一权限、对象、状态、版本和幂等约束。Agent 可维护授权范围内的结构化工作判断，通过业务能力修改事实；文本声明不能直接伪造事实变更。项目事实、任务源、运行控制、会话与文件分别保持其权威来源。

## 连续性与降级

草稿、详情入口、列表和消息阅读位置按事情或范围保存。输入法组合期间不破坏输入，后台刷新不替换未提交内容或跳转页面。网络、连接、权限、冲突和缺失绑定错误明确说明恢复动作并保留输入。旧会话不能静默拼接成另一个底层 thread。

760px 及以下列表通过入口展开，底部仍可发起；390px 无横向溢出。消息弹层局限于中间工作区；运行状态面板适配窗口。所有按钮可键盘访问、具有可读标签和可见焦点。语音入口在未实现时禁用且不访问麦克风。
