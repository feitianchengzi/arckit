# Release 本地交付工作台

## 目标与范围

Release 为当前可访问项目的已有本地工作区提供真实终端、Git、源码编辑、构建运行和 Agent 协作。顶部产品集/查看/管理继续使用已有能力；页面不创建另一套项目或目录绑定。云端 Project 身份与本机目录、Git 根目录、执行会话分别表达。

## 多项目与连续性

全部范围汇总已有项目与本机活动；操作必须有明确项目。单项目进入其工具台。任务、终端和对话固定启动时的工作区；切换页面或产品集不停止、迁移或重新绑定执行。相同仓库下不同项目共享真实 Git 状态。解除或改变绑定后旧执行仍显示原身份，不迁移到新目录；旧会话不能据新绑定获得访问权。

## 终端

用户可创建多个真实 Shell 终端、切换、分屏、调整大小、搜索、复制、粘贴、关闭和中断；终端支持交互 CLI。启动使用已有本机 Shell 环境。自由 Shell 可以改变 cwd，项目归属不构成系统沙箱。终端输出不作为 Agent 指令或成功凭证。页面重载重连仍活跃的会话；应用关闭结束受管理进程并保留有界日志和中断状态，不承诺退出后存活。

## 构建与运行

页面列出项目已有 package scripts，用户可以直接执行或输入命令。每次执行固定目录、命令、来源版本，返回独立任务记录，展示运行/成功/失败/中断、日志、退出码、重试和停止。允许不同项目并行。停止 Agent 回答不隐式停止构建。构建失败可把同一任务的命令、退出码和日志引用送入当前项目 Agent 对话。产物只来自实际磁盘，打开/定位使用明确选中路径；不虚构已安装或上线。

## Git 与源码

真实 Git 状态区分工作区/index/HEAD；支持文件及补丁暂存、撤销暂存、提交/amend、分支/tag/stash、fetch/pull/push、合并/rebase/cherry-pick 及 continue/abort、文件历史与差异。高级交互式 rebase、bisect、提交图和 worktree 操作通过内嵌 Lazygit 提供。不可用时说明缺失工具并保留真实终端入口。

源码文件支持浏览、搜索、编辑、保存与 Diff。保存和补丁操作绑定读取基线；文件或 index 变化时拒绝旧修改并保留草稿。冲突展示双方与结果，保存、暂存和继续整合是独立动作。二进制或过大文件显示类型/限制和路径，不按文本破坏文件。

仓库操作尊重现有 Git 配置、hooks、签名、凭据与 SSH。危险变更展示精确对象和影响，用户确认绑定操作参数及 Git 基线；状态变化后重新确认。应用内协调不能阻止外部 Shell 或 IDE 写入，因此执行前后重新读取。

## Agent 与能力复用

消息区、输入区、流式状态、工具、审批和停止复用 Chat 的同一实现。Release 建立独立场景会话，复用 Idea 的上下文注入与动态工具；不占用 Automation task thread/lease，不自动创建 Case。Agent 负责理解和推理，代码负责文件/Git/任务的确定性执行与回执。UI 与工具使用同一底层服务。外部插件适配复用相同服务，不复制终端所有权。

## 发布与运维

Release 保留正式发布入口和能力边界。现有项目发布脚本可作为明确命令执行；Git 推送不自动表示渠道发布，构建成功不自动表示部署成功。没有渠道/监控 adapter 时显示尚未接入及可操作终端，不展示模拟健康或回滚成功。未来固定源版本、CI、渠道和部署 adapter 继续复用执行记录与真实回执。

## 验收

真实 PTY 验证交互输入与 resize；真实隔离仓库验证部分暂存、提交、冲突恢复、过期写入拒绝及同仓库多项目；两个项目并行任务、切换后异步归属、进程停止与重启恢复；共享对话组件和动态工具契约；安装包验证依赖、worker、原生模块及离线加载。外部真实发布不作为自动测试副作用。
