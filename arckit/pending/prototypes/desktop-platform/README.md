# Workshop Desktop 交互原型

这是 AI 原生软件产品研发平台的候选桌面端交互原型。

原型采用“桌面优先、云端协同”的产品形态：团队成员从一个桌面客户端进入产品策划、工作协作、自动化运行、本地开发、版本交付、用户反馈和能力管理。

当前名称 `Workshop`、示例团队 `Feitian Studio` 和示例产品“拾光”均为原型占位，不代表正式品牌或产品命名。

## 打开方式

直接使用浏览器打开：

`arckit/pending/prototypes/desktop-platform/index.html`

原型不依赖网络、第三方框架或后端服务。

## 建议体验路径

### 路径一：从登录到今日工作

1. 在登录页点击“进入 Feitian Studio”。
2. 查看“拾光”的产品生命线。
3. 查看需要人工判断的事项和正在运行的自动化。
4. 点击侧边栏或使用数字键 `1-8` 切换主要产品区域。

### 路径二：产品决策进入自动化

1. 进入“工作”。
2. 选择“首页洞察的第一版范围”。
3. 阅读 AI 决策摘要和两个候选方案。
4. 点击“确认并开始执行”。
5. 原型会进入“自动化”，展示 Case、Loop、Run、执行边界和证据。

### 路径三：本地人机协作开发

1. 进入“开发工作台”。
2. 查看当前 Product、Work、Case、事实文档和 SkillSet。
3. 点击“继续执行”。
4. 原型会模拟 Codex 执行验证并生成结构化结果。

### 路径四：人工授权与发布

1. 在“今日”、通知抽屉或“自动化”中打开 App Store Connect 授权请求。
2. 查看本次操作、目标团队和授权有效期。
3. 点击“允许本次操作”。
4. 进入“交付”，查看 Build 18、发布检查、AI 风险审查和 TestFlight 准备。

### 路径五：反馈进入研发

1. 进入“反馈”。
2. 选择不同反馈组，查看影响范围和 AI 问题判断。
3. 在高影响反馈中点击“确认并转为工作项”。
4. 再次点击按钮可以进入 Work Hub。

### 路径六：复用产品能力

1. 进入“能力”。
2. 查看拾光已启用和推荐的 Capability。
3. 点击“崩溃诊断”的“启用”。
4. 原型会模拟检查配置、加入能力并创建接入工作。

## 已实现的交互

- 邮箱登录、GitHub 登录和退出登录。
- 主导航、数字键快捷导航和侧边栏折叠。
- `⌘K` / `Ctrl+K` 命令面板。
- 通知抽屉、用户菜单和工作区切换。
- 产品创意、工作项和 Build 创建弹窗。
- 工作项选择、候选方案选择与产品决策确认。
- 自动化运行状态与人工 Gate。
- Developer Workbench 中的 Codex 执行模拟。
- Release checklist 状态切换。
- Feedback 选择、AI 分析和转 WorkItem。
- Capability 启用状态。
- 全局 Toast 反馈和 `Esc` 关闭临时界面。

## 原型范围

本原型用于判断：

- 单一桌面客户端能否承载完整研发闭环。
- 产品生命线是否比传统项目导航更适合作为整体体验主轴。
- Work Hub、Automation Runtime 和 Developer Workbench 的分工是否容易理解。
- AI 能力是否自然嵌入产品流程。
- 人工判断、权限 Gate 和 Handoff 是否足够醒目且可处理。
- Product、Work、Run、Release 和 Feedback 之间的关联是否能够形成连续感。

本原型不用于确认：

- 正式品牌和视觉规范。
- 正式字段、状态机和权限模型。
- Web 端与桌面端的最终功能分配。
- 最终仓库、服务或部署架构。
- 真实 Codex、GitHub、TestFlight 和 Feedback API 接入方式。

## 文件

- `index.html`：页面结构、示例数据和所有产品视图。
- `styles.css`：桌面壳、组件、状态和响应式视觉。
- `app.js`：登录、导航、弹窗、模拟执行和状态交互。
