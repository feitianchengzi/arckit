# ArcOrbit Today 与就地引导 — 交互形态概念对比

这是一次候选交互形态探索，不是正式 `arckit/interaction/` 事实。原型使用同一业务状态比较三种跨模块引导方式，供选择后再提升为正式页面交互策略与线框。

## 统一演示状态

- 用户已登录；
- 已有一个可访问的远端项目 `ArcOrbit`，并已进入默认产品集；
- 项目尚未绑定本地目录；
- 项目尚未允许自动领取；
- 当前用户有一条处于待评审的待办；
- 全局自动领取关闭。

## 三种候选

### A · 下一步聚焦型

Today 始终突出一个当前最值得完成的动作，完整准备关系收进低强调进度条。功能页面使用紧邻当前对象的行动条解释影响并提供单一修复动作。

- 优势：认知负担最低，首次成功路径最短。
- 风险：用户不展开进度时，对完整依赖关系的理解较弱。

### B · 准备路径型

Today 展示完整准备步骤与当前进度，功能页面保留一个可见的准备侧栏，使用户持续理解自己位于哪一步。

- 优势：依赖关系最透明，中途离开后容易恢复。
- 风险：容易产生安装向导感，成熟用户可能觉得过重。

### C · 产品就绪型

Today 以 Product Workspace 为单位展示就绪度与阻断，功能页面主要使用状态标记和按需展开的动作菜单。

- 优势：最适合多产品长期运营，扩展到多个项目自然。
- 风险：首次用户需要先理解“产品就绪度”，主路径不如 A 直接。

## 原型操作

- 顶部切换 A / B / C，比较同一状态的三种表达；
- 点击主动作或模块内快捷入口，依次模拟绑定目录、允许项目、确认待办和开启自动领取；
- 切换 Organization / Work / Automation / Chat，比较模块内的就地引导；
- 点击“恢复初始状态”重新开始。
