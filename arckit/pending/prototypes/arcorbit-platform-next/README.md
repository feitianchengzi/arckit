# ArcOrbit Platform Next — 可交互概念原型

这是一次候选产品概念探索，不是正式交互事实。原型把 ArcOrbit 作为“开发其他软件产品的桌面平台”继续演进，并只激活当前最值得贯通的四个工作面：项目、待办、执行、反馈。

## 这版的判断

- **一个桌面入口，不是三个网站拼盘**：用户登录一次 Workshop 会话，在同一工作集中处理多个产品的待办、自动执行与反馈。
- **工作集不是产品切换器**：用户勾选需要同时关注的一个或多个产品，Today、Work、Automation、Feedback 都在该范围内聚合；改变工作集只改变显示范围，不退出产品或改写服务端数据。
- **为多产品推进减少人的上下文切换**：平台按产品保留事实和责任边界，同时提供跨产品优先级、需要人工判断的集中入口、统一执行队列和来源标识。
- **本地项目是工作锚点**：进入产品后首先落到本地仓库、分支、Project State 与 Case；远端 Workshop 项目作为协作映射和同步源存在。
- **产品贯穿全链路**：虚拟产品「折光」只是演示数据。所有 Work、Case、Run、Feedback 都归属于同一个 Product Workspace。
- **AI 是产品内能力，不是聊天首页**：Automation 页面保留 ArcOrbit 真实的持续线程、Agent Loop、证据和人工介入；反馈页不虚构当前不存在的 AI 聚类和自动决策。
- **平台框架先保留，能力分阶段开放**：Product / Work / Automation / Feedback 为当前闭环；Delivery / Capability 清晰标注为后续接入，不伪装成已完成。

## 建议体验路径

1. 配置当前工作集，可同时选择「折光」「白昼」「北辰」，也可以只显示一个产品。
2. 从 Today 看跨产品优先级、运行状态、反馈信号以及只需要人处理的判断。
3. 在 Products 管理 Workshop 产品项目、本地仓库绑定和产品成员；在 Team 管理组织成员、角色、邀请与产品参与关系。
4. 在 Work 创建/整理跨产品协作待办，选择“进入自动队列”。
5. 在 Automation 观察统一队列和当前持续线程，在需要时人工介入。
6. 在 Feedback 处理跨产品原始反馈并流转为待办；在 Automation 处理完成任务产生的验收反馈。
7. 证据收束后回写对应产品的任务状态，闭环继续，而不是跳回待办或反馈网页。

## 运行

直接打开 `index.html`，或在本目录启动任意静态文件服务器。

原型内可操作：多产品工作集选择、跨产品聚合视图、产品创建、本地项目绑定入口、组织/产品成员管理、邀请生成、新建待办、待办详情、交给 ArcOrbit、执行暂停/继续、人工介入、反馈受理/忽略/流转待办、全局搜索、未来模块说明以及重置演示。
