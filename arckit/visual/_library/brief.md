# ArcOrbit Desktop 视觉策略

## 定位与依据

ArcOrbit 是围绕项目和事情持续协作的 Agent 工作空间。Project State 通过 Case 和 Loop 推进；界面帮助用户定位事情、表达目标、检查成果、处理例外和改变方向。技术执行细节按需展开，不能成为默认导航或装饰性仪表盘。

视觉依据是用户指定的 Codex Desktop 等 Agent 产品参考方向、`arckit/interaction/project-workbench/interaction.md` 的浅色项目导航与场景详情结构，以及已有视觉系统的克制气质、系统字体和语义状态；橙色操作强调依据用户明确选择。外部参考及适用边界见 `reference-research.md`；具体尺寸与颜色是 ArcOrbit 的规范投影，不是对竞品私有设计系统的声称。

## 品牌气质

可靠、安静、精确、可持续阅读。中性表面按明暗主题形成工作空间，小面积浅杏橙（#F4B77D）承担操作重点。主按钮使用浅杏橙背景与深色文字，取消装饰性深橙描边。普通链接、次要操作和选中项文字使用中性色，选择通过淡橙背景与指示线表达。执行状态标记与焦点在亮色中使用较深橙色、暗色中使用浅杏橙保持可读性。正文、目标、结果和需要用户处理的问题拥有首要视觉权重。界面不使用品牌渐变、大面积彩色背景、玻璃模糊、装饰性 KPI 或每条消息一张重阴影卡片。

## 信息层级

项目导航负责稳定定位；事情列表负责扫描和选择；中央场景呈现目标、进展、成果与验收。消息按交互定义在中央区域打开，不将整个产品变成强制聊天入口。生命周期影响内容和动作，不改变事情身份。

事情台内容区使用一条 54px 顶栏，左侧呈现当前范围，右侧呈现运行状态。主窗口没有独立标题栏或通栏占位；独立窗口控件仅占用顶角局部空间，与内容顶栏职责分离，不能再叠加旧 Command Bar。亮色中项目侧栏使用浅灰、主体使用白色；暗色中侧栏使用深中性色、主体与浮层逐级提亮。列表与辅助资料使用次级表面。边界由分隔线和空间建立，常规区域没有投影。

内容阅读顺序为“当前事情 → 当前状态/需要决定的问题 → 目标或结果 → 证据与细节 → 相关活动”。一个局部决策区只有一个实心主动作。事情标题采用 20px 层级，区块标题 16px，不用欢迎页式巨型标题挤压可用空间。28px 展示标题仅用于独立起始或认证场景。

选中对象使用淡橙背景和指示线；焦点环独立于选中状态。项目计数不伪装成未读数，未读也不伪装成错误。长标题保持单行并以省略号截断；识别标题上限为 64 个 Unicode grapheme clusters。详情正文保留完整内容和换行。

## 色彩角色

| 角色 | 规则 |
|---|---|
| 中性 | 文字、导航、表面、分隔、空闲与待评审；浅色边界不承担唯一控件识别 |
| 橙色 | 主操作、当前选择、键盘焦点和执行中；不表示验收通过 |
| 绿色 | 健康、执行完成；完成不等于验收 |
| 青色 | 已验收、稳定外部确认 |
| 琥珀色 | 需要用户处理、待处理、阻塞；背景保持低饱和度 |
| 红色 | 错误与破坏性操作；已取消沿用既有红色标签，但不显示错误横幅 |
| 蓝色 | 同步、信息、可定位证据；链接同时有下划线或明确操作形态 |

操作橙使用实心按钮或选中指示线，人工注意的琥珀色使用警示图标、说明与浅底提示；二者不只靠色相区分。颜色不独立表达含义。服务器七状态使用固定中文标签，执行与连接状态使用独立描述，不能把等待、暂停、断连映射成新的业务状态。Token 的 `semantic.*` 定义应用角色，`colors.*` 是基础值。

## 字体、密度与图标

使用平台系统无衬线字体，中文使用系统中文回退，不依赖远程字体下载。正文 14/22px，对话 15/24px，标签和按钮 13/18px，元数据 12/18px。11/16px 仅用于短计数或非关键标识。命令、路径、版本和标识符用系统等宽字体；长路径允许换行或局部滚动，不撑宽页面。

8px 是主要间距节奏，4px 处理紧凑细节，12/16px 用于控件与列表，24/32px 用于区块。常规控件至少 36px，数据行至少 40px，标准行 44px；独立图标按钮至少 32px。事情台两行筛选区中的搜索框采用交互指定的 31px 紧凑例外，输入文字仍为 14px；例外不扩散到表单或其他按钮。

按钮、导航使用 6px 圆角，独立对象及浮层 10px，Composer 与认证面板 16px。状态标签可使用胶囊圆角，常规按钮不胶囊化。图标沿用统一轮廓矢量体系，16/18px 画布、1.5px 笔画、圆端点；装饰图标隐藏于辅助技术，独立操作有名称和提示。Logo 延续已有资产，视觉规范不创建新品牌标志。

## 对话、输入与成果

Agent 正文是连续阅读面，最大内容宽度 760px。用户消息使用轻量浅橙表面，不占满整个行宽。Reasoning 使用可折叠次级文本，结束后默认收起；工具活动使用紧凑单行“动作、目标、结果”，空 reasoning 与原始 JSON 不占据正文。权限请求显示具体对象、影响与既有授权动作，不由视觉规范增设审批。

Composer 保持可辨识边界、舒适输入区与固定操作区；上下文附件使用可移除的小标签。模型和执行环境属于次级控制，不与发送动作争夺注意力。输入和失败重试保持草稿。生成中保留停止入口，正在阅读历史时不强制滚动到最新消息。

成果以名称、类型、来源和验证状态构成可检查对象；代码差异用等宽正文及明确的增删标记，增删色不能代替符号。Agent 声称完成、证据检查通过和用户已验收是不同层级，不能统一呈现为绿色成功卡。完整运行时间、Gap 记录和结构化输出位于活动/执行详情，名称来源于真实事实，不预设内部角色与步骤。

## 反馈与动效

状态规则集中在 `state-contract.md`。文字对比度至少 4.5:1，必要图形、边界和焦点至少 3:1。焦点采用不透明橙色 2px 轮廓与 2px 间隔，在深色兼容导航中也保持可见；不使用低透明度轮廓削弱对比度。

hover 轻微改变背景或边界，pressed 使用更深的角色色；列表和文字输入不缩放。一般控件反馈 120ms，面板与内容过渡 160ms，复杂浮层至多 240ms。减少动效时取消非必要位移、缩放和循环动画，运行状态仍以静态文字可见。

## 窗口与主题

`themes/light.yaml` 与 `themes/dark.yaml` 分别定义完整亮色、暗色主题；`themes/legacy-mixed.yaml` 仅保留旧控制台兼容样张，不作为用户外观选项。暗色支持依据用户对 ArcOrbit 暗黑模式的要求，沿用已接受的浅杏橙、层级、密度和状态语义，不引入新品牌方向或反转图片。暗色主面为 #161B22、侧栏为 #121722、浮层为 #222A35，正文为 #E6EDF3；配色完整值由 dark.yaml 维护。主按钮保留 #F4B77D 与深色文字，焦点和状态文字按背景明度适配。

主题覆盖主窗口全部业务页、登录/安装引导、设置、菜单、对话框和空/错/加载状态；终端保持独立的深色阅读面，图片保持原色，外部网页与第三方反馈内容遵循其自身主题契约。主题不改变布局、字号、密度或交互。主题切换与本机偏好规则见 interaction/CONVENTIONS.md；生产接入不由规范或原型完成状态证明。

macOS 保留系统原生 traffic lights、系统布局面板和全屏语义，不绘制第二组。Windows/Linux 保留右侧 46×40px 最小化、最大化/还原、关闭按钮。控件独立放置在顶角，macOS 位于导航顶部左侧，Windows/Linux 位于右侧，保留局部避让空间。控件不参与拖动，导航及页面顶部非交互空白区可以拖动；主题不改变窗口控制行为。主导航底部用户设置入口以至少 12px 次级文字呈现同步状态和时间戳，状态不只靠颜色表达；窄窗仍保持窗口控制与设置状态可达。

宽窗口保持稳定项目导航和列表，内容区使用弹性剩余宽度。760px 以下事情列表按交互进入抽屉；390px、200% 缩放与较长中文文本仍能阅读和操作。多栏收敛、消息层范围和焦点返回遵从交互事实；视觉规范不自行调整页面结构或隐藏动作。
