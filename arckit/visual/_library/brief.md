# ArcOrbit Desktop 视觉策略

## 来源依据

用户要求 ArcOrbit Desktop 达到专业桌面平台的表达质量，并明确指定 `arckit/pending/prototypes/desktop-platform` 作为灵感来源。确认的 Automation Command Center、Task Browser、Intervention Workbench 和 Recovery Center 共同限定视觉系统必须支持高密度运行态势、项目与状态导航、按需人工处理和异常恢复。

## 品牌气质

界面呈现可靠、克制、精确的专业桌面平台气质。视觉重点是任务清晰度、可观察性、执行边界和状态可信度，不使用娱乐化插画、夸张渐变、大面积品牌色或装饰性仪表盘制造情绪。

## 信息层级

深色侧栏承载稳定控制结构，亮色工作区承载当前任务和证据。Command Bar 是全局操作层；页面标题、上下文、主要动作和当前状态建立首屏顺序；人工事项位于当前运行与队列之前；表格和 Inspector 承载细节。指标只在多个可比较数值直接影响当前判断时出现，不作为所有页面的默认模板。

活动对象通过左侧细描边、浅色底和语义标签共同突出。层级主要依靠背景面、分隔线、字体权重和空间组织，阴影不承担常规卡片分层。常规信息共享页面表面；只有可独立操作、选择、折叠或需要语义强调的对象使用卡片边界。

Chat 与 Intervention Workbench 共用一个 Conversation Surface。消息层级以 Agent 正式正文为视觉主角，使用舒适行高和有限内容宽度；非空 reasoning 使用可折叠的次级文本面，完成后默认收起；工具与权限活动使用最轻的一行列表样式。Automation 专属的 state-driven loop 状态、schema-bound 输出、完整执行时间和逐 gap 全貌位于左右面板，不在 Conversation Surface 中形成平行视觉分支。空 reasoning 和原始 JSON 不在主消息面产生空占位或大块高对比内容。

独立 Login 与会话恢复状态属于亮色工作区，不延展深色侧栏或标题栏。认证画布使用中性浅灰承载低对比紫色光晕，白色账号面板保持输入焦点；深色墨色只用于文字和小面积标识，不形成全页背景。

## 色彩角色

中性墨色构成导航、文字、背景和边界。紫色是唯一操作强调色，用于当前导航、主按钮、焦点和活动 Runtime。绿色表达健康与完成，琥珀色表达待处理与人工注意，红色表达错误、取消和破坏操作，蓝色表达信息与同步，青色表达已验收或稳定外部确认。

七种任务状态必须同时使用明确中文文本、英文状态键的可访问说明和语义色。待评审使用中性灰，待处理使用琥珀，进行中使用紫色，已完成使用绿色，已验收使用青色，已取消使用红色，已阻塞使用深琥珀或红琥珀。

## 字体节奏

界面使用系统无衬线字体，并优先匹配 macOS 系统字体。标题采用紧凑字距与较高字重；正文、表格和表单内容使用 14px/22px，人工对话使用 15px/24px；导航、按钮、字段标签和状态文本使用 13px/18px；辅助状态与元数据使用 12px/18px。11px/16px 微型层级只承载短计数和非关键标识，不承载句子、操作、错误或恢复说明；生产界面不使用小于 11px 的可见文字。标识符、时间和命令使用等宽字体，但仍遵守对应信息层级的最小字号。

## 空间密度

应用壳面向最小 1100×720 的桌面窗口。侧栏宽度稳定，Command Bar 紧凑，主页面以 8px 基础网格组织。常规按钮和输入框不低于 36px，可操作数据行不低于 40px，标准列表行使用 44px；仅图标工具可使用 32px 紧凑尺寸。页面区块使用 16–24px 间距；人工对话区域允许更宽松的 20–28px 节奏。Workbench 三栏与底部 Composer 保持稳定边界，中间消息列表占用剩余高度并独立滚动；工具活动行保持 32px 的紧凑高度。

## 组件性格

常规容器使用细边框、小圆角和纯色表面。主按钮使用实心紫色，次按钮使用白底细边框，文字按钮用于低风险导航。状态标签紧凑、可扫描，不使用大面积饱和底色。操作图标来自统一的轮廓矢量图标体系，采用一致的 16px 或 18px 画布、笔画和光学对齐；字符、Emoji 和临时符号不作为生产操作图标。

任务表是主数据组件，行选择不改变队列语义。当前运行使用阶段条、状态点和有限事件摘要表达进度。人工事项使用浅琥珀背景和明确主动作；恢复事项使用浅红或浅琥珀背景，并展示事实差异和责任方。

待办在列表、队列、当前运行、人工事项和 Workbench 顶部等识别区域使用同一个单行展示标题。标题最多承载 64 个 Unicode grapheme clusters，超限时以 `…` 结束，容器保持单行和稳定高度；完整正文只在详情或任务上下文正文区展示一次并保留换行，不与同源标题上下重复形成双重内容层级。

ConversationSurface 使用五类共享层级：ReasoningDisclosure 是默认收起的次级过程文本，AgentMessage 是无多余装饰的主要阅读内容，ToolActivity 与 ApprovalActivity 是单行图标、动词、目标、状态和有界动作，UserMessage 使用轻量区分的输入表面。Composer 以顶部分隔线固定在消息列底部，不通过重阴影覆盖内容。AutomationExecutionOverview 在侧栏内使用紧凑指标与纵向 gap 列表承载完整时间、轮数、目标、工作摘要和结果，不与对话正文争夺层级。

## 状态表达

健康、同步、运行、等待人工、恢复和停止状态同时依赖图标或状态点、标签和说明文字。加载状态保留应用壳和布局，使用低对比骨架；空状态保持信息结构并提供首要动作；错误状态保留最近可信快照。

Workshop 账号状态沿用同一语义体系：未登录使用中性灰，验证码发送与 token 刷新使用信息蓝，已登录使用健康绿，会话失效使用错误红。账号标识保持可读但适度脱敏；access token、refresh token 和具体过期时间不形成视觉字段。认证错误在账号表单内就地出现，不占用 Runtime 人工事项的琥珀色层级。

hover 只轻微改变背景或边界，active 使用 0.98 缩放，focus-visible 在所有可操作元素上使用半透明紫色双像素轮廓和 2px offset，且不被容器裁切。正文对比度不低于 4.5:1，大号文字不低于 3:1，必要图形、控件边界和焦点与相邻颜色不低于 3:1。页面切换使用 160ms 淡入和 2px 位移，不使用长距离运动；减少动效设置下取消非必要位移与缩放。

## 主题策略

当前确认主题是亮色工作区与深色控制侧栏的混合主题。系统跟随能力只影响原生窗口控件，不自动反转工作区信息层级。完整暗色工作区需要独立的人类确认后才能成为新主题。
