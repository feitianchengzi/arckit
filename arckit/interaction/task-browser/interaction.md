# Task Browser - 交互规范

## 交互策略

### 核心任务

用户从 Automation Command Center 的任务状态导航进入 Task Browser，在当前项目范围内浏览某一服务器任务状态的完整列表、检查单项任务及其项目和 Runtime 关联，并执行权限允许的状态操作。Task Browser 负责观察和人工状态处置，不承担自动队列控制。

### 用户场景

1. 用户从“所有项目 / 待处理”进入，查看哪些任务已经获得自动执行资格，以及它们在跨项目队列中的顺序。
2. 用户从单个项目的“待评审”进入，阅读任务详情并明确确认其可以进入待处理队列。
3. 用户从“进行中”进入，打开关联 Runtime；任务没有本地 Runtime 或状态异常时进入 Automation Recovery Center。
4. 用户从“已完成”进入，在右侧 Inspector 审查结果、全部验收问题及进展，提交新的验收问题，或在证据充分时将任务标记为已验收。
5. 用户从“已验收”进入，继续查看全部验收问题及进展并可提交新的验收问题；来源待办和旧完成结果保持不变。已取消任务保持只读，阻塞任务根据恢复条件返回待处理或恢复原运行。
6. 用户操作任务时发现服务器版本已变化。页面不覆盖新状态，而是刷新该任务并解释冲突。

### 主路径

1. Command Center 传入当前项目范围和任务状态；直接进入时默认使用“所有项目 / 待处理”。
2. Task Browser 保留同一应用壳，在左侧高亮项目范围和任务状态。
3. 页面按 `project_id + state` 拉取任务，显示服务器快照时间、结果数量和当前筛选条件。
4. 用户选择任务，右侧 Inspector 展示内容、所属项目、本地工作区、自动执行资格、关联 Runtime、状态历史和可用动作。
5. 用户执行状态操作时，页面先确认权限与当前服务器版本，再提交状态更新。
6. 服务器确认后，任务从当前筛选结果移出或更新；状态计数、Command Center 队列和 Inspector 同步刷新。
7. 用户返回 Command Center 时恢复原项目范围；从 Runtime 入口进入时可直接返回对应运行。

### 决策点

- 左侧项目和状态共同形成观察范围。两者只过滤任务，不改变项目是否参与自动化，也不重排自动队列。
- 待处理列表显示由 Runtime 计算的跨项目队列序号；列表自身的搜索或排序只改变显示，不改变真实领取顺序。
- 待评审任务只有在用户具备状态更新权限并明确选择“确认可处理”后才变为待处理。
- 进行中任务有且仅有一个本地关联 Runtime 时，主动作是“打开运行”；没有关联 Runtime、存在多个关联 Runtime或项目工作区失效时进入恢复中心。
- 已完成任务的主动作是“审查结果”；用户具备权限时可在证据完整后标记已验收，也可提交独立验收问题。
- 已取消任务是只读终态。已验收任务不重新打开原待办执行，但允许新增独立验收问题并查看其进展。
- 已阻塞任务有可恢复的原 Runtime 时可以恢复原运行；否则只能在依赖解除后返回待处理队列。
- 任意状态更新都以服务器返回为准。版本冲突、权限变化或任务已被其他客户端修改时，不覆盖服务器状态。

### 信息架构

#### 应用壳

- 左侧保留 Automation Command Center、项目列表和七种任务状态。
- 当前项目和当前状态同时高亮；状态数量限定在当前项目范围。
- 顶部命令栏展示面包屑、服务器快照时间、搜索、刷新和返回 Command Center。

#### 任务内容区

1. 标题展示当前状态、项目范围、结果数量和一句状态解释。
2. 筛选条展示搜索、排序与“仅显示可执行”等辅助过滤。
3. 任务表格展示任务、项目、优先级、更新时间、执行/结果状态。
4. Inspector 展示服务器事实、项目与本地工作区、关联 Runtime、证据摘要、状态历史和可用动作；completed/accepted 状态额外展示该待办的全部验收反馈项、独立状态、Case/Run 和最近进展。

### 状态流

`Command Center → 选择任务状态 → Task Browser 列表 → 选择任务 → Inspector`

`待评审 → 确认可处理 → 待处理 → 从当前列表移出 → Command Center 队列更新`

`进行中 → 打开关联 Runtime → Command Center 当前运行或 Intervention Workbench`

`进行中但无有效 Runtime → Automation Recovery Center → 重试启动 / 标记阻塞`

`已完成 → 审查结果 → 标记已验收 → 已验收`

`已完成 | 已验收 → 提交验收问题 → 独立反馈 queued → 查看进展或同一对话 → resolved`

`已阻塞 → 恢复原运行 → 进行中` 或 `已阻塞 → 返回队列 → 待处理`

`提交状态更新 → 版本冲突 → 刷新服务器事实 → 保留新状态并重新选择动作`

### 反馈与恢复

- 状态更新期间锁定当前任务动作，但允许浏览其他任务。
- 成功后显示服务器确认结果，并同步当前筛选数量、项目计数和 Command Center 队列。
- 任务移出当前状态时，在原位置显示短暂结果反馈，随后选中相邻任务；列表为空则进入当前范围空状态。
- 拉取失败时保留最近成功结果和快照时间，不把旧数据计入自动领取判断。
- 版本冲突时展示“服务器状态已变化”，刷新 Inspector，不自动重试原操作。
- 进行中任务失去 Runtime、工作区、项目权限或服务器归属时，Task Browser 只展示异常并进入 Recovery Center，不直接修复状态。

### 输入输出边界

- 输入包括项目范围、任务状态、服务器任务快照、本地项目绑定、Runtime 关联、用户权限与搜索条件。
- 输出包括筛选后的任务列表、状态更新请求、独立验收反馈创建请求与进展、Runtime/Workbench/Recovery Center 导航和审查结果。
- 任务服务器拥有项目归属、任务内容和七种任务状态；Task Browser 不直接修改本地 Runtime 状态。
- Renderer 不自行推断状态更新成功；只有服务器响应后才更新任务事实。
- 搜索、显示排序和项目/状态筛选不影响自动队列；自动队列顺序只由 Command Center 的确定性策略生成。

### 线框投影要求

- `default.html` 投影待处理列表、待评审确认、进行中任务、已完成与已验收任务的验收反馈详情、已阻塞恢复、取消任务确认、空状态和同步/版本冲突。
- 状态操作确认必须在设备框内投影为 Sheet、Alert 或 ConfirmationDialog。
- 所有状态保持同一项目范围和返回 Command Center 路径。

## 页面状态

| 状态 | 触发条件 | 关键控件 | 首要动作 |
|---|---|---|---|
| 待处理列表 | 从待处理状态进入且存在结果 | NavigationSplitView、Table、Inspector | 审查队列资格 |
| 待评审确认 | 选择待评审任务并具备权限 | Sheet、Inspector | 确认可处理 |
| 进行中任务 | 选择进行中任务 | Inspector、DisclosureGroup | 打开运行或进入恢复中心 |
| 已完成验收 | 选择已完成任务 | Inspector、验收反馈列表、Composer、ConfirmationDialog | 提交验收问题或验收任务 |
| 已验收反馈跟踪 | 选择已验收任务 | Inspector、验收反馈列表、Composer | 查看进展或提交新问题 |
| 已阻塞恢复 | 选择已阻塞任务 | Inspector、ConfirmationDialog | 恢复原运行或返回队列 |
| 取消任务确认 | 非终态任务没有活动 Runtime | ConfirmationDialog | 确认取消或返回 |
| 当前范围为空 | 项目与状态组合没有结果 | ContentUnavailableView | 切换状态或返回总览 |
| 同步或版本冲突 | 拉取失败或任务版本已变化 | Alert、Inspector | 刷新服务器事实 |

## 导航流程

### 进入方式

- Command Center 左侧的七种任务状态进入对应 Task Browser 筛选。
- Command Center 指标卡进入预设项目范围与状态的 Task Browser。
- 桌面通知可以深链到指定任务；页面仍先恢复项目和服务器任务事实。

### 页面内导航

- 切换项目保留当前任务状态；切换状态保留当前项目范围。
- 选择任务只更新 Inspector，不改变 URL 中的项目与状态筛选。
- 打开运行返回 Command Center 的当前运行；人工处理进入 Intervention Workbench。
- 异常进行中任务进入 Automation Recovery Center。

### 离开方式

- 返回 Command Center 时保留当前项目范围，不保留临时搜索文本。
- 状态更新成功后仍停留在 Task Browser，并选择当前结果中的相邻任务。
- 设置或工作区绑定完成后返回原任务 Inspector，并重新验证执行资格。

## 交互行为

### 项目与状态导航

- 项目和状态是两个正交筛选轴，当前组合始终显示在标题和面包屑中。
- “所有项目”聚合当前用户可访问项目的任务，不产生新的任务副本。
- 状态数量来自同一服务器快照；部分项目同步失败时显示不完整标记。

### 列表与 Inspector

- 待处理列表按真实自动队列序号展示；其他状态默认按更新时间倒序展示。
- 搜索只匹配当前项目与状态范围。
- Inspector 始终展示任务所属项目，避免跨项目聚合时误操作。
- 无权限的状态操作隐藏或禁用，并解释权限来源。

### 状态操作

- “确认可处理”执行 `pending_review → pending`。
- “标记已验收”执行 `completed → accepted`。
- “提交验收问题”创建独立反馈项并追加同一待办会话消息，不改变 completed/accepted 状态，也不把任务返回待处理队列。
- “返回队列”执行 `blocked → pending`；“恢复原运行”执行 `blocked → in_progress` 并恢复原 Runtime。
- “取消任务”只对非终态且没有活动 Runtime 的任务开放；活动 Runtime 必须先进入 Recovery Center 安全停止。
- Task Browser 不提供待处理任务的“立即执行”；领取由自动队列负责。

## 弹窗/对话框

| 名称 | 触发 | data-kit | 内容 |
|---|---|---|---|
| 确认可处理 | 待评审任务进入待处理 | Sheet | 项目、任务、执行资格和确认动作 |
| 验收任务 | 已完成任务标记已验收 | ConfirmationDialog | 结果证据、终态影响和确认动作 |
| 恢复阻塞任务 | 已阻塞任务恢复 | ConfirmationDialog | 恢复原运行或返回队列的差异 |
| 取消任务 | 非终态任务取消 | ConfirmationDialog | 当前状态、Runtime 影响和取消动作 |
| 版本冲突 | 状态更新返回版本变化 | Alert | 服务器新状态和刷新动作 |

## 错误处理

| 错误类型 | 展示方式 | 恢复操作 |
|---|---|---|
| 任务列表拉取失败 | 保留旧列表并标记过期 | 重试当前项目与状态 |
| 状态更新失败 | Inspector 就地错误 | 重试或保持服务器状态 |
| 版本冲突 | Alert 与刷新后的 Inspector | 基于新状态重新操作 |
| 权限不足 | 禁用动作与权限说明 | 刷新身份或返回只读浏览 |
| 进行中但无 Runtime | Inspector 异常卡 | 进入 Recovery Center |
| 项目工作区失效 | 项目与执行资格提示 | 重新绑定后再验证 |

## 加载策略

| 场景 | 策略 |
|---|---|
| 首次进入 | 保留应用壳，加载当前项目与状态列表 |
| 切换项目或状态 | 保留标题与筛选，替换表格骨架 |
| 搜索 | 本地过滤已加载页，服务端分页继续携带筛选条件 |
| 状态更新 | 锁定当前任务动作，其他列表浏览不阻塞 |
| 分页 | 表格底部加载下一页并保留当前选中任务 |
