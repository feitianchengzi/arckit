# 项目事情台交互

## 交互策略

核心任务是以稳定事情身份表达目标、检查结果、处理例外与改变方向。事情列表负责定位；中间场景内容负责直接操作；消息按需打开。生命周期改变内容与动作，不改变事情身份或强制跳页。

事情台作为与 Chat 并列的新独立页面入口，导航名称为 Thing，不接管应用默认路由或替代既有业务页面。主导航直接保留各业务入口，不收进“全部页面”二级菜单。本轮只聚焦事情台页面内体验；项目列表、所有事情、需要我关注和项目资源不再作为新增全局入口。需要我关注保留在页内状态筛选中。

此边界依据用户 2026-09-17 的明确修正。生产规格和技术方案已同步为 Thing 独立入口、四组业务导航与跨项目列表；生产验证记录随实施 Case 维护。

## 主路径

1. 用户从跨项目事情列表选择事情，中间展示概览，底部输入关联当前事情。
2. 用户从列表底部发起，首条发送创建自己负责的待评审事情并开始交流；失败显示已创建身份并允许重试。
3. 用户可以直接 Auto 或先分析。开始 Auto 沿用事情会话并根据实际资格执行/排队。
4. 运行中发送补充显示待生效；暂停并讨论先请求暂停，再允许继续；仅显式继续恢复自动执行。
5. 用户查看阶段成果、检查证据和验收标准；提交独立验收问题，解决后确认验收。

## 导航与布局

左侧使用随明暗主题适配的业务页面导航，保持既有四组类别：PERSONAL（Today、Chat、Thing）、PRODUCT（Product）、PRODUCT LIFECYCLE（Idea、Work、Automation、Release、Operations、Feedback）、ORGANIZATION（Organization、Engineering）。Thing 为当前入口，Chat 名称不变。底部完整个人中心按钮打开“账户与 Runtime”。不展示项目列表、项目计数、工作分组或项目资源导航。列表统一浏览跨项目事情，项目归属在事情属性及创建表单中表达；运行定位和创建不切换隐藏的项目范围。

主体顶部复用 CONVENTIONS.md 定义的唯一全局上下文栏，产品范围、同步、运行、反馈与设置在所有页面保持一致。事情列表遵循顶部产品范围；窄窗列表入口位于内容区。

运行状态弹窗包含“所有项目 · 此设备”范围、可滚动的需要处理/正在执行/等待执行分组，以及统一的自动领取、暂停领取与设置入口。点选事情定位到所属项目详情；再次点击、外部点击、关闭按钮或 Esc 关闭，键盘关闭恢复触发按钮焦点。

事情列表控制区两行：第一行标题与数量、状态选择（含需要我关注）、更多筛选图标；第二行 31px 搜索框。更多筛选展开执行人/优先级和清除筛选，按钮表达展开状态。列表保持单行，底部是唯一固定创建入口。

详情标题不承担大面积展示。属性通过紧凑面板查看/编辑。概览、资料与协作、成果与验收、活动保持稳定入口。

## 个人中心

“账户与 Runtime”包含工作空间同步和产品反馈、账号摘要与邮箱/手机验证码登录、活动执行下的退出确认、高级任务源及三种认证模式、两组 Codex 默认值与清单、YOLO、代理、独立 Codex 保存和完整保存并同步。所有既有字段和动作保持可达。能力映射、优化差异和模拟边界见 `account-capabilities.md`。运行概况内的执行设置独立存在。

## 内容状态

- 待处理：目标、当前判断、完成标准与开始/分析操作。
- 分析中：分析结论、尚待明确问题、可查看阶段方案，不自动生成固定计划。
- 执行中：当前工作、已取得进展、待解决问题和下一步；有计划时可展开调整。
- 待决定：顶部直接呈现问题与选项入口，允许先讨论。
- 排队：显示等待位置/条件，允许补充或撤回。
- 暂停、停止、失败：保留现场和草稿，显示对应继续或恢复动作。
- 外部等待/阻塞：显示具体条件与恢复入口，评论不自动解除等待。
- 完成：突出成果、证据、逐项标准与问题；未解决问题阻止验收。
- 验收：结果与检查只读，来源可追溯。

## 消息与上下文

消息层只覆盖中间区域，背景详情不可操作且保留位置，右侧列表仍可切换。Esc/关闭返回原详情入口。每条消息可保存为共同约定，用户决定是否采纳；来源可定位并高亮。团队留言可放入 Agent 草稿后发送，不自动转换为指令。

资料预览显示名称、内容/附件、来源与引用状态。共同约定与概览同步。完成标准从概览编辑、成果页核对，不能保存两份分叉副本。阶段成果可以先于执行完成。

## 状态反馈与恢复

运行状态面板支持再次点击、外部点击与 Esc 关闭；关闭不关闭消息层。无运行显示空闲与执行设置。新消息、运行事件与同步更新不抢选择、不重置草稿及阅读位置。

目标、属性、标准或安排提交失败保留输入；冲突显示当前事实并允许核对重试。安排修改显示待生效，实际边界采用后更新；暂停期间修改继续保持暂停。

## 窄窗口与键盘

760px 及以下事情列表变为抽屉；列表底部保留创建。运行概览限制在视口内。390px 输入、标题、标签页、表单与消息无水平溢出。所有图标按钮提供标签；弹层关闭恢复焦点；输入法组合过程不触发发送或重建输入。

## 原型与覆盖

default.html 是完整正式原型，包含主路径、业务页面导航、右侧列表、中央消息和局部异常恢复；不依赖探索目录加载样式、模型或行为。interaction.md 是交互策略源，原型是可操作投影。生产实现不得加载样本模型或定时推进逻辑。

## 视觉依据

原型使用 arckit/visual/_library/brief.md、design-tokens.yaml、component-catalog.yaml、state-contract.md 和 themes/light.yaml / dark.yaml（2026-09-18 主题适配）。通过 ../../visual/_library/generated-tokens.css 读取 Token；visual.css 仅映射页面组件规则，不维护第二套数值事实。基础样式中的 green 别名仅兼容既有选择器，值指向橙色 accent 角色。

浅灰业务页面导航、白色内容面、浅杏橙主操作与淡橙选择、中性链接和选中文字、明确的状态色、14px 正文和 15px 对话共同构成可读层级。业务状态标签与执行方式分别表达；运行详情及属性面板保留执行方式。输入边界、焦点、危险动作和禁用状态遵循正式组件契约。

## 操作与状态覆盖

| 场景 | 触发与结果 | 恢复或连续性 |
|---|---|---|
| 发起事情 | 列表底部输入项目和首条内容，建立自己的待评审事情并打开协作消息 | 本地提交失败保留输入，重试不重复创建；真实分步失败另行验证 |
| 分析转 Auto | 先分析打开消息，从同一事情开始 Auto | 持续会话不更换，不自动填充固定计划 |
| 补充与调整 | 运行中补充或调整安排显示待生效 | 下一执行边界采用；暂停时保存仍保持暂停 |
| 运行概况 | 顶栏打开本设备跨项目概况 | 点选定位；关闭不影响消息层；Esc 返回触发按钮 |
| 资料与约定 | 添加资料、切换上下文、留言存为约定 | 只有明确采纳的约定进入概览，留言交给 Agent 先放入草稿 |
| 成果与验收 | 成果可先于完成；完成后核对共用标准和问题 | 未解决问题或未确认标准阻止验收；验收结论只读 |
| 离线/无权限 | 提交显示原因，保留目标或消息草稿 | 恢复连接/权限后对原事情重试 |
| 版本冲突 | 保存检测版本变化，保留打开的表单 | 核对最新版本显示当前事实；用户确认后重新提交，不静默覆盖 |
| 暂停/停止/失败/外部等待 | 显示实际控制状态与对应说明 | 明确继续/恢复/重新检查沿用身份；评论不自动恢复 |
| 空列表 | 不匹配的筛选保留搜索与创建入口 | 清除筛选恢复；不以空结果清除数据 |
| 键盘与输入法 | 可聚焦控件、Tab、Esc、Ctrl/⌘+Enter | 输入法组合不触发提交或刷新输入 |
| 窄窗 | 760px 及以下列表抽屉、中央消息受限 | 390px 和 200% 缩放不出现页面级水平溢出 |

## 原型模拟边界与复现

README.md 提供打开与验证命令；scenarios.html 是与产品区分开的本地异常场景工具。正式原型、异常场景和探索稿分别使用独立存储。所有 Agent 与业务动作只修改当前样本，不连接真实服务，不访问麦克风。

并列业务导航在原型中通过独立标签页访问已有页面设计，以保留当前原型的事情、草稿和阅读位置；生产仍按应用壳契约在应用内切换。Organization 复用 platform-workspace/collaboration-views.html。未重做旧页面的交互能力。

加载场景只表达短暂的内容忙碌反馈；上传附件、真实流式 Agent、先创建成功后首条发送失败、跨设备/进程恢复、实际线程幂等与原生窗口行为不由本地样张证明。正式产品要求保持有效，生产证据位于对应验收矩阵。
