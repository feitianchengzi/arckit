# Operations Workspace - 交互规范

## 交互策略

Operations 承接发布后的对外市场化动作，展示受众、渠道、内容、负责人、时间窗口和效果信号。页面把市场动作与 Release、Feedback、Idea 和 Work 的关系呈现给团队，但不宣称接入外部平台。

英文界面统一使用 `Operations`，中文说明使用“运营”。

## 页面结构

- 顶部展示本周期运营主题、待发布动作和效果信号。
- 左侧按待发布、进行中、已复盘显示动作。
- 中间展示目标受众、渠道、内容和时间窗口。
- 右侧展示来自 Feedback 与产品数据的示意信号，以及回流入口。

## 主路径

1. 用户进入 Operations 并选择产品范围。
2. 页面展示当前市场动作与渠道计划。
3. 团队查看负责人、内容资产、时间和关联 Release。
4. 团队阅读用户反馈与触达信号。
5. 新机会或问题进入 Idea、Work 或 Feedback 的转换预览。

## 状态与反馈

- 待发布动作显示缺少的内容或批准。
- 进行中动作显示时间窗口和示意信号。
- 已复盘动作展示结论与后续事项。
- 未接入渠道、分析或 CRM 时，页面明确显示“示例数据”或“未接入”。

## 边界

Operations 不自动发布社交媒体、邮件或广告内容，不写入外部分析或 CRM 平台，也不把示意指标当作真实商业结果。

## 全局上下文原型

`default.html` 使用 `_shared/global-context.js`、`global-shell.js` 与 `context-pages.js`，连续演示 CONVENTIONS.md 定义的产品范围、对象选择、草稿和统一顶部能力；页面专项状态图保留在 `page-states.html`，其旧窗口壳仅作历史示意。原型保存及运行状态均为浏览器本地模拟，服务调用和页面专项深层操作的验证边界沿用各自说明。

当前生产入口尚未接入运营记录服务，原型主入口对应显示当前产品范围与规划空态；专项图中的数量和渠道为示意，不作为真实产品统计。
