# Today Workspace 交互说明

> 状态：🟡 探索中
> 页面入口：`Today`

## 交互策略

Today 是 ArcOrbit Desktop 的人工责任工作台。页面只处理两类事情：新用户把一个或多个项目配置到 Automation 可以领取和执行任务的状态；返回用户处理来自其他页面、已经明确交给人的责任项。

Today 不生成下一工作，不展示普通待办、未读反馈、队列容量、已完成历史和完整运行进度，也不根据活跃度推断“你可能该做什么”。来源页面发布稳定责任对象和动作契约，Today 承载跨项目发现、选择、阅读、直接操作、即时结果确认和异常恢复。

待验收 Work 责任项在操作台内直接展示验收问题列表。每项始终显示问题原文、当前处理状态和来源提供的进展，不使用默认折叠的 disclosure。用户提出新问题并获得来源确认后，Task 保持 `completed`，仍有效的当前责任项保持选中并以 fresh-read 结果原位更新列表；用户在提交期间主动选择了其他责任项时保留较新的选择。

页面采用双工作区与人机接力时间线的组合：

- `需要你处理` 汇总跨项目人工责任；
- `项目配置` 管理一个或多个项目的 Automation 执行前置；
- Automation 的复杂责任项在操作台内展示从自动执行到人、再回到自动执行的接力时间线。

## Desktop 信息架构

### 应用导航

左侧应用导航复用 ArcOrbit 的稳定信息架构：

- `PERSONAL`：Today、Chat；
- `PRODUCT LIFECYCLE`：Idea、Work、Automation、Release、Operations、Feedback；
- `ORGANIZATION`：Organization、Engineering。

Today 不新增导航分组或 Projects 主入口。项目目录和项目治理继续归属 Organization，Today 的项目栏只是当前页面内的人工责任范围选择器。

Today 导航项显示当前可确认的全部人工责任数。来源未知时使用未知标记，不用零掩盖未知。账户、同步和设置位于导航底部；全局自动领取属于 Automation，不占据 Today 常驻工具栏。

### Today 三栏工作区

应用导航右侧固定为三个可独立滚动的区域：

1. **项目栏**：全部项目、项目搜索、添加项目，以及每个项目的配置状态、人工责任数和最小自动状态；
2. **责任栏**：`需要你处理 / 项目配置` 两个模式和对应对象列表；
3. **操作台**：当前对象的责任原因、影响、上下文、关联身份、历史、动作和提交结果。

项目栏选择“全部项目”时责任栏聚合所有项目；选择单个项目只改变当前查看范围，不改变 Today 导航总数，也不影响其他项目后台运行。窗口变窄时先把项目栏收进侧栏入口，责任栏与操作台保持同屏；再窄时责任栏成为可返回的列表层，操作台保留当前选择和输入。

后台快照、实时事件和其他页面状态更新以当前责任项 identity 为操作台上下文边界。同一责任项的展示事实未变化时，操作台保持现有内容节点、滚动位置、焦点、文本选区和草稿；展示事实变化时原位更新并保持这些阅读与输入状态。用户选择另一责任项时进入新上下文，操作台从新详情顶部开始，不继承上一责任项的焦点或滚动位置。

## 项目栏

- “全部项目”显示人工责任总数、配置未完成数和来源未知数。
- 每个项目使用稳定列表行，行内显示项目名、`需处理 N / 配置状态 / 自动状态`。
- 项目按“有人工责任、配置阻塞、来源未知、其余项目”分区；分区内稳定排序，实时计数变化不使项目跨行跳动。
- 项目栏底部的“添加项目”在 Today 内打开项目目录 Sheet。
- 项目栏不使用 Workset 裁剪人工责任；Workset 只作为其他页面的观察范围事实。

## 责任栏

### 需要你处理

责任项按权限安全、活动执行阻塞、部分成功事务、Work 状态门、项目配置阻塞排序。每行展示责任类型、单行问题、项目、来源对象、等待时间和同步新鲜度。同一来源对象的多个症状合并为一个责任项。

### 项目配置

列表展示当前范围内全部未 ready 项目及当前唯一阻塞。项目检查可以并行；一个项目被人工阻塞时，其他项目继续检查或自动执行。已 ready 项目只保留在项目栏，不占据配置列表。

责任栏底部只显示最小非人工摘要，例如“3 个项目正常推进，1 个项目自动恢复中”，不显示任务名称、下一任务或完整阶段。

## 操作台

操作台保持以下稳定层级：

1. 身份：责任类型、项目、来源、来源对象、等待时间和最近同步；
2. 为什么需要你：当前责任、阻塞范围、不处理的结果；
3. 上下文：完成决定所需的完整业务事实；
4. 关联对象：Project、Task、Run、Case、thread、Feedback 等身份关系；
5. 历史或人机接力：导致责任交接的关键变化；
6. 操作：字段、候选项、影响预览和确认；
7. 固定操作栏：提交、取消、状态反馈。

选择另一项只更新责任栏选择和操作台，保留项目范围、滚动、栏宽及每个责任项自己的草稿。复杂证据使用 disclosure；确认动作使用 Today 上方的 Sheet、Alert 或 ConfirmationDialog，不跳转来源页面。

## 人工责任收录契约

对象同时满足以下条件才进入 Today：

1. 有稳定的 `source_object_id` 并可 fresh-read；
2. 来源状态明确表示当前用户是下一责任方；
3. 不处理会阻塞、悬置或留下已经发生但未收口的流程；
4. 来源提供当前用户可在 Today 内执行的类型化动作；
5. 动作声明权限、前置版本、幂等身份、成功状态和失败恢复。

每个责任对象包含聚合身份、来源、项目、责任类型、原因、影响、最小证据、完整证据分区、允许动作、来源版本、幂等键、创建时间和同步时间。相同动作不得同时以通知、待办和恢复项重复出现。

## 首次使用和多项目配置

### Today 前置门

冷启动先完成全局 Setup Readiness 和 Login。任一未通过时不显示 Today，也不把安装 Codex 或登录账号包装成 Today 责任项。两者通过后进入应用。

### 单项目完成口径

项目同时满足以下四项即为 Automation-ready：

1. 当前用户可访问项目；
2. 项目有当前设备上的有效本地 repository 绑定；
3. 绑定目录的项目级 Setup Readiness 为 `ready`；
4. 当前用户已在当前设备允许该项目参与自己的 Automation。

待办数量、执行人、全局自动领取、队列状态和第一次运行不属于项目配置完成条件。

### 连续主路径

1. 新用户进入 Today，系统自动选择 `项目配置`，项目栏为空。
2. 用户选择“添加项目”，Sheet 提供新建个人项目、从可访问项目目录添加、使用邀请码加入三种真实来源。
3. 用户可以一次选择多个可访问项目；创建个人项目一次创建一个。确认后项目立即进入项目栏。
4. 系统为每个项目独立检查本地绑定、项目 Setup 和当前设备的 Automation participation；无风险检查并行执行。
5. 配置列表为每个未 ready 项目展示当前唯一阻塞。用户选择项目后在操作台完成目录选择、Setup 确认或本机参与选择。
6. 操作 Project A 时，Project B/C 的检查和 Automation 保持运行；Project A ready 后只从配置列表移除，不改变当前其他项目状态。
7. 任意一个项目 ready 后，操作台显示“前往 Work 新建待办”。新建待办属于 Work，不在 Today 内完成。
8. 用户以后添加项目时复用相同路径，已有项目和人工责任草稿保持不变。

应用重启不保存“向导第几步”。Today fresh-read 全部项目事实，恢复原项目选择、栏宽和仍有效草稿，并把每个项目放回事实决定的状态。

## 项目配置操作

| 当前阻塞 | 操作台事实 | 直接操作 |
| --- | --- | --- |
| 没有本地目录 | 项目身份、当前设备、已有本地项目 | 选择目录或添加本地项目 |
| Setup 检查中 | 已完成检查、当前检查和影响范围 | 允许后台完成；不要求确认 |
| Setup 写入或冲突 | 写入目标、变更摘要、漂移、冲突、备份边界 | 确认写入、备份并恢复、保留并退出、重新检查 |
| participation 未开启 | 当前设备、项目、自动领取影响 | 当前用户开启或保持关闭 |
| 来源未知 | 最近可信事实、失败来源、受影响项目 | 只重试失败来源 |

## 其他页面的人工责任

### Chat

只有 `waiting_approval` 进入 Today。操作台展示 session、turn、工具动作、目标路径或资源、工作区边界、请求理由和影响。用户执行“本次允许”或“拒绝并继续”，结果回到同一 session/thread/turn。

### Automation 人工交接

- 产品决定或缺失事实：展示 Task、Case、当前 gap、Agent 已确认事实、选项影响和相关消息；提交决定后继续同一 task session/thread/Case。
- 外部依赖：展示责任方、外部对象、完成条件和最近检查；用户选择“已处理，重新检查”，通过后才恢复。
- 用户离开或选择其他责任项时，当前输入按 attention item 保存，Automation 保持等待人。

### Automation 恢复

Today 按 Recovery 类型加载不同操作面，不压成通用“重试”：

| 类型 | 关键证据 | 操作 |
| --- | --- | --- |
| Runtime 启动失败 | 服务器任务版本、启动意图、工作区检查、持久 thread | 重试同一启动、补充说明并继续、重新绑定、标记阻塞 |
| Case 绑定待确认 | terminal handoff、候选 Case、trusted receipt、Git closeout | 复用已有 Case、作为新事项继续、补充说明、标记阻塞 |
| 同一 lane 多个进行中任务 | 冲突任务、execution identity、Runtime 匹配 | 为该 lane 选择唯一恢复任务 |
| 外部任务状态变化 | 服务器新状态、来源、安全停止阶段 | 等待安全停止并重新对齐 |
| Work Sync 异常 | 受影响项目、最近快照、仍可信范围 | 只重试异常来源或重新认证 |
| CLI 交接或写回失败 | Case、执行权、commit/writeback 检查点 | 重试交接、恢复自动执行、重试写回或标记阻塞 |

### Work

| 状态 | 操作台 | 操作 |
| --- | --- | --- |
| `pending_review` | 完整内容、属性、提交者和项目 | 确认可处理，执行 `pending_review → pending` |
| `completed` | 完成证据、直接可见的验收问题原文、处理状态、进展、对话和版本 | 无未解决问题时标记已验收；否则提出验收问题，来源确认后保持当前有效责任项并原位刷新问题列表 |
| `blocked` | 阻塞原因、Runtime/Case、可恢复身份 | 返回待处理、取消；有可信原运行时恢复原运行 |
| 跨产品移动部分成功 | 新旧 Task、创建和删除阶段 | 重试删除旧待办或保留两份 |

### Feedback

Feedback→Task 已创建 Task 但关联失败时进入 Today。操作台展示 Feedback、已创建 Task 和事务阶段，动作只重试关联，不创建第二个 Task。

## Automation 人机接力时间线

复杂 Automation 责任项在操作台内展示有界时间线：

`自动执行 → 形成责任交接 → 等待用户 → 用户提交 → 来源校验 → 恢复原执行 / 保持等待 / 进入恢复`

时间线只显示改变责任方和恢复路径的语义节点，不展示逐命令日志、token delta 或完整流水线。当前节点明确责任人、保持的 session/thread/Case、冻结范围和下一可能状态。

不同项目各自保持时间线。Project A 等待决定只冻结其任务或 lane；Project B 的健康执行继续。提交成功必须恢复原执行身份，不创建替代 Task、Run 或 thread，除非来源动作明确要求“作为新事项继续”。

## 连续操作状态

`缓存列表 → 后台 fresh-read → 保持仍有效选择和操作台阅读上下文 → 选择责任项 → 从新详情顶部加载来源契约 → 编辑 → 提交中 → 来源确认 → 原地展示结果 → 移出 Today → 选择相邻项`

`编辑 → 来源版本变化 → 提交冲突 → 保留草稿并展示差异 → 基于新事实重新决定`

`编辑 → 来源撤销当前用户责任或操作权限 → 提交拒绝 → 展示来源新事实 → 移出当前用户的 Today；未提交输入保留为本地记录`

`应用重启 → 恢复选择与草稿 → fresh-read → 对象仍等待当前用户则恢复操作台；已被处理则短暂确认来源结果后移除`

`待验收项 → 提出验收问题 → 来源确认 → Task 保持 completed → 当前责任仍有效时保持选择 → 问题原文、状态和进展在操作台原位直接刷新`

提交只锁定当前责任项，其他项目仍可读取和操作。同一来源对象只允许一个提交在途。

## 反馈和异常恢复

- 提出验收问题成功后，来源确认结果与 fresh 问题列表同时在原操作台显示；责任项仍有效时不移出 Today、不重置当前选择，提交期间产生的较新用户选择不被旧回调覆盖。
- 其他完成当前责任的成功结果在原操作台展示来源确认的新状态、时间和 identity；确认反馈结束后对象移出 Today，责任栏选择原位置的相邻项。
- 校验失败定位字段并保留输入。
- 版本冲突不自动覆盖或重放，展示服务器新事实和差异。
- 部分成功恢复使用原事务幂等身份，不重复创建业务对象。
- 来源不可用时保留最近可信列表和时间；导航计数显示“已知数量 + 未知来源”，不能宣称零责任。
- 后台 fresh-read、实时事件和主动刷新不重置范围、仍有效的选择、操作台滚动、焦点、文本选区、栏宽和草稿；只有责任项 identity 变化才建立新的操作台阅读上下文。

## 非人工状态

非人工状态只回答系统是否仍可自动推进：

- 正常推进：可工作项目数和正在推进的项目数；
- 自动恢复中：受影响项目和恢复类型，尚未需要人时不进入责任栏；
- 部分未知：失败来源、最近可信时间和重试；
- 没有运行：说明当前没有自动执行，不生成启动或下一工作建议。

## 输入输出边界

输入包括登录用户、全部可访问项目、本地绑定、项目 Setup、Automation participation、Chat approval、Automation handoff/Recovery、Work 状态门、Feedback/Task 部分成功事务和来源新鲜度。

输出包括三栏聚合投影、项目配置操作、人工决定与批准、类型化恢复、Work 状态动作、部分成功收口和即时来源确认。Today 不建立第二套业务状态机，不保存已处理历史，也不复制完整来源管理页面。

## 线框投影

- `default.html`：真实应用导航、三栏桌面工作区、两个责任模式、无责任和来源未知。
- `readiness-details.html`：首次使用与多个项目并行配置。
- `action-details.html`：Chat、Automation、Work 和 Feedback 的完整操作台。
- `action-continuity.html`：一项责任从选择、提交到确认、冲突与重启恢复。
