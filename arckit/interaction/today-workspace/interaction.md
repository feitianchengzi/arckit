# Today Workspace - 交互规范

## 交互策略

### 核心任务

Today 是登录后的个人工作首页。页面根据当前 Workset、Product Workspace、本地绑定、Setup Readiness、Work Task Projection、Automation participation、全局领取状态、活动执行、人工事项和完成结果，回答“ArcOrbit 当前在做什么”和“用户现在最值得做什么”。

Today 不建立新的 Project、Task、Workset、Run、Case 或资格事实。页面把各事实源的当前状态组合为可操作投影，并把写操作交还给 Organization、Work、Automation、Chat 或 Setup Readiness 已有动作。任一动作完成后，Today fresh-read 相关事实并重新选择当前主动作。

页面采用“一个主动作、完整关系按需展开、多产品长期可见”的信息策略：

- 首屏只突出一个当前最值得处理的动作；
- “查看全部准备关系”展示完整前后依赖、已完成步骤和后续影响；
- Product Workspace 就绪度在用户拥有多个产品或首次准备完成后成为长期状态摘要；
- 健康运行不制造需要用户点击的伪任务，人工责任、恢复和验收优先于普通准备动作。

### 用户场景

1. 用户首次登录且没有可访问项目。Today 解释个人项目、加入现有团队和创建团队项目的差异，让用户先选择真实工作归属；创建组织和邀请成员不作为个人首次使用的必要步骤。
2. 用户已有可访问远端项目但未绑定本地目录。Today 不区分 owner、admin 或 member，均以“绑定本地目录”为当前用户可执行的唯一主动作，并说明该缺口同时影响 Chat 和本地 Automation。
3. 项目已绑定但尚未允许自动领取。Today 显示项目级授权的影响范围，用户显式允许后才继续。
4. 当前用户只有待评审任务。Today 解释待评审不会进入 Automation，并允许用户进入 Work 审查，或使用“确认并交给 ArcOrbit”处理明确任务。
5. 当前产品没有待办。用户从 Today 选择“创建并交给 ArcOrbit”，在一个确认 Sheet 中明确产品、执行人、待处理状态和自动执行影响。
6. 项目和任务均可执行但全局自动领取关闭。Today 显示“开始自动执行”，并说明该总闸只作用于已绑定且已授权项目。
7. Automation 正常运行。Today 以当前执行、阶段、最近事件和下一队列为主，不再展示首次准备卡。
8. 存在 requires_human、恢复项、认证失效或完成待验收。Today 把对应人工动作提升为唯一主动作，健康产品和执行保持次要摘要。
9. 用户同时推进多个产品。Today 保留产品来源、工作区状态、自动化授权、任务数量、活动执行和首要阻断，并只为当前最高优先级事项提供主动作。
10. 用户从 Organization、Work、Automation 或 Chat 自由探索。各页面显示与当前对象相关的同一缺口、影响和直接动作；完成后留在原页面并重新计算，不要求返回 Today 才能继续。

### 主路径

1. 登录和全局 Setup Readiness 门禁通过后进入 Today；页面立即显示最近一次本地投影，同时请求当前登录代际的 fresh 平台与 Automation 状态。
2. 系统先识别需要人工负责的运行、恢复、验收和认证事项；存在这类事项时，将其作为唯一主动作。
3. 没有人工事项时，系统检查当前 Workset 是否包含可访问产品。没有产品时显示工作归属选择，不把 Organization 伪装成必经步骤。
4. 对选定 Product Workspace，系统依次检查本地目录、项目 Setup Readiness、Automation participation、当前用户任务资格和全局自动领取总闸。
5. 系统把第一个可由当前用户推进的缺口显示为主动作，并在同一卡片中说明当前产品、影响能力和完成后的下一结果。
6. 用户执行主动作。Today 调用目标页面拥有的操作或打开其复用 Sheet，不复制数据写入规则。
7. 动作成功后保持 Today 的 Workset 和产品范围，fresh-read 受影响事实并原位显示下一个主动作；动作失败时保留当前卡片和输入，显示目标事实源返回的错误。
8. 全部准备条件满足且存在可领取任务时，主动作变为“开始自动执行”或“查看 Automation”；全局总闸已开启时不要求重复确认。
9. 运行开始后，Today 切换为日常推进视图，持续展示活动执行、人工事项、下一工作和产品就绪度。

### 主动作优先级

Today 在同一时间只提升一个主动作，优先级从高到低为：

1. 当前用户必须处理的人工 Gate、恢复、认证失效和权限确认；
2. 已完成任务的结果审查与验收；
3. 活动执行的异常或外部状态冲突；
4. 当前范围没有可推进产品；
5. Product Workspace 缺失本地目录或项目 Setup Readiness 不可用；
6. 项目尚未允许自动领取；
7. 当前用户没有待处理任务，但存在可确认的待评审任务；
8. 当前产品没有可执行工作，可创建并交给 ArcOrbit；
9. 已有可执行任务但全局自动领取关闭；
10. 健康运行、待命、最近完成和普通产品摘要。

同一优先级存在多个对象时，当前单产品范围优先；“项目集全部”下依次使用需要人工负责的对象、活动执行对象、包含当前用户待评审或待处理任务的 Workset 产品，最后使用 Workset 稳定顺序。页面展示被选中的产品来源，不把其他缺口静默标记为完成。

### 准备关系

“查看全部准备关系”使用以下可见步骤，不生成单独的持久 onboarding 记录：

1. 工作归属：存在当前用户可访问且位于当前 Workset 的 Workshop Project；
2. 本地工作区：Project 绑定一个有效本地目录；
3. 项目环境：该目录的项目级 Setup Readiness 可用；
4. 项目授权：Automation participation 已显式允许；
5. 工作资格：存在分配给当前用户且状态为待处理的任务，或用户可以创建/确认一项；
6. 全局领取：全局自动领取已开启且队列未暂停。

Workset 只决定 Today 的观察范围。加入 Workset 不自动绑定目录、授权项目或开启领取；创建项目也不隐式修改 Workset。组织创建、成员邀请和产品集管理只在用户选择对应目标或真实缺口时出现，不作为所有用户的固定步骤。

### Product Workspace 长期摘要

产品摘要分别表达项目连接与当前工作，不把二者压成一个模糊百分比：

- 项目连接：远端可访问、本地目录、Setup Readiness、Automation participation、Work Sync；
- 当前工作：待评审、待处理、活动执行、需要人工、完成待验收；
- 首要阻断：当前产品最先阻止目标动作的事实；
- 可用能力：Chat 可用、本地 Automation 可用、仅远端协作或数据降级。

只有全部组成项都可 fresh-read 时才显示完整就绪。部分同步失败时保留已知项，明确标记未知，不把未知计入完成或阻断数量。

### “创建并交给 ArcOrbit”

该动作表达明确的自动执行意图，不改变 Work 普通“创建待办”的默认待评审语义。

- Sheet 显示完整待办正文、目标产品、执行人“我”、状态“待处理”、本地目录、项目授权和全局领取状态；
- 用户可以修改正文和产品，但执行人和待处理状态的变化必须在提交前保持可见；
- 提交使用 Work 的真实创建动作，以当前用户为执行人并请求待处理状态；
- 创建成功但仍缺本地目录、项目授权或全局总闸时，Today 展示新的首要缺口，不声称任务已经开始；
- 创建失败时保留 Sheet 草稿和目标产品，不产生本地假任务；
- 用户选择普通协作流程时可以转到 Work 的“保存为待评审”，两种动作不共用含糊的提交按钮。

### 跨页面就地引导

Organization、Work、Automation 和 Chat 对同一缺口使用共同事实与动作身份，但按页面任务解释影响：

- Organization 在项目详情解释本地绑定、Workset 和 Automation participation，并直接开放当前项目动作；
- Work 在任务 Inspector 解释执行人、任务状态和项目资格，并提供确认、改派或项目修复动作；
- Automation 解释待处理数量与可领取数量的差异，并提供首个实际阻断的直接修复动作；
- Chat 在 Composer 附近解释 Product Workspace 不可用原因，并允许选择项目和绑定目录，完成后恢复草稿。

就地引导遵循以下规则：

- 只展示影响当前页面主任务的首要缺口；
- 能直接操作时不只提供导航说明；
- 需要多字段输入时打开目标页面复用的 Sheet，完成后返回原页面；
- 本地目录绑定对任意可访问项目成员始终是当前用户动作；项目授权、任务 mutation 等远端治理动作没有权限时，显示所需角色、可处理责任方和返回路径，不显示必然失败的主按钮；
- 同一原因在 Today 和目标页面显示一致的当前事实，页面文案可以按影响场景变化；
- 操作成功后 fresh-read 并原位消失或切换到下一缺口，不要求用户手动刷新。

### 状态流

`登录与全局准备完成 → Today 本地投影 → fresh-read → 人工事项优先判断 → 准备缺口或日常推进`

`没有可推进产品 → 选择个人项目 / 使用邀请码加入 / 创建团队项目 → 加入当前 Workset → 重新计算`

`项目未绑定 → 选择本地目录 → 项目 Setup Readiness → 项目允许自动领取 → 工作资格 → 全局领取`

`待评审任务 → 确认并交给 ArcOrbit → Work 服务器确认待处理 → Today 重新计算 → 开始自动执行`

`没有任务 → 创建并交给 ArcOrbit → Work 创建成功 → 缺口重算或进入可领取`

`自动领取开启 → Work 发布进行中 → Today 日常推进 → 人工事项 / 完成审查 / 下一任务`

`就地修复 → 返回原页面上下文 → fresh-read → 引导消失或显示下一缺口`

### 反馈与恢复

- fresh-read 期间保留最近投影，主动作显示校验中且不可重复提交；
- 动作成功后显示有界确认，再原位切换到下一状态；
- 目标操作部分成功时保留已成立事实和恢复动作，不自动回滚已确认的远端结果；
- Work Sync 或某项目同步失败时，Today 不把队列空态解释为没有工作；对应产品显示数据时间、未知项和重试；
- 当前主动作因权限或外部修改失效时，页面刷新事实并解释变化，不把动作落到另一个产品；
- 用户切换 Workset 或产品范围时取消未提交的派生选择，但保留显式表单草稿并要求重新确认目标产品；
- 活动执行和人工事项不因 Today 切换范围而停止、恢复或重排。

### 输入输出边界

- 输入包括当前用户、Workset 与产品范围、Organization/Project 可访问事实、本地绑定、Setup Readiness、Work Task Projection、Automation participation、全局领取与暂停、活动执行、人工事项、恢复项和完成结果；
- 输出包括主动作投影、完整准备关系、多产品连接与工作摘要、目标页面导航以及目标页面拥有的显式写动作；
- Today 不保存 readiness 百分比、步骤完成记录或第二套资格状态；所有完成与阻断均由当前事实派生；
- Today 不创建组织、邀请成员、绑定目录、修改任务或开启 Automation 的平行接口；复用动作仍由各自事实拥有者校验和提交；
- 页面不因观察范围、卡片打开或“查看全部准备关系”修改 Workset、成员关系、项目授权、任务状态或执行顺序。

## 页面结构

### 应用壳

- Today 位于 `PERSONAL` 第一入口，沿用顶部 Workset、产品范围和全局自动领取总闸；
- 页面不重复 Organization、Work 或 Automation 的完整管理界面；
- 首屏由主动作区、当前运行/人工事项、产品摘要和工作信号组成；
- “查看全部准备关系”在同页 Inspector 或 Sheet 中打开，不跳转为新主导航页面。

### 主动作区

- 标题使用用户目标或当前责任，不使用内部错误码；
- 同时显示当前产品、影响能力和完成后的结果；
- 只保留一个强调主按钮，查看关系、稍后处理和进入详情使用次要动作；
- 主动作不存在时显示健康运行、待命或审查摘要，不伪造“继续”按钮。

### 日常推进区

- 活动执行优先展示任务、产品、阶段、最近事件和是否需要用户；
- “需要你处理”只聚合真实人工责任、恢复与验收；
- 下一工作保留产品来源和任务状态，不把待评审计入可领取；
- 产品摘要在多产品范围下显示全部 Workset 产品，在单产品范围下只显示当前产品。

## 页面状态

| 状态 | 触发条件 | 首要内容 | 首要动作 |
|---|---|---|---|
| 唯一下一步 | 存在可由当前用户推进的首个准备缺口 | 目标、原因、影响、完成后结果 | 当前缺口直接动作 |
| 没有可推进产品 | 当前 Workset 没有可访问产品 | 个人、加入团队、创建团队三种归属 | 选择真实工作归属 |
| 完整准备关系 | 用户展开全部关系 | 六步事实、已完成、当前、未知与后续 | 当前可执行步骤 |
| 创建并交给 ArcOrbit | 当前产品没有合适待办 | 正文、产品、我、待处理、执行影响 | 创建待处理任务 |
| 可执行但总闸关闭 | 存在可领取任务且全局领取关闭 | 项目范围、队列数量、总闸影响 | 开始自动执行 |
| 多产品就绪度 | Workset 包含多个产品或首次准备完成 | 项目连接、当前工作、首要阻断 | 当前最高优先级动作 |
| 健康运行 | 存在无人工事项的活动执行 | 当前任务、阶段、最近事件、下一队列 | 查看运行 |
| 需要人工处理 | 存在 requires_human、恢复或认证责任 | 对象、责任、影响和恢复条件 | 处理当前事项 |
| 完成待审查 | 存在 completed 且未验收结果 | 结果证据、验收问题和产品来源 | 审查结果 |
| 已就绪但无工作 | 项目连接完整且无待评审/待处理 | 可用能力与创建入口 | 创建工作或开始 Chat |
| 部分数据未知 | 一个或多个事实源读取失败 | 最近事实、数据时间、未知范围 | 重试对应来源 |
| 主动作失败 | 目标写操作失败或权限变化 | 原输入、真实错误和当前事实 | 修正、重试或请求责任方 |

## 导航流程

- 登录和全局 Setup Readiness 完成后默认进入 Today；
- Today 主动作打开目标页面复用 Sheet 时记录来源，完成或取消后返回 Today 原范围；
- “查看 Work”“查看 Automation”“打开 Chat”“管理项目”进入对应稳定页面并携带明确产品或对象身份；
- 目标页面就地修复完成后留在目标页面，不强制返回 Today；
- 从其他页面返回 Today 时重新读取当前状态，不恢复已经失效的主动作。

## 弹窗与覆盖层

| 名称 | 触发 | data-kit | 主要内容 |
|---|---|---|---|
| 全部准备关系 | 选择查看全部准备关系 | Inspector | 六步事实、影响、未知与当前动作 |
| 选择工作归属 | 当前没有可推进产品 | Sheet | 个人项目、邀请码加入、创建团队项目 |
| 绑定本地目录 | 项目未绑定 | Sheet | 当前项目、已有本地项目、添加目录、Setup Readiness |
| 创建并交给 ArcOrbit | 当前产品没有合适工作 | Sheet | 正文、产品、执行人、待处理状态和执行影响 |
| 开始自动执行 | 全局总闸关闭且存在可领取任务 | ConfirmationDialog | 作用项目、队列数量、不会停止/修改的范围 |

## 线框投影要求

- `default.html` 投影唯一下一步、可执行但总闸关闭、健康运行、需要人工处理、完成待审查和部分数据未知；
- `readiness-details.html` 投影没有可推进产品、完整准备关系、多产品就绪度、创建并交给 ArcOrbit 和无权限恢复；
- 两个 HTML 保持相同应用壳、顶部 Workset/产品范围和主动作优先级；
- 主动作状态必须显示当前产品、影响和完成后结果；
- 多产品摘要分别展示项目连接和当前工作，不只显示单一百分比；
- 跨页面就地引导分别由目标页面线框投影，Today 不复制目标页面完整表单。
