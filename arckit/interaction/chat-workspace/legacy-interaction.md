# Chat Workspace - 交互规范


## 交互策略

Chat 承接绑定本地 Product Workspace 的自由对话与待办对话，Agent 在同一 thread 内感知和调用当前项目的原生待办能力。页面按项目分组展示会话，用户浏览历史时不需要先选择项目；新建对话时，系统在首条消息发送前持续显式展示将要绑定的 Product Workspace，并允许快速切换。系统持续展示用户消息、Agent 正文、折叠 reasoning、工具活动、权限请求和运行状态。Chat 不要求用户先创建待办，也不把对话自动转成 Idea、Work、Case 或其他正式对象。

每个 Chat session 固定对应一个本地项目根和一个持久 Codex thread。会话与对应待办指向同一持久 thread；创建来源和主待办绑定分别表达。自由对话不自动进入 Automation；待办执行遵循既有 thread 归属、运行所有权、权限与并发约束。切换会话或离开页面不停止正在生成的回答；停止操作只 interrupt 当前会话的当前 turn，并保留部分输出。

核心任务包括浏览会话、建立或恢复对话、提交消息、选择原生能力或 Skill、让 Agent 整理或创建待办、读取和写回待办、继续执行、停止及异常恢复。页面使用左侧应用导航、中间 Chat/文件工作区、右侧会话列表、当前待办详情或文件树的三栏结构。Chat 容纳 transcript 和 Composer，文件在中央独立 Tab 浏览编辑，不增加完整事情详情 Inspector。中间工作区宽度始终服从页面父容器，消息和文件内容不改变页面宽度。

## 页面结构

- 左侧应用导航保持 PERSONAL、PRODUCT、PRODUCT LIFECYCLE、ORGANIZATION 四组，Chat 与 Thing 并列；个人中心复用完整账户与 Runtime 能力。
- 顶部复用全局上下文栏，布局对齐现有 `desktop/renderer/index.html` 与 `global-context.css`：左侧产品集 / 查看 / 管理组合，右侧依次为同步状态、运行状态、产品反馈、同步图标、设置图标；桌面不显示页面导航按钮，760px 及以下折叠；内容区显示 `Chat` 和 Codex 连接状态，新建对话入口位于右侧会话列表底部，会话列表受统一顶部产品范围过滤。
- 右侧会话列表按 Product Workspace 分组，组标题显示工作区名称、可用状态和会话数量；会话以单行标题和状态标记展示，完整标题与状态可悬停读取。拖动左侧分隔线调整列表宽度。
- 每个项目默认展示 5 个会话；点击项目标题展开或收起整个项目，每次“查看更多”增加 5 条，收起再展开恢复 5 条。
- 中间对话区顶部使用 64px 固定高度的紧凑栏，不随窗口宽度、会话状态或操作数量增高。左侧只显示一行会话标题，超出可用宽度时末尾省略，悬停提示和可访问名称保留完整标题。右侧把项目入口与 32px“会话操作”入口并排归组：临时新对话的项目入口可以切换目标 Product Workspace，既有会话在同一位置显示不可改写的固定项目归属。
- 临时新对话的项目入口使用工作区图标、单行省略名称和下拉指示，不使用原生 `select`。激活后，单选菜单锚定入口右侧并从入口下方向下展开；菜单使用中性浮层、10px 圆角、轻阴影、36px 选项行、选中标记和明确 hover/focus，项目较长时名称省略但保留完整提示。菜单不得遮挡顶栏标题或向上覆盖全局上下文栏。
- transcript 按时间显示用户消息、Agent 正文、reasoning disclosure、工具活动、权限请求和错误恢复提示；消息与 Markdown 内容沿中间对话区宽度收缩。
- Composer 位于中间对话区底部，包含多行输入、当前会话的“模型能力”配置入口、靠右的发送或停止主按钮、快捷键说明和当前权限边界摘要。
- 顶栏不展示“整理为待办”、完成/运行状态、待办业务状态或关联身份。整理能力仍可从 Composer 的“能力与引用”或自然语言调用；对应待办身份、状态与来源在右栏待办详情和消息对象卡片呈现，不与标题和项目归属争夺空间。

## 主路径

1. 用户进入或重新进入 Chat，系统立即显示 Chat 页面壳和内存中最近一次会话、草稿与消息投影，同时在后台读取 fresh snapshot；导航不等待 IPC 返回。
2. 系统把自由会话按 Product Workspace 分组，每组默认展示 5 条；用户逐次查看更多，或点击项目标题收起、展开。
3. 用户选择“新建对话”，系统展示临时草稿、建议问题，并在中央顶栏右侧显示目标工作区入口，不立即创建持久空会话。目标工作区默认取当前会话所属的可用工作区；没有当前会话时取最近成功使用的可用工作区。没有可用工作区时，在 Chat 原位从当前账户全部可访问远端项目中选择目标并完成本地目录绑定，不按 owner、admin 或 member 角色过滤，草稿不丢失。
4. 用户核对目标工作区；目标不符合预期时，用户在第一条消息发送前打开向下展开的项目菜单并切换到另一个可用 Product Workspace。切换保留草稿文本，只改变预期 session owner、工作目录和权限边界；选中后菜单关闭，焦点回到项目入口。
5. 用户核对或通过 Composer 的“模型能力”入口调整 Model/Level，输入第一条非空消息并发送；系统创建 session，固定工作区与会话配置，立即显示用户消息，并在首个 turn 前持久化 Codex thread id。
6. Agent 正文和工具活动以稳定消息项流式更新。页面在用户处于底部时跟随新内容；用户上滚后保持阅读位置。
7. 用户继续发送消息时，系统在同一 session 和 thread 启动新 turn。用户可切换其他会话，活动会话继续更新并在列表显示状态。
8. 用户可停止当前生成；系统发出 interrupt，保留部分回答并标记“已中断”。用户随后发送“继续”或新的要求时启动同一 thread 的新 turn。
9. 用户从顶栏唯一的“会话操作”菜单重命名会话，或经确认删除会话。删除活动会话时系统先停止 turn，进入终态后再删除本地记录。

## 项目分组 Git 状态与就地详情

### 入口与归属

- 项目分组标题右侧提供独立 Git 摘要按钮，标题点击只展开／折叠会话，Git 按钮不改变折叠或当前会话。折叠后摘要仍显示。项目标题与 Git 摘要始终保持同一行；宽度不足时先压缩项目名称并以省略号截断，展开符、会话计数和 Git 状态组不换行、不被项目名称挤出。极窄宽度继续保持单行并裁切项目名称，不新增全局状态条。
- 摘要来自项目绑定的实际工作区，同一工作区下所有会话共享；不将修改归属于当前会话。详情持续显示项目名及工作区归属，点击其他项目的摘要不切换 Chat session、thread、中央文件 Tab、Composer 草稿或阅读位置。
- 用户选择采用右侧栏详情。打开时临时替代会话列表内容，保留侧栏顶部分页与调宽能力；提供“返回会话列表”。切换待办详情／文件或收起侧栏时入口可以不可见，不另增全局提示。
- 文件差异和提交内容在同一右栏逐层查看，提供返回上一级和返回会话列表；长行在查看器内部横向滚动，可调宽侧栏，不撑宽主页面，不新增模态窗口。

### 状态表达

摘要只显示紧凑的符号与数字组，不显示“本地干净”“N 个文件未提交”“待推送”等描述性短句。组间使用固定小间距，顺序为冲突、已暂存、未暂存修改、未跟踪、领先、落后；数量为 0 的普通组省略。完整语义通过悬停提示和可访问名称提供，不能只依赖颜色或要求用户记忆符号。

| 情况 | 可见摘要 | 数字口径与完整语义 |
|---|---|---|
| 冲突 | `! N` | `N` 为未解决冲突路径数；冲突组始终排在其他本地组之前 |
| 已暂存 | `+ N` | `N` 为 index 中有变化的路径数 |
| 未暂存修改 | `M N` | `N` 为 worktree 中有变化的路径数；同一路径同时存在 index 与 worktree 变化时分别进入 `+` 与 `M` |
| 未跟踪 | `? N` | `N` 为未跟踪路径数 |
| 待推送／待拉取 | `↑ N`／`↓ N` | 分别为相对可比较上游的领先与落后提交数，基于本地远端跟踪缓存；两者同时存在时并列，不额外显示“分歧”文字 |
| 零本地变更 | `✓ 0` | 表示冲突、已暂存、未暂存和未跟踪数量均为 0；不宣称实时远端已同步，仍可与 `↑`／`↓` 并列 |
| 未知／读取中 | `…` | 数量尚不可确认，不以 0 或 `✓` 代替；完整名称说明正在读取或尚无成功结果 |
| 过期 | `◷` + 上次可信数字组 | `◷` 表示数字不是当前成功结果；详情保留读取时间、原因和重试入口 |
| 本地读取失败 | `×` + 上次可信数字组 | 没有可信旧值时只显示 `×`；详情说明失败原因并提供重试 |
| Fetch 失败 | `⇅×` + 当前本地数字组 | 本地状态与远端获取失败分开表达，保留上次成功时间和缓存；不自动 Pull 或 Push |
| 无 Git 仓库／未绑定 | `⊘`／`◇` | 不伪造数字；悬停提示、可访问名称和详情分别说明原因，不自动建仓或修改绑定 |

无远端或无可比较上游时不显示 `↑ 0`／`↓ 0`，完整名称与详情分别说明未配置远端、未设置上游或上游为本地分支；存在远端时仍允许显式 Fetch。本地读取成功时间不冒充 Fetch 时间。

### 详情与恢复

- 概览按需展示当前分支、修改文件及暂存情况、双方提交数量、远端检查情况和时间；本地刷新与“获取远端更新”是两个不同动作。普通观察不会自动 Fetch。
- 文件按未暂存、已暂存、未跟踪、冲突说明；同一文件同时有已暂存及未暂存修改时两种差异分别可达。未跟踪文件可只读查看内容；冲突查看当前内容及冲突标记，本事项不提供编辑合并。
- 待推送／待拉取提交列表按需加载；列表有界分页，更多内容提供明确入口，不静默将截断结果当成全部。查看提交展示身份、说明与变更文件，再查看相对父提交的文件差异。
- 二进制、不支持的编码、过大差异或特殊对象提供真实不可预览说明，不显示空白并冒充无变化。差异／历史读取失败提供局部重试，保留概览和返回路径。
- 刷新不抢用户正在看的文件／提交、滚动或焦点；已选对象消失时说明状态已改变，允许返回概览，不自动转到其他对象。账号、项目绑定或真实根身份失效后旧详情禁止继续读取新根，明确失效并重新进入。
- 标题按钮、摘要、返回、文件和提交入口均可键盘操作，有可见焦点；打开后焦点进入详情，返回列表恢复对应摘要。Esc 返回会话列表，不停止 Agent；有更上层对话框时先由该对话框处理。窄窗沿用既有侧栏抽屉。

### 来源、原型与验证边界

状态语义来自待办 1358；右侧栏方案由用户本轮“按照你的推荐方案吧”明确采纳。层内只读导航、内部滚动、返回及错误恢复沿用 Chat 既有连续性与视觉规则。继续消费正式视觉 Tokens，不新增主题或提交工作台。

`default.html` 通过 `git-ui.js` / `git.css` 提供摘要、右栏概览、文件与提交差异的模拟主路径；`ChatGitPrototype.scenario(name)` 为独立场景控制接口。样本不证明真实 Git、权限、监听、分页性能或生产生命周期。验收证据见 `../../cases/evidence/CASE-20260930-002/git-adopted-prototype-final/result.json`；未覆盖的生产行为由实现验收承担。

生产接入已取得实际 Renderer 与真实临时 Git 仓库验证，见 `../../cases/evidence/CASE-20260930-002/git-ui-final-checks/report.md`。认证/会话使用隔离夹具，未打包安装或连接用户远端账号。

## 当前待办详情与 Work 入口

- Work 待办详情的“打开 Chat”建立或恢复该待办对应会话，进入 Chat 并显示右栏“待办详情”。重复打开恢复同一 session/thread；未绑定本地工作区时保留 Work 现场并提示先绑定。
- 右栏顶部“会话列表 / 待办详情”切换只改变侧栏内容；保持当前会话、Composer 草稿、消息阅读位置和运行中的回复。自由会话没有主待办时，详情说明尚未关联，不展示上一个会话的待办。
- 待办详情与 Work 共用内容及操作：身份与状态、引导及允许操作、完整 Markdown 内容、属性、协作、评论、附件和适用的验收反馈。编辑权限、版本冲突、业务状态及 Automation 授权边界一致。
- 会话切换后详情跟随新会话主待办，不能使用 Work 列表的选中项推断。加载时说明正在读取；对象失权、删除或同步失败提供真实提示及重试，不继续显示其他待办。
- Agent 使用原生 read/update 读取最新版本后修改；成功写回由 Work 同步刷新两处详情。未发送的评论及 Composer 文本在同步和切换侧栏时保持，迟到请求不覆盖新对象。
- 窄窗侧栏沿用可关闭抽屉，详情内容内部滚动、操作换行；切换按钮支持键盘和可访问名称，Esc 关闭抽屉并恢复焦点。

## 项目文件与中央 Tab

### 文件归属与完整目录

- 右栏提供“会话列表 / 待办详情 / 文件”，沿用右栏尺寸与窄窗抽屉。文件归属取当前会话固定工作区；临时新对话取已选择的目标工作区，不从全局查看范围猜测目录。
- 文件面板持续显示工作区名称。未选择、目录失效、权限拒绝和读取失败分别给出真实说明与重试，不能展示上一项目内容冒充当前内容。
- 文件树按层展开，文件夹优先、同类按名称排序，展示所有目录项，包括点文件、`.git`、`.env`、`node_modules`、被忽略文件及符号链接。读取权限不足的节点仍保留错误反馈；完整展示不意味着所有条目都能作为文本编辑。
- 每层可分批加载并明确显示“加载更多”，最终全部可达，不静默截断。刷新保留仍有效的展开、选择和滚动，不读取全部文件正文，不递归预扫描整个项目。
- 符号链接有可读标记；本版不展开链接目录或通过链接读写内容。点击说明链接目标及限制，避免循环和项目外访问；复制路径和在系统中显示仍针对链接本身。

### 实时新鲜度与加载反馈

- 展开和收起首先是本地树状态切换，点击或键盘操作后立即改变 `aria-expanded`、disclosure 方向和子级可见性。已取得的目录结果直接复用；普通展开、收起和重新展开不显示“正在读取”，也不以整棵树的 loading 行替换现有内容。
- 第一次展开尚无可用结果的目录时，树仍保留现有行、选择、焦点和滚动。只有读取持续到需要反馈时，才在该目录子级范围给出非阻塞进度；读取成功后原位填充，读取失败后在该目录原位说明并重试。后台刷新不得重复闪现文字 loading。
- 当前工作区的文件树是持续更新的本地投影，不以打开面板、窗口 focus 或手动刷新作为正常新鲜度前提。用户在系统文件管理器、终端或其他编辑器中创建、删除、重命名文件后，受影响的已展开分支主动更新；从其他侧栏模式回到“文件”时直接看到最新已知结果。应用从隐藏或暂停观察恢复时先核对变化，再继续增量更新。
- 外部变化保留仍存在的展开项、选择、焦点和滚动，不抢占中央 Chat／文件 Tab。选中项被删除时清除失效选择并把键盘焦点留在最近仍存在的父级或相邻项；已打开文件的草稿和外部修改／删除保护继续按编辑规则处理，不因树刷新丢失。
- 根目录“刷新”是异常恢复和用户显式核对入口，不是日常同步机制。监听不可用、事件遗漏或读取失败时保留最后一次可信目录，不清空树；在文件面板就地标明结果可能过期并提供刷新。没有可信结果时才显示有界初始空态，不以旧项目目录冒充当前工作区。

### 文件与祖先目录 Git 状态

- 文件树复用项目分组已经观察到的实际工作区 Git 状态；同一工作区只维护一份状态来源。状态变化独立更新可见行，不切换会话、Tab、选择、焦点或滚动，也不得把迟到结果应用到其他账号、项目绑定或真实根目录。
- 有变化的文件在名称后、行尾更多操作前显示紧凑 Git 标记，并通过完整提示和可访问名称说明含义。路径级标记使用 `!`（冲突）、`?`（未跟踪）、`A`（新增）、`M`（修改）、`D`（删除）、`R`（重命名）和必要的两段组合表达 index／worktree 同时变化；颜色只能辅助，不能作为唯一信息。干净和被忽略的文件不显示标记。
- 任何可见目录只要包含发生变化的后代，就显示祖先聚合标记；聚合优先级为冲突 `!`、已跟踪变化 `M`、仅未跟踪 `?`，完整提示和可访问名称给出后代变更类别与路径数量。聚合覆盖从变更文件父目录到工作区根的全部现存祖先，使收起目录也能提示内部变化，但不把目录自身误报为 Git 路径变更。
- 重命名后的新路径显示 `R`，旧路径从文件树移除；已删除的 tracked 路径不伪造可打开的幽灵文件行，其最近仍存在的祖先保留含删除的聚合提示，完整删除项仍可从既有 Git 详情到达。仓库外路径、非 Git 工作区或尚无可信 Git 结果不伪造“干净”标记。
- Git 读取中不遮挡目录浏览。结果过期或刷新失败时保留最后一次可信标记，并在文件面板级别附加过期／失败语义与重试；完全没有可信结果时暂不显示路径标记。文件树变化和 Git 状态可以分批到达，但每次渲染只消费当前工作区身份下的完整结果，不短暂把旧路径状态贴到新项目。

### 常见操作与引用

- 工作区名称与单一“项目根目录更多操作”入口同排；原刷新、新建文件和新建文件夹按钮不再平铺。根目录菜单按顺序提供“刷新 / 新建文件 / 新建文件夹 / 在系统中显示”；固定作用于当前工作区根，不被文件树当前选择改写。
- 项目根目录与普通条目共用同一更多菜单容器、菜单项样式、键盘导航、外部点击关闭和 Esc 焦点恢复语义，再根据目标类型取舍能力。行尾更多菜单与右键菜单保持相同操作：文件打开、目录展开/收起、新建文件/文件夹、重命名、删除、复制相对路径、在系统中显示、添加相对路径引用到 Chat。根目录没有可用的工作区内相对路径，也不作为可重命名或删除的子项，因此不显示打开/展开、重命名、删除、复制路径或添加引用。
- 名称输入只接受一个有效文件名，不接受空名称、`.`、`..`、路径分隔符或 NUL。已存在目标不覆盖，失败保留输入。新文件为空文本，创建成功后打开对应 Tab；新目录成功后展开父目录并定位新项。
- 重命名保持同一父目录，目录重命名同步更新其已打开后代文件的路径与标题，保留草稿和编辑位置。所选目录项消失时先刷新，不在旧目标上盲目重放。
- 删除使用确认对话框，明确相对路径及目录包含的内容；确认后移入系统废纸篓。失败保留原项并可重试，不降级为永久删除。删除涉及未保存文件时先取消、保存后继续或明确放弃；取消任何一步不删除。成功后关闭受影响 Tab，未受影响文件和 Chat 保持。
- “添加相对路径引用到 Chat”将相对于当前工作区的路径按纯文本插入当前 Composer 光标位置，补必要间隔，保留其他正文并切回 Chat、聚焦输入框；目录引用使用末尾 `/`。不会发送消息、读取正文或启动 Agent。路径包含空格、引号或反引号时原样作为输入文本保留，不解释为 HTML 或命令。
- 引用动作核对项目仍为当前项目；菜单打开后项目变化则取消旧动作并提示。写入使用现有 Chat 草稿保存通道。复制操作反馈成功/失败；菜单可用键盘打开并通过 Esc 关闭、恢复行焦点。

### 编辑、保存与关闭

- 打开首个文件后中央显示不可关闭的“Chat”Tab 与文件 Tab；点击文件激活对应 Tab，同一工作区相同路径不重复打开。文件 Tab 显示文件名、未保存标记和独立的 x 关闭按钮，完整相对路径可读取；同名文件用父路径区分。
- 中央编辑区提供路径、保存、重新读取及状态。文本采用 Monaco，支持语法着色、行号、查找、撤销/重做和 Cmd/Ctrl+S；保持现有明暗主题。编辑区内部滚动，Tab 溢出时横向滚动，不扩大页面。
- UTF-8 文本不超过 2 MiB 时允许编辑；二进制、无效编码、大文件及特殊节点显示不可编辑说明，并提供在系统中显示。文件仍留在树中；不截断正文后允许保存，不将文件内容当 HTML 执行。
- 保存是显式动作，保存中防重；成功清除本次已保存内容的未保存状态，保存期间的新输入仍保持未保存。权限、磁盘或路径失败保留草稿与错误信息。
- 保存前发现磁盘版本不同，保留编辑草稿并显示冲突；用户可查看当前磁盘内容、复制草稿，或确认放弃本地修改并重新读取。普通保存不提供静默覆盖。外部删除不自动重建文件。
- 关闭干净 Tab 立即关闭；关闭脏 Tab 提供“保存并关闭 / 放弃修改 / 取消”。保存失败时保持 Tab 和草稿。关闭活动 Tab 后激活相邻 Tab，最后一个文件关闭后回到原 Chat 布局；关闭非活动 Tab 不改变当前选择。
- 切换中央 Tab、侧栏、会话或应用内页面不停止回复；Chat 草稿、阅读位置和文件草稿、撤销历史、光标独立保留。文件会话按账号、本地工作区身份与真实根目录隔离，同项目会话共享打开文件；切到其他项目显示该项目的文件会话，不把旧项目文件带入新项目。
- 文件草稿在当前窗口存活期间保留。重载、退出或账号切换有脏文件时需要明确的保存/放弃/取消处理；不承诺崩溃后或跨设备恢复文件草稿。工作区重绑定使旧文件会话失效且禁止向新根保存，先允许复制或放弃旧草稿，再建立新会话。

### 可访问性、视觉与验收

- 目录树支持可见焦点、方向键移动/展开/收起、Enter 打开及键盘更多菜单；文件或目录已选中且焦点位于对应树条目时，Esc 清除选择但保留该条目的键盘焦点。菜单或确认框打开时由上层先处理 Esc，Composer 和中央编辑器中的 Esc 不清除文件树选择。选中和未保存状态不只依赖颜色。Tab 提供可访问名称、选中态、方向键切换，关闭按钮名称包含文件名。
- 复用现有中性表面、边框、文字及强调色 Tokens，文件树采用 28px 专用紧凑单行高度，名称操作占满剩余行宽，行尾更多操作保持同高方形目标。可展开目录使用与名称分离的 16px 轮廓 disclosure：收起向右、展开向下；状态同时保留 `aria-expanded`，不能只依赖颜色或把三角符号混入名称文本。项目根目录入口与行尾更多入口使用同类图形、状态和焦点表达。窄窗在选择文件后关闭抽屉并聚焦中央文件，菜单和确认框保持视口内可达。
- 验收覆盖项目根目录菜单的选项取舍、创建目标与 Esc 焦点恢复，文件和目录选择的 Esc 清除及菜单、Composer、中央编辑器优先级，28px 条目高度及同屏展开/收起 disclosure 差异；展开、收起及重新展开不出现“正在读取”，外部创建、删除、重命名在已展开分支主动反映且不依赖回切/focus/手动刷新；文件标记、全部现存祖先聚合、组合状态、冲突／未跟踪／重命名／删除、干净／忽略／非仓库及 stale/error 恢复语义；以及隐藏项、超过单批数量的目录、同名文件、右键及键盘引用、新建/重命名/废纸篓、保存失败/冲突、脏 Tab 关闭、项目和账号切换、迟到响应、Chat 运行与草稿连续性、明暗主题与窄窗。

- `default.html` 已同步文件树与文件 Tab 的可操作样本；`files-model.js` 使用内存目录与模拟 Git 投影，`files-ui.js` 使用 textarea 模拟编辑器。实时目录与路径 Git 标记的样本验证见 `../../cases/evidence/CASE-20261010-002/file-tree-live-expectations/verification.json`；项目根目录菜单的验证见 `../../cases/evidence/CASE-20261009-001/root-menu-prototype-v3/verification.json` 和 `../../cases/evidence/CASE-20261009-001/root-menu-production-v3/result.json`；Esc 取消文件/目录选择及键盘优先级的最新验证见 `../../cases/evidence/CASE-20261009-001/escape-selection-prototype-v2/verification.json` 和 `../../cases/evidence/CASE-20261009-001/escape-selection-production-v2/result.json`；28px 条目与 16px 展开/收起 disclosure 的最新原型和生产证据见 `../../cases/evidence/CASE-20261009-001/file-tree-visual-prototype-v2/verification.json`、`../../cases/evidence/CASE-20261009-001/file-tree-visual-prototype-v2/file-tree-density.png`、`../../cases/evidence/CASE-20261009-001/file-tree-visual-production-v4/result.json` 和 `../../cases/evidence/CASE-20261009-001/file-tree-visual-production-v4/file-tree-density.png`。原型只证明用户可见规则与本地样本连续性，不证明真实 watcher、Git、Monaco、文件 IPC、系统废纸篓、工作区重绑定和账户/退出保护；这些机制由生产夹具另行覆盖。

## 会话列表与新建（详细规则）

- 会话按统一顶部产品范围过滤、按所属 Product Workspace 分组；项目保持稳定 id 顺序，不因会话活动、选中或项目名称变化重排。
- 组内会话保持创建时间倒序，同时间使用稳定 session id，新会话位于组内最上方。活动、选中、重命名和刷新不改变既有相对位置。
- 项目默认显示前 5 条；有剩余时显示“查看更多（剩余 N 个）”，每次增加 5 条，全部显示后隐藏入口。项目状态独立，收起时重置显示数量。
- 选中或活跃会话不强制展开项目、不自动增加显示数量；收起项目不改变当前对话、草稿和运行中的 turn。
- 只有拥有可见 Chat session（自由或待办会话）的项目出现在会话分组列表中；没有历史的可用工作区仍可从新对话的目标工作区选择器进入。工作区暂不可用时，已有会话组保留可读并标记不可用，但不允许在该工作区新建或继续发送。
- “新建对话”建立一个临时草稿视图。用户未发送消息就返回其他会话时，不生成空历史记录。
- 新对话始终在中间标题区和 Composer 边界摘要中显示“会话属于：{Product Workspace}”。该控件在首条消息发送前可操作，并列出所有已绑定本地目录且 Setup Readiness 可用的工作区。
- 新对话默认使用当前会话所属的可用工作区；没有当前会话时使用最近成功创建 Chat session 的可用工作区；只有一个可用工作区时直接选中，但仍显示归属。没有有效默认值时保持未选择并禁用发送。
- 用户切换临时草稿的工作区时保留已输入文本，不创建 session 或 thread。首条消息被接受后工作区固定，既有会话只显示不可编辑的归属；改变项目必须新建会话。
- 第一条消息成功进入本地队列后，临时草稿成为持久 session；标题取第一条用户消息的有界摘要。
- 标题支持就地重命名。空白标题不保存，取消编辑恢复原值。
- 会话列表包含自由会话与在 Chat 中建立或恢复的待办会话。关联待办不生成平行 thread。Automation 的运行控制和验收问题保持各自业务边界；进入已有任务上下文必须复用可信 thread 绑定与持有者规则。旧的无归属默认 session 不进入列表。

## 消息与内容体验

- 用户消息提交后立即显示；同一提交使用客户端幂等键，双击发送或 IPC 重试不会产生两条消息或两个 turn。
- Agent 正文按稳定 `thread_id + turn_id + item_id` 更新同一消息。生成中显示状态，完成后移除运行指示。
- Markdown 正文支持标题、段落、列表、引用、链接、表格和代码块；代码块提供复制，不自动执行。JSON、代码与表格查看器不超过消息可用宽度，超长单行和超高内容分别在查看器内部横向、纵向滚动。
- reasoning 只有在 Codex 提供非空 summary 时出现，生成中可展开，完成后默认折叠；界面不伪造内部思考。
- 工具活动按 item 原位显示开始、运行、完成、失败和有界目标。完整命令输出、文件正文、raw JSON-RPC 和协议 payload 只进入诊断证据，不进入普通消息正文。
- 文件变更活动直接显示“更新 {具体文件路径}”，多个文件按事件顺序去重，以“、”分隔；超过三个文件时展示前三个路径并标明文件总数。每个长路径保留首尾，以中间省略号控制在 120 个字符内，便于识别文件名。路径按纯文本显示，控制字符转为空格；无可用路径时保留同一活动已知的目标，否则显示“更新项目文件”。完成事件补充或更新路径时在同一消息原位反映，已保存的目标在重新打开会话后保持；缺少路径数据的历史消息保留原提示，不推测文件名。
- 权限请求显示操作、目标、工作区和影响范围，并提供允许或拒绝。处理前对应 turn 保持等待；拒绝结果作为工具状态回到 transcript。
- 已中断回答保留可见正文和“已中断”标记。系统不把 interrupt 描述为可恢复同一 turn；后续输入是同一 thread 的新 turn。
- turn 失败保留用户消息、部分 Agent 输出和具体错误。可恢复错误显示“重试”与“编辑后发送”；不可恢复的 thread 丢失显示已建立替代 thread 的恢复记录。

## Composer

- Composer 支持多行文本和输入法组合；`Enter` 发送，`Shift+Enter` 换行。输入法正在组合时按 Enter 不提交。
- 输入框操作行将 Model 和 Level 合并为“模型能力”入口，摘要显示当前推理级别，完整模型与级别可从入口提示或弹出菜单查看。菜单提供“模型”和“推理级别”两个选择控件，不提供输入过滤。新对话继承 Chat 默认配置，既有会话恢复保存值。Model 清单来自 Codex；Level 随模型提供的能力更新，切换后旧 Level 不支持时选择 medium（若可用）或首项。清单获取失败保留已有配置与发送能力，不制造可选能力。
- 模型能力菜单紧贴自身入口向上弹出，左边缘对齐入口；视口右侧空间不足时向左避让，窗口尺寸变化后继续贴合入口。能力与引用菜单遵循相同规则，以其自身按钮为锚点（包括 `/` 调起）；能力与引用菜单在可用空间内展开至 640px，搜索区和底部技能设置保持可见，仅候选列表滚动；不得把候选区压缩到只剩少量入口。菜单限制在视口内。打开时焦点进入配置，完成或 Esc 关闭并返回入口，原消息草稿和阅读位置保持。调整立即保存，无需另一次提交；打开或关闭不发送消息。
- 发送/停止按钮始终位于输入框操作行右侧；能力入口和模型入口在左侧，窄窗口保持对齐。
- 调整 Model/Level 原位保存到当前会话或临时新会话草稿，不改写账号设置中的 Chat 默认值，不改变 Automation 默认值，也不创建新 thread。切换会话时每个会话恢复自己的选择。
- 发送被本地接受时同时固定该 turn 的 Model/Level。活动 turn 期间仍可调整控件，修改只作用于下一次发送；停止、重试和继续都保持同一 session/thread 语义。
- 无文本且无能力时不可发送。有显式能力时可以发送；缺少目标内容由 Agent 在对话中询问。发送后保留焦点，只清除已接受的文本和本条能力标签；提交失败保持完整草稿。
- turn 活动时主按钮变为“停止”，调用当前 turn 的 interrupt。Composer 仍可编辑草稿，但在当前 turn 进入 completed、interrupted 或 failed 前不启动同一会话的第二个 turn。
- 当前 turn 完成后，已有草稿保持不变，用户显式发送才进入下一 turn。
- 页面切换、窗口失焦和会话切换都不自动提交、清空或中断 Composer。

## 待办与会话身份

Chat 右侧支持会话列表与当前会话待办详情切换，不提供独立待办浏览列表或待办筛选控件。会话按工作区分组、组内按会话创建时间倒序；关联待办的会话仍按同一会话规则展示。待办浏览与筛选由 Work 页面承担，Chat 保留原生待办能力、会话关联和业务回执卡片。

会话列表仅展示会话标题和运行状态图标，不展示待办关联文字；关联身份保留在右栏待办详情与对象卡片。来源会话只表示创建来源，不证明待办已有关联会话。关联不改写原会话标题、创建时间或排序；修改待办内容不改写会话标题。

- 整段整理：用户从 Composer 的“能力与引用”选择“整理为待办”并发送，或发出同义请求，Agent 基于当前讨论提炼目标、约束与描述，调用原生能力创建待办。成功后当前会话成为该待办的持续对话，保持同一 thread、历史及阅读位置；已发送的 Composer 正文按普通消息处理，之后的新草稿继续按会话规则保留。再次请求整理时定位已有对应关系，不创建重复身份。
- 其他待办：用户在当前讨论内让 Agent 记录另一件事，或选择“创建待办”能力后发送内容。待办属于当前项目，保存创建来源；不替换当前主待办、不自动成为子任务、不因创建而开新会话。
- 主动打开其他待办：点击对话内待办卡片，优先恢复该待办已有 thread；无对话时建立其对应 Chat，并由 Agent 读取目标。创建来源不等于持续会话，标题提供“创建于：{来源会话}”返回入口。
- 已有待办：从会话列表或对话内待办卡片进入同一对应对象，读取相同历史与执行现场。自然语言提及其他待办不自动切换主待办或 thread。
- 主待办身份不进入紧凑顶栏；右栏待办详情与对象卡片显示“本会话对应待办”、编号、业务状态及创建来源，列表不重复关联提示。结果卡片区分“对应当前会话”和“从本会话创建”。
- 删除本地会话不删除待办。任务拥有的可信 thread 绑定不因删除本地列表投影而失效；再次进入由恢复契约决定如何恢复，不能静默复制新的执行现场。来源会话被删除时保留来源不可访问提示。

## 统一能力与引用

Composer 的“＋ 能力与引用”打开输入框附近的选择器。可选项只包含原生业务能力与已发现 Skill；选择器不再提供项目文件或待办引用候选。按钮名称、技能设置入口、文件工作区、待办创建/读写和会话关联保持不变。

输入独立 `/` 打开能力候选；`@` 不再触发文件或待办选择器，作为普通输入保留。普通句子中的 `/` 不触发。输入法组合期间不打开或发送。选择器支持搜索、空结果、方向键导航和 Enter 选择；关闭或 Esc 恢复触发焦点。选择器为窗口内模态浮层，打开时背景不可操作；高度与宽度限制在视口内，候选独立滚动。

选择能力只添加到草稿。每条消息至多一个显式能力；换能力替换本条选择，不改工程技能配置。标签可移除，正文保留。选择后回到输入框，用户补充内容并发送，Agent 才开始调用。直接自然语言请求同样有效。

能力选择随当前会话或新会话草稿保存，切换对象和刷新后恢复。首条消息前更换工作区保留正文和通用能力意图。发送时固定本条能力与 Model/Level；活动 turn 期间的编辑只作用于下一条草稿。历史已发送消息中的旧文件/待办引用标签继续只读呈现，底层兼容可保留，但选择器不得据此恢复新建入口。

已发送用户消息保留本条能力标签；历史旧引用标签也继续呈现，不等于当前仍可新建引用。只有工具回执表明调用或历史引用的读取结果。只发送“创建待办”能力且没有任务内容时，Agent 通过正常对话询问，不弹出创建表单。

“能力与引用”弹出菜单底部的“技能设置”管理 Engineering 配置，当前页选择 Skill 不自动安装、启用隐藏能力或变更全局设置。未安装、不可用或无权访问的能力不以可执行候选呈现；执行中失效按工具错误恢复。

## 原生读写与消息结果

待办为可持续读写的业务对象。打开或重新读取时，Agent 获得最新目标、状态和版本；用户要求修改时，Agent 按权限和版本约束写回，确认成功后更新关联身份和结果卡片。消息文字不替代业务回执。

Agent 正文、工具活动、原生业务审批和结构化对象卡片各自表达不同信息。待办卡片基于真实对象回执构建，支持定位对应会话；普通正文不自动转化为可执行按钮。Agent 提议其他事项时通过自然语言沟通，用户回复形成下一次意图，不在回复底部生成预设“补充标准 / 继续执行”按钮。

用户明确要求执行时，Agent 沿当前 thread 读取目标、检查实现并执行授权范围内的工作。创建或选择待办不自动启动 Automation；Agent 声明、工具成功、业务完成和用户验收保持不同语义。活动执行的所有权不得由新的 Chat 入口抢占。

| 状态 | 页面反馈 | 恢复与连续性 |
|---|---|---|
| 创建/更新中 | 当前消息显示有界工具活动，停止仍可用 | 不提前添加成功卡片，不清除下一条草稿 |
| 写入失败 | 同一对话保留请求和错误，关联身份及卡片保留可信事实 | 用户回复重试或更正要求；不得因重试重复创建 |
| 版本冲突 | 显示版本已变化、本次未覆盖 | 读取最新内容，核对后再次提出修改 |
| 执行占用 | 显示实际持有/等待原因 | 可读取和讨论授权范围，写入/执行不越过持有者约束 |
| 无权访问/对象消失 | 保留历史，明确对象不可用 | 恢复访问后重读；不自动创建替代任务 |
| 离线/提交拒绝 | 保留文本、能力、引用及对象选择 | 恢复后由用户重新发送 |
| 停止/中断 | 保留工具已确认结果与部分消息 | 不自动重放；停止不撤销已经提交的业务写入 |
| 部分成功/结果未知 | 展示已确认待办身份与待恢复步骤 | 先查询已有结果，按同一对象恢复关联；不重新创建 |

## 原型覆盖与能力依据

完整入口组合现有 Chat 会话、Markdown、工具/权限、账户、尺寸、滚动与新原生待办路径。原型覆盖整体整理、对话内新建、已有待办、能力/Skill 标签、文件/待办候选缺席、自然语言澄清、读写回执、停止、失败重试、冲突、占用、失权与恢复。

原生能力机制参考 Thing 的受控能力发现、调用与 Chat coordinator，但本地原型不共享 Thing 样本数据库。生产应共享可信待办/thread 归属，不从两个页面各创建一套执行现场。文件、Skill 和业务工具实际接入、跨设备恢复、部分成功幂等与读写权限由生产验证，原型没有证明这些协议。

新增上下文标签、会话列表、回执卡片和选择器消费正式视觉 Tokens、按钮/表面/对话通用规则；颜色、字体与主题源仍位于 visual，不维护独立主题。组件目录的细化登记列入维护结果的视觉交接，不影响这里完整的正式交互表达。

## 状态模型

### 初始与空状态

- 有可用工作区且无历史时显示新对话草稿、目标工作区选择、能力边界和建议问题。
- 没有可用本地 Product Workspace 时禁用发送，解释需要本地目录与 Setup Readiness，并直接提供“选择项目并绑定本地目录”。动作打开上下文 Sheet，先选远端项目，再复用 Product Workspace 目录绑定与 Setup Readiness 检查；成功后留在 Chat、恢复草稿并选中新工作区。
- `workspace-setup.html` 投影该上下文 Sheet 的项目选择、目录绑定、环境检查和失败保留；它不是独立设置导航。
- 首次没有可显示投影时，会话列表和 transcript 保持 Chat 页面骨架；已有投影时后台同步状态出现在页面内且不遮挡阅读或 Composer。
- 后台同步成功后按 owner freshness 规则更新列表与 transcript；失败时保留当前投影、显示就地重试，不回退到旧页面，也不创建默认假会话。

### 运行状态

- `starting`：本地用户消息已接受，正在初始化 app-server、恢复或创建 thread。
- `running`：turn 已开始，Agent 或工具事件持续更新。
- `waiting_approval`：Codex 请求用户批准，Composer 草稿可编辑，停止仍可用。
- `interrupting`：停止请求已发出，主按钮禁用并显示“正在停止”，直到 turn 终态。
- `completed`：turn 正常结束，可以发送下一条消息。
- `interrupted`：部分输出已保存，可以在同一 thread 开始新 turn。
- `failed`：显示错误、保留输入与上下文，并按可恢复性提供动作。

### 后台与重启恢复

- 用户切换到另一会话时，原会话继续接收事件；列表使用状态标记区分运行、等待批准和失败。
- 应用关闭时 main process 对活动 Chat turns 发出 interrupt，并尽力持久化到最后一个语义消息边界。
- 重启后 session、消息、草稿和 thread 绑定恢复。之前未形成终态的 turn 显示“应用退出时中断”，不会自动重启或重复用户请求。
- 下一条消息先 resume 持久 thread；瞬时 resume 失败保留绑定和恢复入口，只有 Codex 明确确认 thread 不存在时才创建替代 thread。

## 删除确认

- 删除入口打开 ConfirmationDialog，展示会话标题、工作区、消息数量和当前运行状态。
- 非活动自由会话确认后只删除该 session 的本地消息、草稿、运行引用和会话 thread 绑定，不影响同项目其他 Chat 或 Automation 数据。待办会话删除只移除本地会话投影与引用，保留待办拥有的可信 thread 身份及业务对象。
- 活动会话确认后先进入 `interrupting`；interrupt 成功或 turn 已终结后执行删除。停止失败时保留会话并显示恢复错误，不执行部分删除。
- 确认文案明确说明本操作不承诺擦除 Codex 自身可能保留的底层 thread 数据。

## 滚动、选择与反馈

- 用户在 transcript 底部阈值内时，新消息和 delta 自动保持最新内容可见。
- 用户主动上滚时，更新不改变当前阅读位置，并显示“回到最新”及未读消息数。
- 切换会话前保存当前草稿、跟随状态和滚动锚点；返回时恢复该 session 自己的状态。首次进入一个会话时默认显示最新内容。
- 后台会话的 delta、终态刷新和已排队自动滚动只更新其所属 session；切换到其他会话后不得改变当前 transcript 的滚动位置、跟随状态或“回到最新”反馈。
- Chat 页面、中间对话区、transcript 和消息的横向边界只由各自父容器决定；JSON、代码和表格查看器内部滚动不产生页面级横向滚动。
- 复制、重试、权限决定、重命名和删除均提供就地成功或失败反馈，不使用全局静默失败。重命名或删除打开后，“会话操作”菜单关闭；取消后焦点回到统一入口。

## 键盘与可访问性

- 项目组、历史会话展开/收起、目标工作区选择、会话列表、更多菜单、权限请求、停止、重试和删除确认均可通过键盘访问，并有可见焦点。顶栏项目入口通过 Enter/Space 打开，方向键、Home/End 在单选项间移动，Enter/Space 选择；Esc 或外部点击关闭，Esc 关闭后焦点回到项目入口。顶栏“会话操作”沿用同一关闭与焦点恢复规则，方向键在“重命名 / 删除会话”间移动；两个菜单互斥。
- 发送与停止按钮拥有随状态变化的可访问名称；运行、等待批准、中断和失败状态通过文字与辅助技术通知，不只依赖图标或颜色。
- 流式 delta 不逐字符触发播报；Agent 消息完成、权限请求和错误形成有界通知。
- `Esc` 只关闭当前菜单或弹窗，不停止 turn；停止必须由明确按钮或其快捷操作触发。

## 边界

- Chat 产品层直接使用 Codex 对话能力，不自动启动 state-driven Runtime、`$using-arckit`、trusted ledger 或 Automation Coordinator；用户显式调用 Skill 的授权边界按场景技能规则保持。
- Chat 内 Agent 可通过可用、受控的原生能力创建和更新当前项目待办；不因自然语言声明而直接改变业务事实。此能力不自动授权 Project、Feedback、Idea、Project State、Case 或 acceptance feedback 写入。
- Product Workspace 决定 `cwd`、workspace root、skill discovery 与 sandbox 边界；Renderer 不获得文件系统、Codex 凭据或通用 RPC 能力。
- Chat 的停止不释放 Automation human Gate，不改变远端任务状态，也不抢占 Automation task thread lease。
- Composer 的“能力与引用”选择器不提供项目文件或待办上下文引用；文件工作区、待办业务能力和历史旧引用呈现不受此菜单调整影响。语音、共享链接、跨设备同步、会话分支和模型目录管理不在本页范围；Model/Level 仍只控制当前会话，不承担全局默认值管理。

## 场景技能入口

“能力与引用”弹出菜单底部的“技能设置”进入 Engineering 的 Chat 配置，输入框不单列该链接；“能力与引用”中的 Skill 选择只影响本条请求，两者职责不同。默认关闭内置 Automation 技能，可开启普通技能或官方 Loop 核心配套。返回后保留当前会话、工作区与草稿；保存从下一条消息生效。关闭技能不清除已有历史，需要全新上下文时新建会话。用户主动让 Agent 依据 skill 推进 Loop 时，Agent 可执行对应项目操作；Chat 产品层不自动创建 Automation Run 或调度租约。

## 原型布局与视觉

中央消息与 Composer 填满剩余宽度，桌面两侧保留 24px 边距；窄窗使用 12–16px 边距。中央顶栏在桌面和窄窗均固定为 64px，不因 1100px 或 760px 断点改为纵向堆叠；左侧标题只占一行并优先省略，完整内容通过悬停提示读取。右侧项目入口在桌面不超过 220px、窄窗不超过可用宽度约三分之一，名称省略后仍保留图标；32px 会话操作入口始终可达，两个入口不换列。项目菜单和会话菜单都在各自入口下方展开并保持在视口内。右侧独立滚动，拖动左边界调整宽度（220–560px，并给对话保留空间）；输入框顶部支持上下拖动调整高度（66–420px，受可用高度约束）。尺寸本机保存，窗口变窄时限制尺寸而不丢草稿。分隔线支持键盘方向键调整。760px 及以下会话列表使用抽屉，选择后关闭，Esc 关闭并恢复焦点；抽屉不提供横向调宽。

使用 visual/_library/generated-tokens.css、brief.md、components/conversation.yaml 和 light 主题的既有浅色与浅杏橙角色。states.html 仅为历史辅助状态说明，default.html 是唯一完整主入口。模型、渲染、输入选择器和原生能力模拟按职责拆分。

原型仅操作隔离本地样本；正文、工具过程、待办回执、文件内容和 Skill 加载都是模拟。场景工具提供离线、提交失败、权限、工作区缺失、长消息、清单不可用、原生写入失败、版本冲突、占用、失权及恢复入口，不在产品区域添加演示控件。实际原型验证见 verification.json 与 verification-native.json。生产 Codex、业务权限、幂等、跨进程 thread 绑定、目录读取和后台同步需要独立实现验证；已有生产布局证据不能证明本页新增能力已实现。

## 待办 Chat 与 Auto 连续协作

同一待办共享会话与消息浏览组件。Work/Thing 的“查看对话”打开 Chat；Auto 执行与历史记录入口打开自身三栏 Intervention Workbench，中间读取同一会话，左右保留执行与证据上下文；新打开的空待办会话保持空白，不发送读取提示。留言“交给 Agent”将文字带入该会话草稿，提交仍由用户触发。

| 执行状态 | 输入与控制 | 可见反馈 |
|---|---|---|
| 人工讨论 | 普通发送、停止当前回答 | 普通 Chat 消息和权限请求 |
| Auto 执行中 | 补充信息、暂停并接管 | 同一历史中的 Auto 正文与折叠执行进展 |
| 回合切换中 | 补充信息暂存 | 等待送达，下一可接收回合再投递 |
| Auto 暂停 | 普通发送、继续 Auto | 讨论不恢复自动推进，恢复是明确操作 |
| 补充发送异常 | 保留原消息和错误 | 失败或送达未确认；不自动重复提交 |

送达标签随原用户消息原位更新，不另造一条消息；“已送达”仅确认接收。页面切换、刷新及重启继续显示人工和 Auto 历史。旧 Run 记录保留出处并去重；工具输出与结构化进展按既有折叠组件展示，不展开原始协议日志。账号、工作区及任务身份改变时不得混入其他会话数据。沿用现有间距、边框、颜色和窄窗抽屉，不建立新视觉主题。

原型 `task-conversation.js` 提供执行、补充送达、未知送达、暂停及恢复场景；仅模拟本地状态。生产 Electron 夹具验证真实 Renderer 的入口和控制，Runtime/进程与持久化由行为测试分别验证，原型不作为真实 Auto 成功证据。验证记录见 `../../cases/evidence/CASE-20260930-001/verification/report.md`。
