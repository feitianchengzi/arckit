# Chat Workspace - 交互规范

## 交互策略

Chat 承接尚未确定正式形态的自由 Agent 对话。用户可以直接提问，选择是否携带当前产品范围，并在结论明确后显式选择转为 Idea 或 Work。页面始终区分自由讨论、Agent 建议和用户已确认结论。

Chat 不复用 Automation 当前待办的持久 thread，不自动创建 Project、Task、Case 或 ledger fact。当前计划展示页中的转换动作只说明目标形态，不产生真实写入。

## 页面结构

- 左侧显示最近对话和“新对话”入口。
- 中间显示用户问题、Agent 正文、相关项目事实和建议的下一形态。
- 底部 Composer 接受自由文本，并显示当前可选产品上下文。
- 右侧显示“形成后续事项”摘要，提供转为 Idea、创建 Work 和继续讨论三种计划动作。

## 主路径

1. 用户进入 Chat 或新建对话。
2. 用户选择无产品上下文、项目集全部或单个产品，并提出问题。
3. Agent 给出回答、依据和仍未确认的假设。
4. 用户继续讨论，或确认结论并选择目标形态。
5. 页面展示将被带入目标形态的标题、摘要和来源；当前阶段不提交真实转换。

## 状态与反馈

- 初始状态提供基于当前 ArcOrbit 工作的建议问题。
- 对话进行中保留 Composer 和产品上下文，不把建议标为正式决定。
- 形成后续事项时显示来源对话、目标形态和待确认内容。
- 无可用产品时仍允许自由问答，但创建 Work 的计划动作显示需要先选择正式项目。

## 边界

- Automation Workbench 继续承接待办执行、人工介入和恢复对话。
- Chat 的历史、转换和上下文目前均为团队对齐示意。
- Chat 不修改 Workset、Automation participation 或当前运行。
