# Chat Workspace - 交互规范


## 交互策略

Chat 承接绑定本地 Product Workspace 的自由对话与待办对话，Agent 在同一 thread 内感知和调用当前项目的原生待办能力。页面按项目分组展示会话，用户浏览历史时不需要先选择项目；新建对话时，系统在首条消息发送前持续显式展示将要绑定的 Product Workspace，并允许快速切换。系统持续展示用户消息、Agent 正文、折叠 reasoning、工具活动、权限请求和运行状态。Chat 不要求用户先创建待办，也不把对话自动转成 Idea、Work、Case 或其他正式对象。

每个 Chat session 固定对应一个本地项目根和一个持久 Codex thread。会话与对应待办指向同一持久 thread；引用、创建来源和主待办绑定分别表达。自由对话不自动进入 Automation；待办执行遵循既有 thread 归属、运行所有权、权限与并发约束。切换会话或离开页面不停止正在生成的回答；停止操作只 interrupt 当前会话的当前 turn，并保留部分输出。

核心任务包括浏览会话与引用当前项目待办、建立或恢复对话、提交消息、选择能力与引用、让 Agent 整理或创建待办、读取和写回待办、继续执行、停止及异常恢复。页面使用左侧应用导航、中间对话、右侧会话列表或当前待办详情的三栏结构。中间容纳 transcript 和 Composer，不增加完整事情详情 Inspector。中间对话区宽度始终服从页面父容器，消息中的超长结构化内容不改变页面宽度。

## 页面结构

- 左侧应用导航保持 PERSONAL、PRODUCT、PRODUCT LIFECYCLE、ORGANIZATION 四组，Chat 与 Thing 并列；个人中心复用完整账户与 Runtime 能力。
- 顶部复用全局上下文栏，布局对齐现有 `desktop/renderer/index.html` 与 `global-context.css`：左侧产品集 / 查看 / 管理组合，右侧依次为同步状态、运行状态、产品反馈、同步图标、设置图标；桌面不显示页面导航按钮，760px 及以下折叠；内容区显示 `Chat` 和 Codex 连接状态，新建对话入口位于右侧会话列表底部，会话列表受统一顶部产品范围过滤。
- 右侧会话列表按 Product Workspace 分组，组标题显示工作区名称、可用状态和会话数量；会话以单行标题和状态标记展示，完整标题与状态可悬停读取。拖动左侧分隔线调整列表宽度。
- 每个项目默认展示 5 个会话；点击项目标题展开或收起整个项目，每次“查看更多”增加 5 条，收起再展开恢复 5 条。
- 中间对话区顶部显示会话标题和固定工作区，以及重命名、删除入口；临时新对话在同一位置显示可操作的目标工作区选择器。
- transcript 按时间显示用户消息、Agent 正文、reasoning disclosure、工具活动、权限请求和错误恢复提示；消息与 Markdown 内容沿中间对话区宽度收缩。
- Composer 位于中间对话区底部，包含多行输入、当前会话的“模型能力”配置入口、靠右的发送或停止主按钮、快捷键说明和当前权限边界摘要。
- 自由会话标题旁提供“整理为待办”，输入框统一提供“能力与引用”；已对应待办的会话显示身份、业务状态与来源入口。

## 主路径

1. 用户进入或重新进入 Chat，系统立即显示 Chat 页面壳和内存中最近一次会话、草稿与消息投影，同时在后台读取 fresh snapshot；导航不等待 IPC 返回。
2. 系统把自由会话按 Product Workspace 分组，每组默认展示 5 条；用户逐次查看更多，或点击项目标题收起、展开。
3. 用户选择“新建对话”，系统展示临时草稿、建议问题和醒目的目标工作区选择器，不立即创建持久空会话。目标工作区默认取当前会话所属的可用工作区；没有当前会话时取最近成功使用的可用工作区。没有可用工作区时，在 Chat 原位从当前账户全部可访问远端项目中选择目标并完成本地目录绑定，不按 owner、admin 或 member 角色过滤，草稿不丢失。
4. 用户核对目标工作区；目标不符合预期时，用户在第一条消息发送前切换到另一个可用 Product Workspace。切换保留草稿文本，只改变预期 session owner、工作目录和权限边界。
5. 用户核对或通过 Composer 的“模型能力”入口调整 Model/Level，输入第一条非空消息并发送；系统创建 session，固定工作区与会话配置，立即显示用户消息，并在首个 turn 前持久化 Codex thread id。
6. Agent 正文和工具活动以稳定消息项流式更新。页面在用户处于底部时跟随新内容；用户上滚后保持阅读位置。
7. 用户继续发送消息时，系统在同一 session 和 thread 启动新 turn。用户可切换其他会话，活动会话继续更新并在列表显示状态。
8. 用户可停止当前生成；系统发出 interrupt，保留部分回答并标记“已中断”。用户随后发送“继续”或新的要求时启动同一 thread 的新 turn。
9. 用户可重命名会话，或经确认删除会话。删除活动会话时系统先停止 turn，进入终态后再删除本地记录。

## 当前待办详情与 Work 入口

- Work 待办详情的“打开 Chat”建立或恢复该待办对应会话，进入 Chat 并显示右栏“待办详情”。重复打开恢复同一 session/thread；未绑定本地工作区时保留 Work 现场并提示先绑定。
- 右栏顶部“会话列表 / 待办详情”切换只改变侧栏内容；保持当前会话、Composer 草稿、消息阅读位置和运行中的回复。自由会话没有主待办时，详情说明尚未关联，不展示上一个会话的待办。
- 待办详情与 Work 共用内容及操作：身份与状态、引导及允许操作、完整 Markdown 内容、属性、协作、评论、附件和适用的验收反馈。编辑权限、版本冲突、业务状态及 Automation 授权边界一致。
- 会话切换后详情跟随新会话主待办，不能使用 Work 列表的选中项推断。加载时说明正在读取；对象失权、删除或同步失败提供真实提示及重试，不继续显示其他待办。
- Agent 使用原生 read/update 读取最新版本后修改；成功写回由 Work 同步刷新两处详情。未发送的评论及 Composer 文本在同步和切换侧栏时保持，迟到请求不覆盖新对象。
- 窄窗侧栏沿用可关闭抽屉，详情内容内部滚动、操作换行；切换按钮支持键盘和可访问名称，Esc 关闭抽屉并恢复焦点。

## 会话列表与新建

- 会话按统一顶部产品范围过滤、按所属 Product Workspace 分组；项目保持稳定 id 顺序，不因会话活动、选中或项目名称变化重排。
- 组内会话保持创建时间倒序，同时间使用稳定 session id，新会话位于组内最上方。活动、选中、重命名和刷新不改变既有相对位置。
- 项目默认显示前 5 条；有剩余时显示“查看更多（剩余 N 个）”，每次增加 5 条，全部显示后隐藏入口。项目状态独立，收起时重置显示数量。
- 选中或活跃会话不强制展开项目、不自动增加显示数量；收起项目不改变当前对话、草稿和运行中的 turn。
- 只有拥有可见 Chat session（自由或待办会话）的项目出现在会话分组列表中；没有历史的可用工作区仍可从新对话的目标工作区选择器进入。工作区暂不可用时，已有会话组保留可读并标记不可用，但不允许在该工作区新建或继续发送。
- “新建对话”建立一个临时草稿视图。用户未发送消息就返回其他会话时，不生成空历史记录。
- 新对话始终在中间标题区和 Composer 边界摘要中显示“会话属于：{Product Workspace}”。该控件在首条消息发送前可操作，并列出所有已绑定本地目录且 Setup Readiness 可用的工作区。
- 新对话默认使用当前会话所属的可用工作区；没有当前会话时使用最近成功创建 Chat session 的可用工作区；只有一个可用工作区时直接选中，但仍显示归属。没有有效默认值时保持未选择并禁用发送。
- 用户切换临时草稿的工作区时保留已输入文本，不创建 session 或 thread。首条消息被接受后工作区固定，既有会话只显示不可编辑的归属；改变项目必须新建会话。
- 第一条消息成功进入本地队列后，临时草稿成为持久 session；标题取第一条用户消息的有界摘要。
- 标题支持就地重命名。空白标题不保存，取消编辑恢复原值。
- 会话列表包含自由会话与在 Chat 中建立或恢复的待办会话。关联待办不生成平行 thread。Automation 的运行控制和验收问题保持各自业务边界；进入已有任务上下文必须复用可信 thread 绑定与持有者规则。旧的无归属默认 session 不进入列表。

## 消息与内容体验

- 用户消息提交后立即显示；同一提交使用客户端幂等键，双击发送或 IPC 重试不会产生两条消息或两个 turn。
- Agent 正文按稳定 `thread_id + turn_id + item_id` 更新同一消息。生成中显示状态，完成后移除运行指示。
- Markdown 正文支持标题、段落、列表、引用、链接、表格和代码块；代码块提供复制，不自动执行。JSON、代码与表格查看器不超过消息可用宽度，超长单行和超高内容分别在查看器内部横向、纵向滚动。
- reasoning 只有在 Codex 提供非空 summary 时出现，生成中可展开，完成后默认折叠；界面不伪造内部思考。
- 工具活动按 item 原位显示开始、运行、完成、失败和有界目标。完整命令输出、文件正文、raw JSON-RPC 和协议 payload 只进入诊断证据，不进入普通消息正文。
- 文件变更活动直接显示“更新 {具体文件路径}”，多个文件按事件顺序去重，以“、”分隔；超过三个文件时展示前三个路径并标明文件总数。每个长路径保留首尾，以中间省略号控制在 120 个字符内，便于识别文件名。路径按纯文本显示，控制字符转为空格；无可用路径时保留同一活动已知的目标，否则显示“更新项目文件”。完成事件补充或更新路径时在同一消息原位反映，已保存的目标在重新打开会话后保持；缺少路径数据的历史消息保留原提示，不推测文件名。
- 权限请求显示操作、目标、工作区和影响范围，并提供允许或拒绝。处理前对应 turn 保持等待；拒绝结果作为工具状态回到 transcript。
- 已中断回答保留可见正文和“已中断”标记。系统不把 interrupt 描述为可恢复同一 turn；后续输入是同一 thread 的新 turn。
- turn 失败保留用户消息、部分 Agent 输出和具体错误。可恢复错误显示“重试”与“编辑后发送”；不可恢复的 thread 丢失显示已建立替代 thread 的恢复记录。

## Composer

- Composer 支持多行文本和输入法组合；`Enter` 发送，`Shift+Enter` 换行。输入法正在组合时按 Enter 不提交。
- 输入框操作行将 Model 和 Level 合并为“模型能力”入口，摘要显示当前推理级别，完整模型与级别可从入口提示或弹出菜单查看。菜单提供“模型”和“推理级别”两个选择控件，不提供输入过滤。新对话继承 Chat 默认配置，既有会话恢复保存值。Model 清单来自 Codex；Level 随模型提供的能力更新，切换后旧 Level 不支持时选择 medium（若可用）或首项。清单获取失败保留已有配置与发送能力，不制造可选能力。
- 模型能力菜单紧贴自身入口向上弹出，左边缘对齐入口；视口右侧空间不足时向左避让，窗口尺寸变化后继续贴合入口。能力与引用菜单遵循相同规则，以其自身按钮为锚点（包括 `/`、`@` 调起）；能力与引用菜单在可用空间内展开至 640px，搜索区和底部技能设置保持可见，仅候选列表滚动；不得把候选区压缩到只剩少量入口。菜单限制在视口内。打开时焦点进入配置，完成或 Esc 关闭并返回入口，原消息草稿和阅读位置保持。调整立即保存，无需另一次提交；打开或关闭不发送消息。
- 发送/停止按钮始终位于输入框操作行右侧；能力入口和模型入口在左侧，窄窗口保持对齐。
- 调整 Model/Level 原位保存到当前会话或临时新会话草稿，不改写账号设置中的 Chat 默认值，不改变 Automation 默认值，也不创建新 thread。切换会话时每个会话恢复自己的选择。
- 发送被本地接受时同时固定该 turn 的 Model/Level。活动 turn 期间仍可调整控件，修改只作用于下一次发送；停止、重试和继续都保持同一 session/thread 语义。
- 无文本、无能力且无引用时不可发送。有显式能力或引用时可以发送；缺少目标内容由 Agent 在对话中询问。发送后保留焦点，只清除已接受的文本和本条能力/引用标签；提交失败保持完整草稿。
- turn 活动时主按钮变为“停止”，调用当前 turn 的 interrupt。Composer 仍可编辑草稿，但在当前 turn 进入 completed、interrupted 或 failed 前不启动同一会话的第二个 turn。
- 当前 turn 完成后，已有草稿保持不变，用户显式发送才进入下一 turn。
- 页面切换、窗口失焦和会话切换都不自动提交、清空或中断 Composer。

## 待办与会话身份

Chat 右侧支持会话列表与当前会话待办详情切换，不提供独立待办浏览列表或待办筛选控件。会话按工作区分组、组内按会话创建时间倒序；关联待办的会话仍按同一会话规则展示。待办浏览与筛选由 Work 页面承担，Chat 保留原生待办能力、引用、会话关联和业务回执卡片。

会话列表仅展示会话标题和运行状态图标，不展示待办关联文字；关联身份保留在当前会话标题区与对象卡片。来源会话只表示创建来源，不证明待办已有关联会话。关联不改写原会话标题、创建时间或排序；修改待办内容不改写会话标题。

- 整段整理：用户点击“整理为待办”或发出同义请求，Agent 基于当前讨论提炼目标、约束与描述，调用原生能力创建待办。成功后当前会话成为该待办的持续对话，保持同一 thread、历史、未发送草稿及阅读位置。再次请求整理时定位已有对应关系，不创建重复身份。
- 其他待办：用户在当前讨论内让 Agent 记录另一件事，或选择“创建待办”能力后发送内容。待办属于当前项目，保存创建来源；不替换当前主待办、不自动成为子任务、不因创建而开新会话。
- 主动打开其他待办：点击对话内待办卡片，优先恢复该待办已有 thread；无对话时建立其对应 Chat，并由 Agent 读取目标。创建来源不等于持续会话，标题提供“创建于：{来源会话}”返回入口。
- 已有待办：从会话列表或对话内待办卡片进入同一对应对象，读取相同历史与执行现场。消息里引用其他待办只提供上下文，不切换主待办或 thread。
- 主待办身份在标题下显示“本会话对应待办”、编号和业务状态；列表不重复关联提示；主待办关联和创建来源在当前会话标题区与对象卡片保持可读。结果卡片区分“对应当前会话”和“从本会话创建”。
- 删除本地会话不删除待办。任务拥有的可信 thread 绑定不因删除本地列表投影而失效；再次进入由恢复契约决定如何恢复，不能静默复制新的执行现场。来源会话被删除时保留来源不可访问提示。

## 统一能力与引用

Composer 的“＋ 能力与引用”打开输入框附近的选择器。调用能力包含原生业务能力与已发现 Skill，引用上下文包含当前项目的文件与待办；类型有明确标签，不要求底层使用同一协议。

输入独立 `/` 打开能力候选，输入独立 `@` 打开上下文候选；普通句子中的这些字符不触发。输入法组合期间不打开或发送。选择器支持搜索、空结果、方向键导航和 Enter 选择；关闭或 Esc 恢复触发焦点。选择器为窗口内模态浮层，打开时背景不可操作；高度与宽度限制在视口内，候选独立滚动。

选择能力或引用仅添加到草稿。每条消息至多一个显式能力、多个去重引用；换能力替换本条选择，不改工程技能配置。标签可移除，正文保留。选择后回到输入框，用户补充内容并发送，Agent 才开始调用和读取。直接自然语言请求同样有效。

能力与引用随当前会话或新会话草稿保存，切换对象和刷新后恢复。首条消息前更换工作区保留正文和通用能力意图，清除旧项目引用并反馈，避免把无效对象带入新项目。发送时固定本条能力、引用与 Model/Level；活动 turn 期间的编辑只作用于下一条草稿。

已发送用户消息保留本条选择标签。标签表达随请求提供的上下文，不等于已读取；只有工具回执表明读取或调用结果。只发送“创建待办”能力且没有任务内容时，Agent 通过正常对话询问，不弹出创建表单。

“能力与引用”弹出菜单底部的“技能设置”管理 Engineering 配置，当前页选择 Skill 不自动安装、启用隐藏能力或变更全局设置。未安装、不可用或无权访问的能力不以可执行候选呈现；执行中失效按工具错误恢复。

## 原生读写与消息结果

待办为可持续读写的业务对象。打开或重新读取时，Agent 获得最新目标、状态和版本；用户要求修改时，Agent 按权限和版本约束写回，确认成功后更新关联身份和结果卡片。消息文字不替代业务回执。

Agent 正文、工具活动、原生业务审批和结构化对象卡片各自表达不同信息。待办卡片基于真实对象回执构建，支持定位对应会话；普通正文不自动转化为可执行按钮。Agent 提议其他事项时通过自然语言沟通，用户回复形成下一次意图，不在回复底部生成预设“补充标准 / 继续执行”按钮。

用户明确要求执行时，Agent 沿当前 thread 读取目标、检查实现并执行授权范围内的工作。创建或选择待办不自动启动 Automation；Agent 声明、工具成功、业务完成和用户验收保持不同语义。活动执行的所有权不得由新的 Chat 入口抢占。

| 状态 | 页面反馈 | 恢复与连续性 |
|---|---|---|
| 创建/更新中 | 当前消息显示有界工具活动，停止仍可用 | 不提前添加成功卡片，不清除下一条草稿 |
| 写入失败 | 同一对话保留请求和错误，关联身份及卡片保留可信事实 | 用户回复重试或更正要求；不得因重试重复创建 |
| 版本冲突 | 显示版本已变化、本次未覆盖 | 读取最新内容，核对后再次提出修改 |
| 执行占用 | 显示实际持有/等待原因 | 可读取和讨论授权范围，写入/执行不越过持有者约束 |
| 无权访问/对象消失 | 保留历史，明确对象不可用 | 恢复访问后重读；不自动创建替代任务 |
| 离线/提交拒绝 | 保留文本、能力、引用及对象选择 | 恢复后由用户重新发送 |
| 停止/中断 | 保留工具已确认结果与部分消息 | 不自动重放；停止不撤销已经提交的业务写入 |
| 部分成功/结果未知 | 展示已确认待办身份与待恢复步骤 | 先查询已有结果，按同一对象恢复关联；不重新创建 |

## 原型覆盖与能力依据

完整入口组合现有 Chat 会话、Markdown、工具/权限、账户、尺寸、滚动与新原生待办路径。原型覆盖整体整理、对话内新建、已有待办、能力/引用标签、自然语言澄清、读写回执、停止、失败重试、冲突、占用、失权与恢复。

原生能力机制参考 Thing 的受控能力发现、调用与 Chat coordinator，但本地原型不共享 Thing 样本数据库。生产应共享可信待办/thread 归属，不从两个页面各创建一套执行现场。文件、Skill 和业务工具实际接入、跨设备恢复、部分成功幂等与读写权限由生产验证，原型没有证明这些协议。

新增上下文标签、会话列表、回执卡片和选择器消费正式视觉 Tokens、按钮/表面/对话通用规则；颜色、字体与主题源仍位于 visual，不维护独立主题。组件目录的细化登记列入维护结果的视觉交接，不影响这里完整的正式交互表达。

## 状态模型

### 初始与空状态

- 有可用工作区且无历史时显示新对话草稿、目标工作区选择、能力边界和建议问题。
- 没有可用本地 Product Workspace 时禁用发送，解释需要本地目录与 Setup Readiness，并直接提供“选择项目并绑定本地目录”。动作打开上下文 Sheet，先选远端项目，再复用 Product Workspace 目录绑定与 Setup Readiness 检查；成功后留在 Chat、恢复草稿并选中新工作区。
- `workspace-setup.html` 投影该上下文 Sheet 的项目选择、目录绑定、环境检查和失败保留；它不是独立设置导航。
- 首次没有可显示投影时，会话列表和 transcript 保持 Chat 页面骨架；已有投影时后台同步状态出现在页面内且不遮挡阅读或 Composer。
- 后台同步成功后按 owner freshness 规则更新列表与 transcript；失败时保留当前投影、显示就地重试，不回退到旧页面，也不创建默认假会话。

### 运行状态

- `starting`：本地用户消息已接受，正在初始化 app-server、恢复或创建 thread。
- `running`：turn 已开始，Agent 或工具事件持续更新。
- `waiting_approval`：Codex 请求用户批准，Composer 草稿可编辑，停止仍可用。
- `interrupting`：停止请求已发出，主按钮禁用并显示“正在停止”，直到 turn 终态。
- `completed`：turn 正常结束，可以发送下一条消息。
- `interrupted`：部分输出已保存，可以在同一 thread 开始新 turn。
- `failed`：显示错误、保留输入与上下文，并按可恢复性提供动作。

### 后台与重启恢复

- 用户切换到另一会话时，原会话继续接收事件；列表使用状态标记区分运行、等待批准和失败。
- 应用关闭时 main process 对活动 Chat turns 发出 interrupt，并尽力持久化到最后一个语义消息边界。
- 重启后 session、消息、草稿和 thread 绑定恢复。之前未形成终态的 turn 显示“应用退出时中断”，不会自动重启或重复用户请求。
- 下一条消息先 resume 持久 thread；瞬时 resume 失败保留绑定和恢复入口，只有 Codex 明确确认 thread 不存在时才创建替代 thread。

## 删除确认

- 删除入口打开 ConfirmationDialog，展示会话标题、工作区、消息数量和当前运行状态。
- 非活动自由会话确认后只删除该 session 的本地消息、草稿、运行引用和会话 thread 绑定，不影响同项目其他 Chat 或 Automation 数据。待办会话删除只移除本地会话投影与引用，保留待办拥有的可信 thread 身份及业务对象。
- 活动会话确认后先进入 `interrupting`；interrupt 成功或 turn 已终结后执行删除。停止失败时保留会话并显示恢复错误，不执行部分删除。
- 确认文案明确说明本操作不承诺擦除 Codex 自身可能保留的底层 thread 数据。

## 滚动、选择与反馈

- 用户在 transcript 底部阈值内时，新消息和 delta 自动保持最新内容可见。
- 用户主动上滚时，更新不改变当前阅读位置，并显示“回到最新”及未读消息数。
- 切换会话前保存当前草稿、跟随状态和滚动锚点；返回时恢复该 session 自己的状态。首次进入一个会话时默认显示最新内容。
- 后台会话的 delta、终态刷新和已排队自动滚动只更新其所属 session；切换到其他会话后不得改变当前 transcript 的滚动位置、跟随状态或“回到最新”反馈。
- Chat 页面、中间对话区、transcript 和消息的横向边界只由各自父容器决定；JSON、代码和表格查看器内部滚动不产生页面级横向滚动。
- 复制、重试、权限决定、重命名和删除均提供就地成功或失败反馈，不使用全局静默失败。

## 键盘与可访问性

- 项目组、历史会话展开/收起、目标工作区选择、会话列表、更多菜单、权限请求、停止、重试和删除确认均可通过键盘访问，并有可见焦点。
- 发送与停止按钮拥有随状态变化的可访问名称；运行、等待批准、中断和失败状态通过文字与辅助技术通知，不只依赖图标或颜色。
- 流式 delta 不逐字符触发播报；Agent 消息完成、权限请求和错误形成有界通知。
- `Esc` 只关闭当前菜单或弹窗，不停止 turn；停止必须由明确按钮或其快捷操作触发。

## 边界

- Chat 产品层直接使用 Codex 对话能力，不自动启动 state-driven Runtime、`$using-arckit`、trusted ledger 或 Automation Coordinator；用户显式调用 Skill 的授权边界按场景技能规则保持。
- Chat 内 Agent 可通过可用、受控的原生能力创建和更新当前项目待办；不因自然语言声明而直接改变业务事实。此能力不自动授权 Project、Feedback、Idea、Project State、Case 或 acceptance feedback 写入。
- Product Workspace 决定 `cwd`、workspace root、skill discovery 与 sandbox 边界；Renderer 不获得文件系统、Codex 凭据或通用 RPC 能力。
- Chat 的停止不释放 Automation human Gate，不改变远端任务状态，也不抢占 Automation task thread lease。
- Composer 支持项目文件和待办上下文引用；引用不是上传附件，也不改变工作区。语音、共享链接、跨设备同步、会话分支和模型目录管理不在本页范围；Model/Level 仍只控制当前会话，不承担全局默认值管理。

## 场景技能入口

“能力与引用”弹出菜单底部的“技能设置”进入 Engineering 的 Chat 配置，输入框不单列该链接；“能力与引用”中的 Skill 选择只影响本条请求，两者职责不同。默认关闭内置 Automation 技能，可开启普通技能或官方 Loop 核心配套。返回后保留当前会话、工作区与草稿；保存从下一条消息生效。关闭技能不清除已有历史，需要全新上下文时新建会话。用户主动让 Agent 依据 skill 推进 Loop 时，Agent 可执行对应项目操作；Chat 产品层不自动创建 Automation Run 或调度租约。

## 原型布局与视觉

中央消息与 Composer 填满剩余宽度，桌面两侧保留 24px 边距；窄窗使用 12–16px 边距。右侧独立滚动，拖动左边界调整宽度（220–560px，并给对话保留空间）；输入框顶部支持上下拖动调整高度（66–420px，受可用高度约束）。尺寸本机保存，窗口变窄时限制尺寸而不丢草稿。分隔线支持键盘方向键调整。760px 及以下会话列表使用抽屉，选择后关闭，Esc 关闭并恢复焦点；抽屉不提供横向调宽。

使用 visual/_library/generated-tokens.css、brief.md、components/conversation.yaml 和 light 主题的既有浅色与浅杏橙角色。states.html 仅为历史辅助状态说明，default.html 是唯一完整主入口。模型、渲染、输入选择器和原生能力模拟按职责拆分。

原型仅操作隔离本地样本；正文、工具过程、待办回执、文件内容和 Skill 加载都是模拟。场景工具提供离线、提交失败、权限、工作区缺失、长消息、清单不可用、原生写入失败、版本冲突、占用、失权及恢复入口，不在产品区域添加演示控件。实际原型验证见 verification.json 与 verification-native.json。生产 Codex、业务权限、幂等、跨进程 thread 绑定、目录读取和后台同步需要独立实现验证；已有生产布局证据不能证明本页新增能力已实现。
