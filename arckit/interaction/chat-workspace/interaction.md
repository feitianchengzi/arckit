# ArcOrbit 一体式工作空间

状态：正式交互原型。采用用户选择的 A 三栏工作区与窄图标主导航；本页仅定义和演示交互，不表示生产实现已完成。入口：`default.html`；可重复场景：`scenarios.html`。

## 交互基线

Chat、Work 是同一件工作的两种视角，Auto 是它的推进方式。用户在同一工作现场讨论、查看有效信息、委派、接管、检查成果，不需要“整理成另一个待办”，也不需要在 Chat 与 Automation 页面之间搬运上下文。

- 新 Chat 的第一条非空消息成功提交后创建工作；未提交的空白页只是草稿，失败不留下空工作。
- 直接创建待办保留独立入口，可以只有目标和负责人而没有对话。开始人工协作后沿用该工作身份。
- 对话补充、目标、约束、完成标准、来源、成果、执行状态和负责人都属于同一工作。列表与详情共享编号。
- 创建、分配、讨论、编辑、恢复网络均不授权 Auto。启动和继续必须有明确动作。
- 业务状态与执行状态分别呈现：执行结束产生待验收成果，不直接表示用户验收或反馈解决。

| 项目 | 项目选择 / 生命周期工作区 / 项目上下文 | 概览、Idea、工作、成果、发布、运维、反馈、产品集 |

主产品视图不展示探索说明、候选比较或故障注入按钮。`scenarios.html` 是独立预览入口；`?preview=1` 提供推进一轮、故障和重置工具。普通入口自动推进模拟执行。


### 列表双视角与标题阅读

主导航只有一个 Chat 入口。其内部左栏用对话/待办 Tab 切换：对话列出有消息记录且未归档的工作，按最近交流排序；待办包含所有工作，并提供负责人、Auto、验收和归档筛选。两者使用同一工作 ID。切换 Tab 或筛选只改变列表，不重置中央工作、草稿或 Auto，也不强制选中第一条。

新建入口位于每个项目标题右侧：对话 Tab 下新建对话草稿，待办 Tab 下直接创建待办。直接待办无消息时不出现在对话列表。Chat 不展示产品集名称、独立搜索框或独立新建按钮；产品集维护位于项目页。主导航宽 60px，小窗口收至 50px。

过长标题默认单行省略。仅在溢出且悬停或键盘聚焦时，先停留约 850ms，再以约 32px/s 水平滚至末尾，停留后返回起点并往返；移开/失焦取消并复位，不滚动整行或负责人状态。短标题不动画。完整标题保留在原生 title 和可访问名称中；减少动态效果偏好下禁用标题动画，使用静态完整提示。列表 Tab 支持左右/Home/End 键。

## 项目与 Idea

从 Chat 列表底部或项目页新建项目，填写名称、Idea、所属组织，并明确选择是否加入产品集。成功后建立项目与首件探索工作；不自动授权 Auto，也不创建远端仓库。

项目页左侧选择产品集内项目及其他可访问项目；中央按生命周期展示概览、Idea、工作计划、成果、发布准备、运维记录和反馈；右侧保留当前项目的目标、成员和本机连接入口。点击工作返回同一 Chat 身份。文件与 Git 根据工作所属项目展示，未连接目录时显示缺口。

产品集是本机关注集合，与组织归属和 Auto 参与资格独立。只在项目页管理名称及成员；空集合合法，移出不删除项目或停止工作。Chat 按集合成员分组，不重复提供范围切换。直接从项目标题创建工作，项目归属确定；查看已有工作恢复其项目上下文。

发布与运维是新增的交互预埋：版本、说明、检查项、交付预览、环境记录、异常转工作。原型不执行构建、部署、监控或真实发布。反馈沿用来源→工作→验收→人工关闭的闭环。

## 团队、工程与设置

能力对应、交互位置和模拟边界详见 [suite-coverage.md](suite-coverage.md)。组织管理承载组织/成员/项目与关系矩阵，项目权限不自动继承组织权限。本机目录、产品集成员、Auto 参与资格独立维护。

工程页聚焦已实现的内置 Skills 场景配置：Chat 与 Automation 分开，使用方式为直接、按需或停用；Automation 核心能力锁定。当前原型不新增能力市场。设置按账户、外观、Codex Runtime、任务源、网络、同步与产品反馈分区；草稿独立保留，Chat、Automation、执行权限、任务源、代理各自原位保存，只提交自身配置；保存不触发同步。同步失败在显式同步动作内反馈。关闭重开恢复已保存值。敏感凭据不写入原型持久化存储。

## 人工协作与信息沉淀

输入区 Enter 发送、Shift+Enter 换行；输入法组合中的 Enter 不提交。草稿按工作持久化；切换项目不覆盖草稿。空提交不产生工作。发送失败保留输入并允许重试。

摘要可随时查看和人工纠正；约束保留来源入口，反馈来源返回原反馈，消息来源定位原文。人工修改增加修订号并清除旧检查标记。开放问题和完成标准分开呈现。

运行中的补充先显示“已接收，等待执行边界采用”；到达边界后纳入同一工作。暂停请求到回执之间显示“正在暂停”，暂不允许直接修改。回执后可讨论、编辑、分配，继续 Auto 仍需明确操作。

“工作环境”提供模型与推理强度入口；设置只演示后续回合配置，不修改活动回合。原型没有真实模型调用。

## Auto 连续状态

| 状态 | 可用操作 | 连续性 |
|---|---|---|
| 人工 / 已暂停 | 讨论、编辑、分配、交给/继续 Auto | 保留工作、对话和成果 |
| 等待执行位置 | 取消排队、补充上下文 | 同项目前件释放后开始已授权执行 |
| 推进中 | 补充要求、暂停并讨论 | 切换工作或项目后继续推进，不抢当前选择 |
| 正在暂停 | 等待停止回执 | 不把请求当成停止完成 |
| 需要决定 | 查看取舍并确认 | 决策记录为工作约束，随后继续本轮 |
| 等待外部条件 | 查看原因、确认条件恢复 | 恢复到暂停，明确继续后才执行 |
| 执行失败 | 查看原因、检查后恢复 | 对话和已形成内容保留，不默默从头重建 |
| 他人执行中 | 浏览、补充 | 直接控制和内容改写被阻止，提示执行者 |
| 待验收 | 检查成果、提出调整、验收 | 检查且勾选标准后才能验收 |
| 已验收 | 查看成果、重新打开、归档 | 重新打开沿用身份，旧成果保留、检查失效 |

同项目原型模拟串行执行；不同项目可继续独立推进。刷新后活动模拟执行恢复为暂停，不能把本地恢复视为服务端仍在执行的证明。

## 待办、成果与归档

待办页提供全部、我负责、待验收与已验收、已归档筛选和搜索。直接创建可指定当前项目成员。分配不会启动执行；活动执行需先暂停再变更负责人。

成果在消息区和右侧均可打开。拾光样例可实际点击导出进度、失败、重试与完成；其他项目呈现目标和标准的成果检查卡。成果是候选，必须由用户检查和验收。

提出调整回到暂停协作；重新打开增加修订并清除旧检查。归档需确认，活动/排队工作需先停下；归档隐藏于日常列表但保留对话、成果和来源，从“已归档”可恢复。不提供不可恢复删除。

## 反馈闭环

反馈列表 → 内容与沟通 → 忽略/恢复、关联已有工作或新建关联工作 → 在同一工作推进 → 验收 → 人工标记反馈已解决；已解决可重新打开。

- 回复和工作进度分别保留；创建待办或发送回复不等于反馈解决。
- 转工作表单可编辑目标并选择项目成员；成功后带原反馈来源，尚未开始 Chat 时不制造对话。
- 已有关联时不重复创建；已有待办只从当前项目选择。源反馈可从工作约束返回。
- 工作未验收时解决按钮不可用；验收后仍须人工明确标记。这里的“解决”不代表软件已发布或线上问题经过真实验证。
- 回复输入按反馈保留，失败不清空；忽略后可恢复，关联后可直接打开同一工作。

## 团队协作

团队页展示成员、角色、负责工作数和待接受邀请。邀请防重复，邀请记录不冒充已加入成员；可撤销。管理员可修改其他成员角色。

移出成员必须明确转交其工作，历史记录保留；尚有活动执行时先交接。当前管理员不提供自我移出入口。只读成员可查看资料和成果，不能写入；普通成员可以协作，但不能管理邀请、角色或移出成员。

本原型为项目团队层级，不扩展组织目录、计费、跨组织策略、SSO 或真实邀请接受服务。

## 异常与输入连续性

- 离线：显示连接状态，提交失败保留草稿；重新连接不启动 Auto。
- 刷新失败：保留上次内容并说明非最新，可重试；文件读取失败只影响右侧局部内容。
- 编辑冲突：阻止覆盖新版本，保留表单草稿；查看最新目标后人工合并，再提交。
- 权限不足或被他人占用：说明原因，不假装写入成功；输入保留。
- 空列表、空项目、无对话待办、无反馈、无邀请、未连接目录均有对应空态。

## 键盘、窗口与视觉依据

模态对话框使用原生 dialog，覆盖当前窗口内容；支持 Esc 关闭并返回触发位置。综合栏是非模态资料区。≤1100px 时从标题按钮打开覆盖式综合栏；≤760px 时项目导航可折叠，Esc 关闭。综合栏标签支持左右/Home/End 键，长文件和 Diff 在栏内滚动。标题单行省略保留完整 title。

复用 `arckit/visual/_library/generated-tokens.css`、浅杏橙主操作与明暗主题；本次不修改视觉事实。页面布局以用户选定的三栏交互为准，旧全局顶栏约定在本原型不叠加。浏览器样本不仿造原生窗口控件。

## 场景与验证边界

场景操作及复核见 `coverage.md`；运行命令见 `README.md`。JS 按模型、基础视图、综合栏、项目协作、执行生命周期和呈现拆分。项目模块约 530 行，保留在单文件以维持共享项目上下文；CSS 拆为基础、详情、浮层、综合栏和项目视图，避免大文件继续增长。

所有数据存在独立 localStorage；正式稿与探索稿不共用存储。语义沉淀仅对预置示例有脚本响应，任意输入保留为协作补充；不会真正执行 Agent、读写源码、提交 Git、发邀请或回复用户。真实多用户同步、网络提交中的竞态、真实执行权限和生产性能不由本原型证明。

软件发布、运维、组织治理、工程个性化仍是后续扩展，不在核心页面塞入无效入口。本次不改动其他类型预期事实文档，也不宣称这些长期能力已完整设计或实现。
