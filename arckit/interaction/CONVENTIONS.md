## ArcOrbit Desktop 跨页面体验契约

### 内容与功能边界

- 体验调整保持页面已有文字、数据字段、业务动作、导航目的地、状态语义、权限边界和恢复结果不变。
- 信息重组只改变视觉分组、空间节奏和渐进揭示方式；不得隐藏完成当前任务所需的信息，也不得把既有动作合并为含义不同的新动作。
- 页面身份由任务结构、首要对象和主要操作建立，不以重复指标卡或装饰性容器替代真实层级。

### 窗口框架与控制

- 主窗口在所有平台都只显示一条 ArcOrbit 应用标题栏，不叠加可见的操作系统标题栏；窗口边缘继续支持系统缩放，标题栏空白区域支持拖动。
- macOS 使用系统原生 traffic lights。绿色按钮单击进入或退出系统全屏；悬停或系统支持的按住手势显示由 macOS 提供的移动、缩放、排列和全屏面板。ArcOrbit 不绘制第二组红黄绿按钮、不仿造系统布局面板，也不接管原生按钮的单击、悬停或长按语义。
- Windows 与 Linux 使用应用标题栏右侧的最小化、最大化/还原和关闭按钮。三个按钮可聚焦、不是装饰状态点，控件区域不参与窗口拖动；双击标题区域切换最大化与还原。
- Windows/Linux 最大化按钮随当前窗口状态切换为“最大化窗口”或“还原窗口”的可访问名称和悬停提示。系统快捷键或其他原生方式改变窗口状态时，应用标题栏同步更新，不要求用户再次点击才能校正。
- 平台分支只选择原生 macOS chrome 或受限的 Windows/Linux 产品动作；Renderer 不获得任意 BrowserWindow、Electron API、shell 或系统窗口命令能力。

### 可读性与密度

- 页面正文、表格内容、表单内容和解释性文字使用不小于 14px 的正文层级；人工对话使用不小于 15px 的阅读层级。
- 导航、按钮、字段标签和状态文本使用不小于 13px 的标签层级；辅助状态、时间和元数据使用不小于 12px 的辅助层级。
- 11px 微型层级只用于短计数、非关键标识或具有等价可访问名称的图形旁注，不承载句子、操作名称、状态含义、错误原因或恢复说明；生产界面不使用小于 11px 的可见文字。
- 常规按钮、输入框和可操作列表行高度不小于 36px；高频数据行不小于 40px。仅图标工具可采用 32px 紧凑尺寸，但必须提供可访问名称和清晰的悬停提示。
- 同一信息区优先通过标题、正文、辅助信息三层关系组织；高密度数据与大面积空白不得同时由微型文字维持表面容量。

### 状态、反馈与恢复

- hover、selected、active、focus、disabled、busy、success、warning 和 error 各自具有可辨识且不互相替代的反馈；颜色不作为状态的唯一载体。
- 用户触发操作后，控件或其紧邻区域立即显示接受、进行、完成或失败状态。后台刷新保留最近可信内容，并明确其新鲜度或失败原因。
- 空状态保留页面结构并给出首要动作；错误状态保留最近可信快照、影响范围和可执行恢复动作；破坏操作继续使用已有确认与权限边界。
- 跨页面相同组件使用相同状态名称、反馈位置和恢复语义；页面专属状态不得通过改变共享组件的基本含义表达。

### 键盘与焦点

- 每个鼠标可触发的控件和可选行都具有键盘等价路径。原生控件直接使用其语义；自定义可选行进入正常 Tab 顺序，并以 Enter 或 Space 执行与点击相同的动作。
- focus-visible 覆盖按钮、链接、输入、选择器、菜单项、可选行、折叠控件、图片入口和自定义操作控件，使用连续可见的双像素轮廓与间隔，不被容器裁切。
- 焦点顺序遵循可见阅读顺序。弹窗打开后焦点进入弹窗，关闭后回到触发控件；异步刷新和列表重绘不无故重置焦点或滚动位置。
- 正文与背景的对比度不低于 4.5:1；大号文字不低于 3:1；控件边界、焦点和必要图形与相邻颜色的对比度不低于 3:1。

### 产品质感

- 常规信息区优先使用共享表面、分隔线和空间关系；卡片只表达可独立操作、可选择、可折叠或需要语义强调的对象。
- 图标来自统一矢量图标体系并保持一致笔画、尺寸和对齐；字符、Emoji 和临时符号不承担生产操作图标职责。
- 页面标题、上下文、主要动作和当前状态形成稳定首屏顺序。相同外壳内的 Today、Work、Feedback、Automation、Chat 和规划页面通过任务结构与主要对象形成清晰身份。
- 动效只解释状态变化、层级进入和直接操控反馈；减少动效设置下取消非必要位移和缩放，但保留状态结果。

## 线框图规范

- **视觉风格（强制）**: 极简线框图 — 仅使用 wireframe-style.css 中的灰度与线框类，禁止内联彩色样式，禁止在 HTML 或 CSS 中引入非灰度色值。
- **扩写 wireframe-style.css**：仅添加通用组件类（不与具体业务耦合）；扩写前在文件中搜索，避免重复定义；按既有区块归类插入。详见 references/wireframe-style.md「扩写规则」。
- 格式: 自包含 HTML，样式仅来自根目录 wireframe-style.css（相对路径引用）
- 状态: 至少 4 个（加载中/成功/空状态/错误）
- 标注: 关键节点使用 data-kit 属性标注目标平台控件
- 弹窗: 直接渲染在页面中，不使用 position:fixed
- 设备: `.device-frame`（iOS）/ `.tablet`（iPad）/ `.desktop`（macOS）
