# 添加 Idea

## 交互策略

独立添加页围绕“将这个想法纳入产品管理”推进。选择材料后自动开始一次 Agent 理解；空白起点先描述想法。左侧呈现可编辑结果与必要选择，右侧复用 Chat 消息列表和输入框，显示请求、材料/环境工具、追问与执行回执。长期产品定义是可选完善。

页面顶部持续显示当前阶段及下一步说明。只保留一个当前主要动作：开始整理、保存修改、审阅并确认接入或查看产品。人工直接配置与执行保留为次要路径。任何主动作不可用时就地说明原因。正式完成与已共享分开反馈。

## 页面结构与主路径

- 选择起点：材料入口说明会由 Agent 读取；选择完成后创建仅本机草稿，立即启动整理。空白起点显示一句想法输入和“开始整理”。
- 正在理解：显示已选材料路径、正在理解的状态、真实会话活动和停止；允许补充说明和查看本机记录。
- 待补充：Agent 整理内容和依据可见，缺失组织/仓库等字段就地提示。人直接选择或回答对话。仓库权限未查明不显示成功。
- 待确认：业务字段可修改；新建议在没有手工编辑时装入可编辑草稿，明确标注待保存。修改后一次保存全部资料与方案。确认前使用可读业务摘要，不展示 JSON。
- 执行中：显示正在接入、实际完成步骤及对话工具回执；不允许再改变确认的方案。离开不会丢失记录，停止不能撤销已完成的外部操作。
- 已录入：真实 GitHub 仓库、本地目录和 arckit/product 文件校验成功；主动作“查看产品”，次要“共享资料”。未推送显示待共享，不自动赋产品推进状态。
- 失败与待核对：显示具体失败、已成功步骤与保留内容，提供修改方案、继续整理或直接执行；创建响应不明时引导关联已核对资源。
- 中断恢复：重开恢复原记录和对话，显示继续整理，不自动重放分析或外部创建。Agent 缺失时保留直接编辑、环境设置入口和重试。

## 编辑与对话一致性

建议与手工编辑共享同一基础修订。正在编辑时晚到建议不会覆盖；显示“查看新建议”，用户选择采用或保留自己的修改。资料、名称、接入方案一次保存，界面操作形成对话中的事实记录，发送自由消息前先保存可保存的编辑。过期时保留编辑并提供明确比较/重新整理动作。

材料更换会令旧方案确认与旧建议失效，重新整理必须使用新的材料范围。资料保存不代表正式录入。正式 Idea 与临时记录的存储/恢复遵循产品规格四条约束。

## 布局与可访问性

宽窗口左右并列，左侧结果独立滚动，右侧保持消息与输入可见。窄窗口把当前阶段与主动作放在内容前，详细字段折叠，不把聊天藏在长表单底部。主按钮沿用现有样式，状态使用文字与 aria-live，不仅依赖颜色。反馈、草稿、Disclosure 与滚动位置在会话更新时保留。

## 投影

`default.html` 分别投影上述八个关键状态；每个状态包含触发条件、组件和交互行为。

## 环境探索反馈

Agent 的原生命令、快捷检测结果和后续判断均在同一对话中显示。环境详情显示检查时间、执行来源与可展开的脱敏诊断；未知不是未登录或无仓库。用户可重新检查，也可让 Agent 继续排查；失败不清除已确认账号、仓库根或正在编辑的方案。需要突破原生只读/网络沙箱时显示现有 Chat 审批，环境探索不自动批准接入写入。

## 正式工作目录

字段提供“使用所选材料目录”和“选择其他工作目录”。后一项提供原生文件夹选择，可新建空文件夹或选择对应已有仓库；明确显示实际完整路径，以及“复制材料、保留来源”或“空白起点，仅准备仓库”。不显示应用托管源码选项。已有项目显示其绑定目录并允许明确沿用。确认区重复源、目标、复制范围及不会自动提交/上传；旧 managed 草稿显示需要重新选择，保存前后都不能误用私有 Agent cwd。

材料区只负责添加/更换来源，正式目录区负责最终位置，避免两个“复制位置”入口竞争。Agent 与界面使用同一目录标签、选项说明和计划投影；消息发送前保存当前编辑，用户无需复述左侧选择。源目标冲突显示实际路径，允许返回修改，成功后显示正式目录和材料处理回执。
