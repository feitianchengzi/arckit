# A · 并肩工作

状态：候选。入口 default.html；共享策略 ../../exploration.md。

## 策略

对话左侧推进，待办摘要右侧常驻。 无需切换就能核对自动沉淀、负责人和完成标准。 代价：信息持续可见，但对话可用宽度减少。

所有操作留在当前 Chat 页面。列表中的同一编号同时代表对话关联工作和待办；无 Chat 的待办显示真实空态，可以直接启动 Auto 或发起人工交流。

## 主路径

新对话 → 首条消息创建工作 → 填入示例并发送 → 工作摘要沉淀 → 查看来源或直接编辑 → 明确启动 Auto → 推进样本 → 方向选择 → 推进 → 检查成果 → 体验失败/重试 → 勾选并验收。

接管路径：Auto → 暂停并讨论 → 推进样本收到停止回执 → 人工消息或修改摘要 → 明确继续 Auto。直接待办路径：创建表单 → 负责人 → 无 Chat 的工作 → Auto 或人工对话。修订路径：待验收 → 提出调整 → 暂停 → 继续 → 重新检查。

## 连续性与异常

每工作独立草稿、阅读位置和有效信息；首条消息失败不创建空对象。离线、下次失败在灰色场景工具中触发，输入保留可重试。刷新后运行恢复暂停。列表切换不改变执行状态。编辑旧验收内容会使检查失效。

Enter 发送，Shift+Enter 换行，输入法组合不发送。模态 dialog 覆盖预览窗口、Esc 关闭、恢复触发控件焦点；详情侧栏非模态、Esc 关闭，窄窗覆盖内容但保留关闭入口。窄窗列表从顶部打开。主题可切换。

## 视觉与模拟边界

使用正式 generated-tokens.css 与共享 app.css；桌面原型不仿造操作系统窗口控件。本地脚本只理解预置示例，任意文本不声称被结构化理解。上方“推进样本”是独立模拟工具。代码、服务、权限、发布、真实多用户同步均未接入。

实际验证见 ../../verification-notes.md。

## 本轮调整

A 被选择继续深化。综合栏位于应用 grid 第三列，顶部与左侧栏及中央标题栏齐平，不再嵌在中央 body 内。执行状态与主动作合并进中央标题，不占第二行独立控制栏。综合栏三入口为待办、文件、Git Diff。待办概况使用原同一工作身份；文件与 Git 使用项目级只读样本。目录展开/搜索、文件预览、引用到输入、差异选择和模拟暂存均可操作。

主产品视图不展示探索说明或场景工具；主题入口披露模拟边界，独立 preview=1 入口提供工具。宽度不超过 1000px 时从标题栏打开综合栏，顶部关闭按钮与 Esc 收起。文件引用追加到已有草稿，不清空输入。

## 项目与协作能力接入

沿用 A 三栏。项目名称作为切换入口；左侧增加对话、待办、反馈、团队四个项目内视图，底部从 Idea 新建项目。对话仍为核心工作现场，待办列表仅提供同一对象的管理视图，打开后回到对应 Chat。管理视图替换中央内容，右侧展示项目概况。

新建 Idea 填名称与目标后，在本地建立项目并创建第一件探索工作及其对话。取消/失败保留 Idea 草稿，未提交不创建项目。此处只探索体验，不模拟真实远端项目/GitHub 仓库/本地目录接入已完成。

项目之间隔离待办、反馈、成员、草稿和综合栏选择。示例“拾光”有文件/Git 数据，“轻记”和新项目显示尚未连接目录，不能显示拾光文件。切换不重建待办或清空原工作草稿。运行概况保留跨项目任务定位。

反馈可回复、忽略/恢复、关联已有待办或创建带来源的新待办。创建关联幂等保护防止同一反馈重复建工作；关联工作验收后才启用标记已解决，已解决可重新打开。回复、任务验收与反馈解决各自保留状态；不以创建任务代表问题解决。源反馈可从待办约束回到反馈详情。

团队可查看成员及负责工作数、编辑角色、创建或撤销待接受邀请。邀请不会增加成员数。待办负责人候选取当前项目成员。所有数据仅在当前浏览器保存；不会发送真实邀请、回复或通知，没有真实权限与组织服务接入。
