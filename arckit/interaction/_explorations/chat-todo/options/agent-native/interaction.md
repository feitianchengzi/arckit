# Chat 原生待办能力 · V4 交互候选

## 本轮策略

统一输入框入口“＋ 能力与引用”，分为原生能力/Skill 与文件/待办引用。选择后只放入本条草稿，发送才调用。普通语言始终可用。`/`、`@` 是本轮探索的快捷触发方式，尚未作为正式产品要求。

会话与对应待办从两个列表进入同一 Chat thread；其他待办的创建来源另行标注。Agent 消息保留文本和真实事件式的工具活动，移除预设快捷回复。完整依据和边界见 [主题说明](../../exploration.md)。

## 试用路径

| 体验 | 操作 | 结果 |
|---|---|---|
| 当前会话整理 | 标题“整理为待办” | 当前 thread 创建并关联待办，列表两个入口回到同一历史 |
| 显式调用 | ＋ 能力与引用 → 创建待办 → 输入“给 Chat 增加会话搜索” → 发送 | 标签选择时不创建；发送后出现工具活动和结果卡片 |
| 自然语言创建 | 探索工具试填“创建其他待办”后发送 | 当前项目创建另一条待办，继续当前会话 |
| Skill 与上下文 | 输入 / 选择“问题诊断”，输入 @ 选择文件或待办，输入问题发送 | 先模拟读取引用，再模拟使用 Skill；当前 thread/主待办不改变 |
| 来源与对应关系 | 打开刚创建的其他待办，再点击标题“创建于…” | 主动打开才建立该待办的对话；可返回创建来源 |
| 待办读写 | 待办列表打开 T201；试填“读写当前待办”后发送；点击“查看最新内容” | 读→写→再次读可看到更新后的内容 |
| 执行 | 输入“继续执行”，或试填执行请求 | 当前 thread 模拟执行反馈，不假称已完成业务 |
| Agent 建议 | 试填“Agent 发现旁支”，再回复“记成另一个待办” | 无回复按钮，以自然语言触发创建 |
| 错误恢复 | 勾选下次写入失败后创建，回复“重试刚才的操作” | 保存请求，对话重试，成功回执后新增列表 |
| 草稿与标签 | 添加能力与引用，写草稿，切换会话再返回/刷新 | 能力、引用与文本按会话恢复 |
| 取消和移除 | 选择器 Esc；标签 × | 取消保留触发字符与原草稿；移除标签不删正文 |

每条消息至多一个显式能力、多个去重引用；换能力替换本条能力，不改全局配置。发送后标签保留在用户消息中，输入框为下一条清空。只发送能力时可由 Agent 询问任务内容。消息标签表示随请求传入，不表示此前已读取；读取完成单独显示工具事件。

## 选择器与键盘

选择器用原生 dialog，定位输入框附近，背景不可操作；关闭按钮/Esc 返回触发控件。选中后回到输入框。搜索支持无结果状态，方向键移动候选，Enter 选择。仅输入单独 / 或 @ 时触发，不解析一般正文中的这些字符。输入法组合期间不触发，结束后判断。

760px 以下列表为抽屉，关闭按钮或 Esc 关闭。Ctrl/⌘+Enter 发送，输入法组合期间不发送。选择能力不发起后台动作；引用待办不导航。发送中的停止只阻止尚未提交的模拟操作。

## 实现与模拟边界

model.js 保存隔离样本；prototype.js 管理 Chat、索引与模拟 Agent；composer.js 管理能力/上下文选择、标签与草稿。独立存储 key `arcorbit-chat-todo-agent-native-v4`，不复用旧稿状态。刷新不重放未完成请求。

正文与工具活动参考现有生产能力。统一选择器、标签、待办结果卡片为新增候选。Skill、项目文件内容、待办 API、工具回执及 thread 全部是本地样本，不连接真实模型、文件读取、原生工具或服务。自由文本识别限于样本短语；超出样本明确说明未连接真实 Agent。

真实执行资格、授权、冲突、失权、任务删除、Automation 占用、部分成功和跨进程绑定仍需正式实现验证。引用具体 Skill 不等于它已被安装或授予权限。Agent 文字不承担完成/验收或业务回执的事实来源。

视觉沿用 `../../../../../visual/_library/generated-tokens.css` 和 light 主题。应用导航为定位背景。新增选择器/标签是既有视觉角色的候选组合，尚未增加正式组件规范。
