# Idea Workspace - 交互规范

## 交互策略

Idea 是正式项目之前的创意探索与团队讨论页。页面把来自 Chat、Feedback 和团队输入的机会组织为可比较的创意，展示问题、目标用户、价值假设、证据、风险和待确认问题。

创意状态使用“探索中”“讨论中”“已确认”三类计划状态。只有用户明确选择“开始项目”时才进入正式项目转换预览；当前展示页不创建 Workshop Project 或 Project State。

## 页面结构

- 顶部展示当前产品范围和创意漏斗摘要。
- 左侧按状态展示创意列表。
- 中间展示所选创意的问题、用户、证据和风险。
- 右侧展示团队观点、待确认问题和来源关系。
- 已确认创意显示“开始项目”计划动作。

## 主路径

1. 用户从 Idea 入口查看当前创意。
2. 用户按状态或来源选择一项创意。
3. 团队阅读事实、假设、观点和开放问题。
4. 用户继续探索，或把创意标记为已确认。
5. 已确认创意进入正式项目转换预览，明确项目名、范围和来源。

## 状态与反馈

- 探索中强调问题与未知，不要求提前给出解决方案。
- 讨论中展示成员观点与冲突，不自动做业务优先级决定。
- 已确认展示明确依据和开始项目动作。
- 缺少关键事实时，“开始项目”保持不可用并列出缺口。

## 边界

Idea 不是 Task、Case 或 Project 的别名。当前页面中的状态、讨论和转换是计划展示，不写入远端项目、成员关系或 ledger。
