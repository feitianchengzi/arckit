# Release Workspace - 交互规范

## 交互策略

Release 同时展示发版准备和线上监控的计划全貌。页面连接候选变更、验证证据、release-intent、安装包、签名、渠道和上线后健康，但不替代任何真实发布授权或监控系统。

英文界面统一使用 `Release`，中文说明使用“发布”。

## 页面结构

- 顶部展示 release train、目标版本、渠道和整体准备度。
- 主区展示候选变更、验证、产物和审批检查。
- 侧区展示上线健康、事件和回退关注项示意。
- 发布动作显示真实约束说明并标记为计划动作。

## 主路径

1. 用户进入 Release 并选择产品范围。
2. 页面展示当前版本候选、验证证据和未闭合风险。
3. 用户查看 `tf/*`、`beta/*` 或 `appstore/*` release-intent 与平台产物状态。
4. 团队讨论发布窗口、签名、渠道和上线观察。
5. 页面保留人工授权边界，不自动触发 workflow 或发布。

## 状态与反馈

- 准备中展示未闭合验证和风险。
- 可发布只表示示意检查通过，不构成发布授权。
- 监控区区分健康、观察和事件；没有真实来源时明确标记示例。
- 回退动作不可用时说明缺少受信部署或监控 adapter。

## 边界

Release 不创建 tag、不触发 GitHub workflow、不签名、不发布安装包，也不写入外部监控系统。
