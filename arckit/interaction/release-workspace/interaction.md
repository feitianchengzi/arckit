# Release 工作台

## 交互策略

用户在既有产品集与查看范围内完成构建运行、终端、Git、源码和 Agent 协作。全部范围显示项目与活动，进入具体项目后明确工作区。切换范围不迁移任务、终端或会话；本机活动可以返回范围外仍可访问项目。页面复用既有主题和 Chat 组件。

## 主路径

选择已有项目 → 查看命令并构建/运行 → 查看输出和真实结果 → 失败时交给 Agent → 检查文件/Diff → 暂存提交 → 重新执行。高级 Git 打开内嵌 Lazygit，终端保持在页面内。

## 状态与反馈

- 全部/空状态：显示已有绑定与项目入口；缺少绑定引导既有配置页面，不创建 Release 配置流程。
- 终端：多标签、分屏、搜索、清屏、resize、关闭与 Ctrl/Cmd+反引号；活动终端关闭明确提示。
- 任务：准备、运行、成功、失败、停止、中断；日志与停止入口始终可达。重试启动新记录。
- Git：未暂存/已暂存/冲突分别显示；分块暂存对应所选补丁；提交说明保留草稿。危险变更确认显示对象和后果。
- 源码：文件浏览与搜索、编辑/Diff 切换、未保存标记、基线变化冲突；保存失败保留草稿。
- Agent：使用 Chat 相同消息与输入组件；附件上下文是具体操作/文件引用；停止回答不停止任务。
- 发布：使用真实脚本与结果；无远端 adapter 时说明未接入，不展示示例健康数字。

## 恢复与边界

项目切换保留文件/提交/对话草稿，迟到结果只归属原项目。终端允许用户 cd，显示来源项目和启动目录，不将其描述为隔离沙箱。绑定变更要求重新进入新上下文，不重绑原会话。账号切换清理旧活动。应用重启显示未完成任务已中断，并保留实际日志。相关状态线框见 default.html。
