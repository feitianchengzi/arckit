# Automation Workspace - 交互规范

## 交互策略

### 核心任务

用户在 Automation Command Center 中先掌握当前用户可访问的项目，再查看项目产生的待办、自动化吞吐、当前运行、下一队列和需要人工判断的事项。系统按项目拉取待办并形成跨项目串行队列；Chat 仅在审查执行过程或处理人工中断时进入独立的 Intervention Workbench。

### 用户场景

1. 用户启动应用并查看项目列表，确认每个远端项目的任务数量、本地工作区绑定和是否参与自动化。
2. 用户选择“所有项目”观察跨项目队列，或选择单个项目聚焦其待办和运行历史；项目选择只改变观察范围。
3. 用户快速判断系统是否健康、正在做什么、下一项是什么、是否需要本人处理。主页面在首屏完成这些回答，不要求用户先选择任务。
4. 用户让系统持续自动运行。系统从参与自动化的项目中领取一项待处理任务，更新为进行中，执行 Runtime loop，完成后更新为已完成并领取下一项。
5. Runtime 需要授权、补充事实或产品判断。Command Center 把人工事项提升到首要关注区；用户进入 Intervention Workbench，处理后返回自动化主页面。
6. 用户主动审查某个任务的对话、计划、工具调用和证据。Intervention Workbench 以只读审查模式打开，用户显式选择介入后才出现可提交输入。
7. 项目、待办、状态写回或 Runtime 收束失败。系统保留已知事实与本地证据，冻结受影响的领取范围，并明确展示恢复责任和下一动作。

### 主路径

1. 应用恢复认证、当前用户项目列表、本地工作区绑定与 Runtime 执行状态。
2. 系统按项目拉取待办并保留 `project_id` 归属，再计算各项目状态数量与跨项目执行资格。
3. Command Center 展示项目列表、当前项目范围、自动化健康、需人工处理数量、运行中数量、待处理队列和最近完成结果。
4. 自动化开启且没有未收束任务时，系统按确定性规则从参与自动化的项目中选择一项符合条件的待处理任务。
5. 系统基于最新服务器版本条件式提交 `待处理 → 进行中`；领取冲突时刷新队列并选择下一项，不启动 Runtime。
6. 服务器确认进行中后，系统保存任务、项目、工作区和待启动 Runtime 的关联，再启动 Runtime loop。
7. Runtime 执行 Controller Plan、Worker、Controller Review、Gate 与 ledger writeback，并把阶段、事件和证据投影到主页面。
8. Runtime 与 ledger 均收束后，系统将远端任务更新为已完成；服务器确认后领取下一项。
9. 需要人工时，系统暂停当前推进并创建 attention item；用户在 Intervention Workbench 提交处理结果后，系统恢复当前任务并返回 Command Center。

### 决策点

- 项目是待办的一级来源。任务必须保留有效 `project_id`；无法解析项目归属的任务不进入队列，并进入数据异常提示。
- “所有项目”是聚合观察范围。选择项目只过滤指标、列表和历史，不隐式开启、暂停或重排自动化。
- 每个项目独立展示远端任务源状态、本地工作区绑定和自动化参与状态。只有任务源可用、工作区已绑定且项目参与自动化时，其待处理任务才有执行资格。
- 跨项目队列先按服务器优先级从高到低，再按确认进入待处理的时间从早到晚，最后按项目 ID 与任务 ID 稳定排序。同步引起的顺序变化只影响下一次领取，不改变当前运行。
- 待评审任务不进入自动队列。用户或任务服务器将其确认为待处理后，任务才获得自动执行资格。
- 待处理是唯一允许自动领取的新任务状态。进行中任务只用于当前执行或重启恢复，不与新任务并行。
- Command Center 的自动化总开关关闭时，系统继续同步和展示，不领取新任务。
- 人工介入是 Runtime 子状态，不直接等同于远端已阻塞。可恢复的人工等待保持任务为进行中；无法继续或依赖外部条件时才更新为已阻塞。
- 状态写回失败时，系统不推断服务器结果，不领取下一任务。
- 服务器已确认进行中但 Runtime 启动失败时，任务保持进行中；系统冻结队列并进入 Recovery Center，主动作是重试启动同一任务，不自动回退为待处理。
- 活动任务被外部更新为已取消、已阻塞、转移项目或失去权限时，系统请求 Runtime 在安全停止点收束，保留证据并冻结队列，直到服务器事实与本地运行重新一致。
- 多个客户端争抢同一任务时，以服务器条件式更新结果为准；失败的客户端不得创建本地 Runtime。
- 未绑定工作区、缺少项目权限或存在多个进行中任务时，系统进入需处理状态，不静默选择执行目标。
- 只读审查不会改变 Runtime；用户选择“介入当前运行”后才获得输入与控制能力。

### 信息架构

#### 应用壳

- 左侧固定导航依次展示自动化入口、项目列表、当前范围内的七种任务状态、任务源同步状态和本地 Runtime 健康。
- 项目列表首项为“所有项目”，其后展示当前用户可访问的项目；每行展示待处理数量和绑定/异常提示。
- 七种任务状态进入独立 Task Browser，并携带当前项目范围；它们不在 Command Center 内直接替换运行态势内容。
- 顶部命令栏展示当前项目范围、全局搜索、自动化总开关、同步和设置入口。

#### Command Center 首屏

1. 当前项目范围、项目数量和一句运行摘要。
2. 自动化健康、需人工处理、运行中、待处理四项核心指标。
3. 需要人工判断的 attention strip；没有人工事项时显示低强调的正常状态。
4. 当前运行的阶段条、当前动作和最近事件。
5. 下一队列表格，展示顺序、任务、所属项目、优先级、资格和状态。
6. 右侧展示项目源摘要、运行边界、完成证据和最近完成结果。

#### Intervention Workbench

- 左侧固定当前任务、人工请求、执行边界和已加载事实。
- 中间展示对话、计划、工具调用和输入区。
- 右侧展示 Runtime 阶段、证据、影响与返回自动化动作。
- 只读审查模式隐藏输入区；人工处理模式显示输入区与“提交并恢复自动化”。

### 状态流

#### 页面状态

`启动同步 → Command Center 待命 → 自动执行中 → 完成并续接`

`Command Center 待命 → 选择项目 → 项目范围视图 → 返回所有项目`

`Command Center → 选择任务状态 → Task Browser → 返回原项目范围`

`自动执行中 → 需要人工处理 → Intervention Workbench → 恢复自动执行`

`任意远端阶段 → 同步或写回异常 → 恢复中心 → 重试成功后返回原阶段`

`领取候选 → 条件式更新冲突 → 刷新队列 → 选择下一项`

`服务器已进行中 → Runtime 启动失败 → Recovery Center → 重试同一 Runtime 或标记阻塞`

`自动执行中 → 服务器状态外部变化 → 安全停止 → Recovery Center → 对齐后恢复队列`

`Command Center 待命 → 无可执行任务 → 保持监听或查看待评审`

#### 任务状态

`待评审(pending_review) → 待处理(pending) → 进行中(in_progress) → 已完成(completed) → 已验收(accepted)`

`待评审 / 待处理 / 进行中 → 已取消(cancelled)`

`进行中 → 已阻塞(blocked) → 待处理或进行中`

系统只自动执行 `待处理 → 进行中 → 已完成`。评审、验收、取消和阻塞处置由用户或任务服务器规则完成。

### 反馈与恢复

- 首次加载保留完整应用壳，用骨架与阶段文本说明正在恢复哪些事实。
- 自动领取成功后，页面摘要、指标、当前运行和任务行同步变化。
- 人工事项通过 attention strip、侧栏数量、任务行和桌面通知共同提示，但不自动打开 Chat。
- 用户提交人工处理后，Workbench 显示“正在交给 Controller”，确认 Runtime 接受后返回 Command Center。
- 拉取失败保留最近一次成功列表并标记数据时间；用户可重试同步。
- `待处理 → 进行中` 写回失败时不启动 Runtime。
- 条件式领取冲突时，候选任务显示“已由其他执行端领取”，刷新队列后继续选择下一项。
- `待处理 → 进行中` 已成功但 Runtime 启动失败时保留任务与启动意图关联，冻结下一任务并提供重试启动。
- `进行中 → 已完成` 写回失败时保留本地完成证据，冻结下一任务，直到服务器确认。
- 应用重启时优先恢复同一用户的进行中任务和关联 run；多个进行中任务触发人工恢复中心。
- 活动 Runtime 期间持续核对远端任务版本。终止性外部变化先停止本地执行，再允许处理下一任务。

### 输入输出边界

- 输入包括认证用户、当前用户可访问的远端项目、按项目返回的待办、本地工作区绑定、项目自动化参与状态、Runtime 状态和人工消息。
- 输出包括项目范围与项目状态摘要、远端任务状态更新、Runtime 阶段和事件、人工请求、证据摘要、完成结果与恢复状态。
- 任务服务器拥有项目、项目与任务归属及七种任务状态；Runtime 拥有本地工作区绑定、项目自动化参与状态、执行子状态、Controller/Worker 生命周期、事件和 ledger 证据。
- Renderer 不直接访问凭证或任意 API；远端请求通过主进程任务源服务完成。
- 自动化一次只拥有一个活动任务。状态不确定、人工 Gate、多个活动任务或回写失败都会阻止领取下一项。

### 线框投影要求

- `default.html` 投影应用壳、项目列表与范围切换、Command Center 待命、启动同步、自动执行中、人工介入入口、完成续接、空队列和异常恢复。
- `intervention-workbench.html` 投影人工处理模式与只读审查模式。
- `runtime-recovery.html` 投影领取冲突、Runtime 启动失败、停止当前运行、外部状态变化、多个进行中任务、任务源完整性异常和任务源会话失效。
- 三个投影保持同一任务上下文和返回路径；Chat 不成为主导航常驻入口。

## 导航流程

### 进入方式

- 应用启动进入 Automation Command Center。
- 桌面通知打开对应 attention item，不直接打开可输入 Chat。
- 项目列表切换项目范围；状态导航携带当前项目范围进入 Task Browser。

### 页面内导航

- “所有项目”展示跨项目聚合；选择单个项目后，指标、状态数量、队列和历史均限定到该项目。
- 项目选择只改变 Command Center 的观察范围；任务状态导航进入 Task Browser，两个动作均不改变自动队列策略。
- 当前运行、队列任务和最近完成项在同页打开 Inspector。
- “处理”进入 Intervention Workbench 的人工模式。
- “查看对话”进入 Intervention Workbench 的只读模式。

### 离开方式

- Workbench 的“返回自动化”恢复原任务和筛选位置。
- 提交人工处理后，系统自动返回当前运行详情。
- 设置、任务源登录和工作区绑定完成后返回原页面状态。

## 交互行为

### 自动化控制

- “暂停队列”只停止领取新任务，当前任务继续执行；按钮在暂停后变为“恢复队列”。
- “暂停此项目队列”只把该项目排除出后续领取，当前属于该项目的活动任务继续执行。
- “停止当前运行”请求 Runtime 在安全停止点收束；任务保持进行中并进入恢复状态，不自动取消、阻塞或退回待处理。
- 用户重新开启自动化时，系统先同步服务器，再恢复进行中任务或领取一项待处理任务。

### Command Center

- 项目列表固定在任务状态之前；项目行展示待处理数量、本地绑定或任务源异常。
- 项目行的自动化参与开关是独立显式操作，不能由选择项目触发。
- 指标卡可过滤关联任务，但不改变自动化策略。
- attention strip 始终位于当前运行和队列之前。
- 当前运行只展示四个可理解阶段、当前动作和最近三项事件；原始事件按需展开。
- 队列表格先固定当前进行中任务，再按优先级降序、确认时间升序、项目 ID 和任务 ID 排序。
- 最近完成项只展示结果摘要与审查入口，不自动打开对话。

### Intervention Workbench

- 人工请求固定展示原因、决策问题、影响范围和恢复条件。
- 用户提交后输入区锁定，直到 Controller 接受或返回错误。
- 用户不提交而返回时，任务保持等待人工，串行队列继续冻结。
- 只读模式不展示 Composer；“介入当前运行”需要明确操作。

## 弹窗/对话框

| 名称 | 触发 | data-kit | 内容 |
|------|------|----------|------|
| 停止当前运行 | 用户停止当前 Runtime | ConfirmationDialog | 停止影响、远端状态、确认与返回 |
| 多个进行中任务 | 启动恢复发现冲突 | Alert | 冲突任务、冻结原因、进入恢复中心 |
| 任务源会话失效 | 同步返回未认证 | Alert | 账号状态和设置入口 |
| 项目列表拉取失败 | 无法确认当前用户的项目范围 | 恢复中心 | 冻结新任务领取并重试项目同步 |
| 单项目待办拉取失败 | 其他项目仍可确认 | 项目行与队列提示 | 排除该项目并重试，不影响已确认项目 |
| 任务缺少有效项目归属 | 无法建立工作区与状态写回边界 | 数据异常提示 | 排除任务并查看原始来源 |
| 停止当前运行 | 用户主动停止 Runtime | ConfirmationDialog | 安全停止影响、任务仍为进行中和恢复入口 |
| 外部状态变化 | 活动任务的服务器版本发生终止性变化 | Alert | 安全停止进度和事实对齐动作 |

## 错误处理

| 错误类型 | 展示方式 | 恢复操作 |
|---------|---------|---------|
| 未登录或会话过期 | Command Center 状态条和设置入口 | 登录后重新同步 |
| 拉取任务失败 | 保留旧列表与数据时间 | 重试同步 |
| 更新为进行中失败 | 当前候选任务显示失败，不启动 Runtime | 重试状态更新 |
| 领取版本冲突 | 候选已被其他客户端修改 | 队列行反馈 | 刷新并选择下一项，不启动 Runtime |
| Runtime 启动失败 | 任务已是进行中但没有活动进程 | Recovery Center | 重试同一启动意图或标记阻塞 |
| 更新为已完成失败 | 显示本地完成、远端未确认，冻结下一任务 | 重试回写或查看证据 |
| Runtime 执行失败 | 当前运行展示失败阶段与责任方 | 重试、人工介入或标记阻塞 |
| 活动任务被外部修改 | Alert 与安全停止进度 | 对齐服务器事实后恢复队列 |
| 工作区未绑定 | 队列资格列显示不可执行 | 绑定本地工作区 |

## 加载策略

| 场景 | 策略 |
|------|------|
| 首次加载 | 保留应用壳，依次恢复账号、项目、各项目待办和 Runtime |
| 后台刷新 | 保留内容，在命令栏显示同步状态和数据时间 |
| 项目切换 | 立即保留项目壳与范围标题，再刷新该项目指标、待办和历史 |
| 状态更新 | 锁定当前任务动作，不阻塞查看其他内容 |
| Runtime 事件 | 增量更新阶段、当前动作与最近事件 |
| 远端任务状态 | 活动任务持续核对版本，终止性变化立即进入恢复状态 |
| Workbench 对话 | 先显示任务上下文，再按需载入完整 transcript |
