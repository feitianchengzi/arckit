# Automation Workspace - 交互规范

## 交互策略

### 核心任务

用户在 Automation Command Center 中沿用顶部产品集的全局观察范围，查看普通待办队列、验收问题队列、自动化吞吐、当前运行和需要人工判断的事项，并可用“仅看验收问题”聚焦独立问题工作。系统按项目拉取待办形成跨项目待办队列，并只从已完成待办的结果审查接收独立验收问题；Chat 仅在审查执行过程、提出验收问题或处理人工中断时进入独立的 Intervention Workbench。

### 用户场景

1. 未登录用户在独立 Login 页面选择邮箱或手机号并完成 Workshop 验证码登录；登录成功后进入 Command Center 并立即同步项目和待办。
2. 用户在任意 ADVANCE 页面从顶部产品集选择“项目集全部”或集合内单个项目；进入 Automation 后沿用同一范围，项目来源保留任务数量、本地工作区绑定和是否允许自动领取的状态。
3. 用户开启“仅看验收问题”后只看到验收问题指标、队列和进展；关闭后恢复普通待办与验收问题双队列总览。该筛选不改变执行仲裁。
4. 用户快速判断系统是否健康、正在做什么、下一项是什么、是否需要本人处理。主页面在首屏完成这些回答，不要求用户先选择任务。
5. 用户开启顶部“自动领取”总闸。系统从已经绑定工作区且明确允许自动领取的项目中领取一项待处理任务，更新为进行中，执行 Runtime loop，完成后更新为已完成并领取下一项。
6. Runtime 需要授权、补充事实或产品判断。Command Center 把人工事项提升到首要关注区；用户进入 Intervention Workbench，处理后返回自动化主页面。
7. 用户主动审查某个任务的执行消息与证据。Intervention Workbench 以只读审查模式打开，Runtime、Controller、Worker、工具摘要和人工输入在同一时间线中呈现；用户显式选择介入后才出现可提交输入。
8. 项目、待办、状态写回或 Runtime 收束失败。系统保留已知事实与本地证据，冻结受影响的领取范围，并明确展示恢复责任和下一动作；已有持久 Agent 对话时，用户可以在恢复卡直接补充说明并继续。
9. 用户判断某次运行是否存在不合理的 Token 或时间消耗。Workbench 按当前待办的 Run、round、turn 和执行 lane 展示逻辑总量、缓存输入、非缓存输入、输出、上下文增长与耗时，并把重复命令、无状态进展的上下文膨胀等异常作为可审查提示，而不是自动终止条件。
10. 用户从已完成任务的右侧详情面板查看全部验收问题、状态和最近进展，选择某一项进入其同一待办对话，或提出新的非空验收问题；已验收任务只显示验收通过。
11. Command Center 用独立区块展示普通待办队列与验收问题队列；用户可以分别查看 ready、running、awaiting human 和 blocked 数量，不会把验收问题计入待处理任务。
12. 用户在项目绑定选择器内没有合适的本地项目时，直接选择“添加本地项目”，完成目录选择后继续当前绑定流程。
13. 用户通过全局侧栏底部的头像打开原账号页面，查看任务源、会话和 Runtime 设置；Workshop 账户标题显示平台 current-user 的名称。
14. 用户希望亲自观察和参与当前任务时，从当前运行直接切换到交互式 Codex CLI；Desktop 安全停止 Runtime 后打开终端，用户在同一 Case 上继续，返回时再显式交还执行权或由已关闭 Case 自动进入收尾。

### 主路径

1. 应用先恢复本地活动任务、Run 与 canonical Case 检查点，再恢复任务源认证会话；未登录时停止远端操作和新任务领取，但仍呈现已关闭 Case、本地 commit 与待远端收尾状态。已登录或最近七天内会话可刷新时静默续期并进入 Automation Workspace，继续恢复当前用户项目列表与本地工作区绑定。
2. 用户在 Login 页面请求验证码并登录；成功后系统进入 Command Center，立即拉取当前用户、独立项目、组织项目及其待办。
3. 系统按项目拉取待办并保留 `project_id` 归属，再计算各项目状态数量与跨项目执行资格；Automation 消费顶部产品集的观察范围，不自行维护第二套项目筛选。
4. Command Center 展示当前顶部项目范围、自动化健康、需人工处理数量、活动执行、普通待办队列、验收问题队列、“仅看验收问题”和最近完成结果。
5. “自动领取”开启且没有未收束任务时，系统按确定性规则从允许自动领取的项目中选择一项符合条件的待处理任务；存在待处理任务但没有符合资格的项目时，Command Center 显示具体阻断原因和直接配置动作。
6. 系统基于最新服务器版本条件式提交 `待处理 → 进行中`；领取冲突时刷新队列并选择下一项，不启动 Runtime。
7. 服务器确认进行中后，系统保存任务、项目、工作区和待启动 Runtime 的关联，再启动 Runtime loop。
8. Runtime 在同一持久 Agent thread 中按 Gap 发起 turn、执行必要工具、完成 Gate 与 ledger writeback，并把语义进展聚合为当前待办的消息、阶段和证据摘要。
9. 用户选择“切换到 Codex CLI”时，系统安全停止当前 run，确认进程退出后在绑定工作区打开可交互终端，并以 `$using-arckit`、Case 标识和待办意图开始接管会话。
10. CLI 接管期间 Command Center 显示执行权所在、Case 和“恢复自动执行”；同步发现 Case 已关闭时直接进入 commit 与远端完成写回，未关闭时只有用户显式交还执行权才启动 fresh Runtime run。
11. Runtime 与 ledger 均收束后，系统将远端任务更新为已完成；服务器确认后领取下一项。
12. 需要人工时，系统暂停当前推进并创建 attention item；用户在 Intervention Workbench 提交处理说明后，系统恢复当前任务并返回 Command Center。

### 决策点

- 项目是待办的一级来源。任务必须保留有效 `project_id`；无法解析项目归属的任务不进入队列，并进入数据异常提示。
- 顶部“项目集全部”是当前 Workset 的聚合观察范围。选择单个项目只过滤指标、列表和历史，不隐式开启、暂停或重排自动化；Automation 不提供面板内项目范围选择器。
- 每个项目独立展示远端任务源状态、本地工作区绑定和“允许自动领取”状态。只有任务源可用、工作区已绑定且项目允许自动领取时，其待处理任务才有执行资格。
- 跨项目队列先按服务器优先级从高到低，再按确认进入待处理的时间从早到晚，最后按项目 ID 与任务 ID 稳定排序。同步引起的顺序变化只影响下一次领取，不改变当前运行。
- 待评审任务不进入自动队列。用户或任务服务器将其确认为待处理后，任务才获得自动执行资格。
- 待处理是唯一允许自动领取的新任务状态。进行中任务只用于当前执行或重启恢复，不与新任务并行。
- 顶部“自动领取”是全局领取总闸。关闭时系统继续同步和展示，但不领取新任务；它不替代项目级授权，也不停止当前活动任务。
- 项目级“允许自动领取”定义全局总闸覆盖的项目范围。选择项目、绑定工作区和开启全局总闸均不隐式改变该授权。
- “暂停领取”只在全局自动领取已开启时临时冻结后续领取，当前活动任务继续执行；恢复后沿用原有项目授权范围。
- “切换到 Codex CLI”转移当前 Case 的本地执行权，不改变远端任务状态、队列顺序或 Case State。动作必须先确认 Runtime 已停止，再打开交互式终端；启动失败时保留当前任务并进入恢复状态。
- CLI 接管不是人工 Gate，也不表示 Case 停止推进。CLI 会话由用户直接观察和输入；Desktop 不复制 Runtime 内部 thread，只显示接管状态、Case 标识以及“恢复自动执行”。
- “恢复自动执行”先读取 fresh Case State：active/Agent Case 启动 fresh Runtime run，需要 human 的 Case 进入人工事项，closed/resolved Case 直接进入 commit 与远端完成写回。关闭终端本身不触发任何一种结果。
- 全局自动领取已开启但待处理任务均因未绑定或未授权而不可执行时，页面显示“待处理任务尚不可领取”，列出首要原因并提供“允许此项目自动领取”或“配置项目”动作，不显示“队列已清空”。
- 人工介入是 Runtime 子状态，不直接等同于远端已阻塞。可恢复的人工等待保持任务为进行中；无法继续或依赖外部条件时才更新为已阻塞。
- 状态写回失败时，系统不推断服务器结果，不领取下一任务。
- 服务器已确认进行中但 Runtime 启动失败时，任务保持进行中；系统冻结队列并进入 Recovery Center。用户可重试同一任务；若该任务已有持久 Agent thread，也可输入说明并继续；系统不自动回退为待处理。
- 活动任务被外部更新为已取消、已阻塞、转移项目或失去权限时，系统请求 Runtime 在安全停止点收束，保留证据并冻结队列，直到服务器事实与本地运行重新一致。
- 多个客户端争抢同一任务时，以服务器条件式更新结果为准；失败的客户端不得创建本地 Runtime。
- 未绑定工作区、缺少项目权限或存在多个进行中任务时，系统进入需处理状态，不静默选择执行目标。
- 只读审查不会改变 Runtime；用户选择“介入当前运行”后才获得输入与控制能力。
- 旧完成结果保持只读；只有已完成待办的结果审查提供独立“提出验收问题”输入。提出后新增问题项和用户消息，不修改旧 Run、旧 Case 或来源待办状态；已验收待办不提供该输入。
- 验收问题队列和普通待办队列在信息架构、计数、筛选和排序上彼此独立；执行器是否空闲只影响问题项何时从 queued 进入 running，不改变它属于哪条队列。
- “仅看验收问题”只隐藏普通待办指标、列表和普通最近完成投影，保留全局当前运行与恢复状态；它不把验收问题计入待办状态，也不改变两条队列的排序和共享执行租约。
- 一个验收问题项显示稳定标识、来源待办、问题摘要、状态、当前 Case/Run、最近进展和阻塞/人工责任。多个问题项按创建时间分别展示，不合并为待办的一条备注。
- 每个远端待办拥有独立的 Workbench 会话。对话区只加载该待办的初始 Run、续接、人工介入和收束消息；项目默认 Chat、其他待办以及归属不明的历史消息不得混入。
- 同一待办的续接保持在同一 Workbench 会话和持久 Codex thread 中；fresh Case State 校正事实与授权，Run 或 turn 切换不创建新的待办对话。
- Workbench 以待办消息流为唯一主时间线。Runtime、Controller、Controller Review、Worker Agent、工具和用户通过消息来源标签区分，不按 Codex thread、Worker thread 或 JSON 事件类型拆成多个对话区。
- 计划、命令、文件变更、验证和 ledger 结果以有界摘要消息进入时间线；原始 JSON envelope、逐 token 文本 delta、逐字符 reasoning delta 和连续命令输出不直接呈现为普通用户消息。
- Workbench 的窗口壳、左右信息栏和底部输入区保持固定；只有中间消息列表沿垂直方向滚动。左右信息栏内容超出时在各自区域独立滚动，不推动输入区离开窗口。
- 消息流以 state-driven loop 状态和 Agent 自然语言输出为主。Round 开始、selected gap、执行阶段、transition 写回、等待人工和 Case 收束使用低噪声状态提示；Agent 的进度说明、判断与最终结果使用主要消息样式。
- Codex reasoning 只有形成非空可读文本时才进入时间线。流式 reasoning 保持展开并原位更新；完成后默认收起为“思考过程”，用户可以按需展开原文。空数组、空字符串和仅空白 reasoning 不产生占位行。
- Agent 受输出 schema 约束时，Runtime 把 Codex 返回的结构化 payload 识别为结构化结果，不把序列化 JSON 当作 Agent 正文气泡。Agent Loop 或收尾事件提供的自然语言 summary 作为正式 Agent 消息；结构化结果以低强调专用查看器保留 schema、关键字段和可展开原始数据，字段值保持 Codex 原值。
- 每次工具调用只占一行，展示状态、动作和目标，例如“读取 renderer.js”“运行 164 项测试”“更新 styles.css”；文件内容、命令 stdout/stderr、原始参数和协议载荷不进入主消息正文，需要诊断时从证据入口查看。
- 用户停留在消息底部时，新消息自动跟随；用户向上浏览后系统保持当前位置并显示“回到最新”，直到用户主动返回底部。
- 等价命令已经在同一工作区运行时，后续调用显示为“复用进行中的命令”，不新增重复进程；长命令等待期间由 Runtime 事件更新状态，不通过新增模型轮询制造进度。
- Token 用量异常只产生软提示和诊断入口。页面不提供基于固定 Token 总量或总轮次自动停止当前 Case 的默认控制；恢复边界仍由状态进展、证据和人工判断决定。
- 普通用户使用验证码登录，不直接填写 access token。服务地址和调试认证位于折叠的高级设置，不参与默认登录路径。
- 发送验证码与提交登录是两个独立动作。验证码发送成功后锁定重发按钮 60 秒，但目标地址和验证码仍可编辑。
- 未登录状态不渲染可交互的 Automation Workspace，也不提供关闭、返回或跳过登录门禁的动作。
- 只有连续超过七天没有有效登录活动、refresh token 缺失或过期、或服务端明确拒绝凭据时，会话才进入失效；系统不自动弹出可输入表单，主页面显示认证失效状态，用户通过“重新登录”进入设置覆盖层。临时网络和服务错误保留会话并进入同步恢复。
- 会话失效只阻止远端同步与写回，不阻止本地 canonical Case 对账。Case 已关闭时当前运行明确显示“Case 已完成，等待远端收尾”，责任方是 Automation Coordinator 与任务源，而不是 Runtime。
- 退出登录只清除远端身份与远端快照；本地项目、工作区绑定、Runtime 历史和代理设置保留。若存在活动任务，退出前展示影响确认并安全停止自动化。

### 信息架构

#### 应用壳

- 左侧固定导航展示产品级页面入口，不放置 Automation 项目列表、独立“添加本地项目”、独立“本地 Runtime”或独立“任务源”入口。
- 顶部产品集控件展示当前 Workset 名称、产品数量和“项目集全部”或单个项目范围，并提供“管理项目集”；该控件由 ADVANCE 应用壳共享。
- 左侧底部使用当前用户头像作为账号入口；点击后打开既有账号设置覆盖层。
- 左侧主导航不显示 `TASK STATUS` 或七种任务状态。七状态筛选在 Work 面板内打开 Task Browser 投影。
- 顶部命令栏展示全局产品集范围、管理项目集、全局搜索、“自动领取”总闸、同步和设置入口；总闸通过说明文本明确只作用于已绑定且已授权的项目。
- 会话失效时，头像账户入口和顶部同步状态共同显示“认证失效”，自动化开关不可用；本地运行历史仍可查看。未登录状态由 Login 页面承载，不显示应用壳。

#### 账号设置覆盖层

- 已登录态展示 Workshop current-user 的平台显示名、当前账号摘要、最近同步状态和退出登录动作；不使用本地配置名、认证目标或任务源标签替代平台显示名，token 与过期时间不直接展示。
- 高级连接设置默认折叠，承载服务根地址与服务名；调试认证能力不出现在普通登录主路径。
- 会话失效态保留账号摘要和失效原因，主动作是重新登录；关闭覆盖层返回只读的 Command Center。
- 账号覆盖层保留原有任务源、会话和 Runtime 设置内容；入口迁移不改变页面能力。

#### 项目绑定选择器

- 选择器列出 Desktop 已有本地项目，并提供同层级“添加本地项目”动作。
- 添加目录成功后，新本地项目立即加入选择器并保持选中，用户可直接确认当前 Workshop Project 的绑定。
- 目录选择取消、初始化失败或路径不可用时保留绑定选择器和原选择，不创建半成品绑定。

#### Command Center 首屏

1. 当前项目范围、项目数量和一句运行摘要。
2. 自动领取状态、需人工处理、运行中、可领取待办四项核心指标。
3. 需要人工判断的 attention strip；没有人工事项时显示低强调的正常状态。
4. 当前运行的阶段条、当前动作和最近事件。
5. 下一队列表格，展示顺序、任务、所属项目、优先级、资格和状态。
6. 右侧展示项目源摘要、运行边界、完成证据和最近完成结果。

#### Intervention Workbench

- 左侧固定当前任务、人工请求、执行边界和已加载事实。
- 中间由固定会话标题、独立滚动的消息列表和固定底部输入区组成；消息增长不改变窗口整体高度，也不带动左右栏或 Composer 滚出视口。
- 消息列表按“Loop 状态提示 → 可折叠思考过程 → Agent 正式输出 → 结构化结果查看器 → 单行工具活动 → 用户输入”组织视觉层级；状态提示、思考过程、结构化查看器和工具活动不使用与 Agent 正文同等体量的消息卡片。
- 右侧展示 Runtime 阶段、证据、Token 用量、软异常、影响与返回自动化动作。
- 普通只读审查隐藏运行控制输入；人工处理模式显示输入区与“提交并恢复自动化”。只有 completed 结果审查显示独立验收问题 Composer；accepted 结果审查保持只读并显示验收通过。
- 对话顶部固定展示当前远端任务 ID、task session 和 Run/续接范围，使用户能够确认所见 transcript 不包含其他待办。
- 消息来源标签只解释“谁产生了这条信息”，thread、turn、round 和 task id 保留为诊断元数据，不成为用户浏览消息的前置层级。
- 工具行使用一致的单行结构：状态图标、动词、目标简称和可选结果摘要。读取类只显示文件路径；命令类只显示命令意图与结果；超过一行的输出只能进入按需证据视图。
- 思考过程使用原始 reasoning 文本，不用 Runtime 生成摘要替代；结构化查看器按 schema 展示原始字段值，并提供二级“查看原始 JSON”，不复制或重写 Agent 的正式自然语言消息。
- Token 用量摘要先区分逻辑总量、缓存输入、非缓存输入和输出，再按 Controller、Builder、Verifier、Commit lane 下钻到 round 与 turn；缓存命中不与非缓存输入合并成单一成本数字。

### 状态流

#### 页面状态

`启动同步 → Command Center 待命 → 自动执行中 → 完成并续接`

`应用启动 → Login 恢复会话 → 未登录表单 → 发送验证码 → 提交验证码 → 登录成功 → Command Center 自动同步`

`已登录 → access token 临近过期或首次 401 → 后台刷新并重试 → 保持当前页面`

`已登录 → 七天内发生有效登录活动 → 服务端轮换 refresh token → 会话窗口滚动续期`

`已登录 → 临时刷新失败 → 保留可恢复会话 → 同步恢复 → 重试成功后继续`

`已登录 → 连续超过七天无活动或 refresh token 被明确拒绝 → Command Center 只读 → 重新登录 → 自动同步`

`已登录 → 退出确认 → 清除远端身份与快照 → Login`

`任意 ADVANCE 页面 → 顶部产品集范围 → 选择 Workset 项目 → Automation 项目范围视图 → 返回项目集全部`

`Command Center 双队列 → 开启仅看验收问题 → 验收问题队列与进展 → 关闭筛选 → 双队列`

`Command Center → 选择任务状态 → Task Browser → 返回原项目范围`

`自动执行中 → 需要人工处理 → Intervention Workbench → 恢复自动执行`

`自动执行中 → 切换到 Codex CLI → 安全停止 Runtime → CLI 接管 → 交还执行权或 Case 已关闭 → fresh Runtime 或完成收尾`

`应用重启 → 本地 Case 对账 → Case 已关闭 → commit pending/running/completed → 任务源认证不可用 → 等待远端收尾 → 认证恢复 → 远端 completed`

`任意远端阶段 → 同步或写回异常 → 恢复中心 → 重试成功后返回原阶段`

`领取候选 → 条件式更新冲突 → 刷新队列 → 选择下一项`

`服务器已进行中 → Runtime 启动失败 → Recovery Center → 重试同一 Runtime / 补充说明并继续 / 标记阻塞`

`Recovery Center 输入说明 → 校验当前 task session 与持久 thread → 启动同 thread 新 Run → 打开 Workbench 并显示“你”的说明`

`自动执行中 → 服务器状态外部变化 → 安全停止 → Recovery Center → 对齐后恢复队列`

`Command Center 待命 → 无可执行任务 → 保持监听或查看待评审`

`自动领取开启 → 存在待处理但没有符合资格的项目 → 展示项目阻断原因 → 允许项目自动领取或绑定工作区 → 立即重新计算并领取`

#### 任务状态

`待评审(pending_review) → 待处理(pending) → 进行中(in_progress) → 已完成(completed) → 已验收(accepted)`

`验收问题 queued → running → awaiting_human | blocked | resolved | cancelled`

两条状态流仅通过来源引用、同一待办会话和执行租约关联；验收问题状态不回写来源待办状态。

`待评审 / 待处理 / 进行中 → 已取消(cancelled)`

`进行中 → 已阻塞(blocked) → 待处理或进行中`

系统只自动执行 `待处理 → 进行中 → 已完成`。评审、验收、取消和阻塞处置由用户或任务服务器规则完成。

### 响应与恢复

- 首次加载先在 Login 页面展示会话恢复进度；确认认证有效后才显示应用壳并恢复远端事实。
- 验证码发送、登录和退出各自锁定对应动作，不锁定设置覆盖层中的无关设置。
- 登录成功后覆盖层关闭，顶部同步状态立即进入“同步中”；同步失败时仍保留已登录状态并提供重试。
- token 后台刷新不打断用户；临时网络或服务错误保留可恢复会话并显示同步恢复，只有超过七天无活动、凭据缺失/过期或服务端明确拒绝时才显示认证失效提示。
- 自动领取成功后，页面摘要、指标、当前运行和任务行同步变化。
- 自动领取开启但候选被项目条件阻止时，健康状态、attention strip、队列空态和任务 Inspector 显示同一个资格原因；用户完成项目授权或绑定后立即重新计算队列。
- 人工事项通过 attention strip、侧栏数量、任务行和桌面通知共同提示，但不自动打开 Chat。
- 用户提交人工处理后，原文立即作为“你”的消息进入当前时间线，Workbench 显示“正在交给 Controller”，确认 Runtime 接受后返回 Command Center。
- 拉取失败保留最近一次成功列表并标记数据时间；用户可重试同步。
- `待处理 → 进行中` 写回失败时不启动 Runtime。
- 条件式领取冲突时，候选任务显示“已由其他执行端领取”，刷新队列后继续选择下一项。
- `待处理 → 进行中` 已成功但 Runtime 启动失败时保留任务与启动意图关联，冻结下一任务并提供重试启动。
- Runtime result validation、trusted ledger Gate 或 transition 拒绝时，Runtime 不展示 Case 完成、不启动 Git closeout；可修正拒绝先在同一 Agent thread 上进入可见的“Agent repair n/N”状态，向 Agent 提供具体 issue path、reason、被拒 claim 和 fresh canonical state，要求只替换无效 claim 而不重复实现。repair 成功后继续原待办；仅预算耗尽或错误不可修正时进入恢复卡，恢复卡优先展示最终 rejection 原因，不使用未接受的成功 handoff 文案。
- 已绑定持久 Agent thread 的 Runtime 失败卡展示说明输入与“补充说明并继续”；空白说明不提交。提交成功后原文进入当前待办时间线并打开只读审查，新 Run 继续同一 thread；启动失败则保留输入场景和恢复项。
- `进行中 → 已完成` 写回失败时保留本地完成证据，冻结下一任务，直到服务器确认。
- 应用重启时先恢复本地活动任务、关联 Run、canonical Case 和 commit 检查点，再恢复远端认证与任务快照；多个进行中任务触发人工恢复中心。
- closed Case 立即结束 Runtime 执行态；commit 已完成且任务源不可用时显示等待远端收尾，不生成“Runtime 丢失”恢复项，也不重复执行 commit。
- 活动 Runtime 期间持续核对远端任务版本。终止性外部变化先停止本地执行，再允许处理下一任务。

### 输入输出边界

- 输入包括验证码类型、邮箱或手机号、验证码、Workshop current-user 平台显示名、当前用户可访问的远端项目、当前 Workset、按项目返回的待办、本地工作区绑定、项目自动领取授权状态、Runtime 状态和人工消息。
- 输出包括项目范围与项目状态摘要、远端任务状态更新、待办级执行消息流、Runtime 阶段、人工请求、证据摘要、完成结果与恢复状态。
- 任务服务器拥有项目、项目与任务归属及七种任务状态；Runtime 拥有本地工作区绑定、项目自动领取授权状态、全局领取与暂停状态、执行子状态、Controller/Worker 生命周期、事件和 ledger 证据。
- Renderer 不直接访问凭证或任意 API；远端请求通过主进程任务源服务完成。
- 自动化一次只拥有一个活动任务。状态不确定、人工 Gate、多个活动任务或回写失败都会阻止领取下一项。

## 导航流程

### 进入方式

- 应用启动先进入 Login 会话恢复状态；已认证时进入 Automation Command Center，未登录时留在 Login。
- 桌面通知打开对应 attention item，不直接打开可输入 Chat。
- 顶部产品集控件切换所有 ADVANCE 页面的观察范围；Automation 面板不重复提供项目范围选择器。

### 页面内导航

- “项目集全部”展示当前 Workset 的跨项目聚合；选择单个项目后，指标、状态数量、队列和历史均限定到该项目。
- 项目选择只改变 Command Center 的观察范围；Work 面板的任务状态筛选进入 Task Browser，两种观察动作均不改变自动队列策略。
- 当前运行、队列任务和最近完成项在同页打开 Inspector。
- “处理”进入 Intervention Workbench 的人工模式。
- “查看对话”进入 Intervention Workbench 的只读模式。
- “切换到 Codex CLI”从当前运行直接打开目标项目的交互式 Codex 会话；返回 Command Center 后仍能看到该待办由 CLI 接管。

### 离开方式

- Workbench 的“返回自动化”恢复原任务和筛选位置。
- 提交人工处理后，系统自动返回当前运行详情。
- 账号设置、任务源登录和工作区绑定完成后返回原页面状态；从绑定选择器添加本地项目不会离开当前绑定流程。

## 交互行为

### 自动化控制

- 顶部“自动领取”控制是否主动领取新任务。关闭后继续同步、展示和完成当前任务；重新开启时先同步服务器，再恢复进行中任务或领取一项待处理任务。
- “暂停领取”只停止领取新任务，当前任务继续执行；按钮在暂停后变为“继续领取”。
- 项目级“允许自动领取”是独立显式授权。关闭后该项目退出后续领取，当前属于该项目的活动任务继续执行。
- “停止当前运行”请求 Runtime 在安全停止点收束；任务保持进行中并进入恢复状态，不自动取消、阻塞或退回待处理。
- “切换到 Codex CLI”先锁定动作并显示“正在安全停止”，确认 Runtime 进程退出后打开终端并进入 `cli_handoff`；失败时不假装已经交接。
- `cli_handoff` 中“恢复自动执行”是显式交还执行权。系统先对账 Case，再决定启动 fresh Runtime、进入人工事项或直接完成收尾。

### 账号与会话

- “发送验证码”要求合法的邮箱或手机号；发送中禁用重复提交，成功后显示 60 秒倒计时。
- “登录”要求目标地址和验证码均非空；提交期间锁定登录按钮，失败信息显示在表单内并保留输入。
- 登录成功后清空验证码字段、关闭设置覆盖层并触发全量同步；项目或待办同步失败不回滚登录。
- “退出登录”在没有活动任务时直接清除远端身份与快照；存在活动任务时先显示影响确认，确认后请求安全停止再退出。
- 会话刷新由主进程静默执行；Renderer 只消费 `logged_out`、`authenticated`、`refreshing`、`expired` 四类可展示状态。
- 成功的验证码登录、应用启动时成功恢复远端会话和成功的 token 刷新会推进最近登录活动时间并将会话窗口滚动至七天；本地页面浏览、普通业务读取、失败请求和离线操作不推进窗口。
- 临时刷新错误保持 `authenticated` 或可恢复状态并允许重试，不清除 refresh token；凭据已过期、被服务端明确拒绝或超过七天无活动时才进入 `expired`。

### Command Center

- 项目来源摘要位于 Automation 内容区，展示当前顶部范围内各项目的待处理数量、本地绑定、任务源异常和“允许自动领取”状态；它不是范围选择器。
- “仅看验收问题”位于 Automation 页面头部。开启时隐藏普通待办专属指标和列表，但始终显示当前活动执行、恢复项以及所选范围。
- 自动领取已开启但候选均不可执行时，attention strip 优先显示候选数量、首个阻断原因和直接修复动作，不使用正常空队列提示。
- 指标卡可过滤关联任务，但不改变自动化策略。
- attention strip 始终位于当前运行和队列之前。
- 当前运行只展示四个可理解阶段、当前动作和最近三条语义消息；细粒度事件不进入主页面。
- 队列表格先固定当前进行中任务，再按优先级降序、确认时间升序、项目 ID 和任务 ID 排序。
- 最近完成项只展示结果摘要与审查入口，不自动打开对话。

### Intervention Workbench

- 人工请求固定展示原因、决策问题、影响范围和恢复条件。
- Workbench 打开时必须携带当前任务的 session 归属；归属不明的消息默认隐藏并进入数据异常证据，不回退加载项目默认会话。
- 同一待办的初始执行、续接、人工输入、恢复与收束按时间合并展示，并在每段 Run 或 continuation 边界显示分隔标记。
- state-driven loop 的 Round、gap、阶段、writeback 与 handoff 变化呈现为紧凑状态行；Agent 的进度说明、判断和最终结果呈现为主要内容消息，用户输入保持独立对齐。
- 非空 reasoning 在生成期间展开并原位更新，完成后默认收起且可展开；没有可读文本的 reasoning 不进入消息列表。
- `arckit-agent-loop-result/v1`、`arckit-task-closeout-result/v1` 等 schema-bound 输出进入专用结构化查看器。查看器显示 schema 和原始关键字段，原始 JSON 保留在二级展开区；对应 Runtime 语义事件的自然语言 summary 单独作为 Agent 正式消息。
- 每个工具调用呈现为一条不换行的活动行。读取文件时只显示“读取 + 相对路径”；搜索、编辑、构建和测试只显示动词、目标及成功/失败摘要，不渲染文件正文、完整 diff、stdout/stderr 或原始 tool payload。
- 流式 Agent 输出更新当前消息，不为每个 delta 新建 DOM 节点；工具活动只在 started/completed/failed 状态变化时更新同一行。
- 消息列表与页面壳分离滚动。用户位于底部附近时保持最新消息可见；用户主动上滚后停止自动跟随并显示回到底部入口。
- 用量 Inspector 默认展示当前 Run 总览；用户可按 lane、round 和 turn 展开，查看 Token 构成、上下文占用、模型耗时、命令等待和工具调用次数。
- 当检测到重复命令、长命令期间的模型轮询、上下文持续增长但 Case State 无进展、Worker 目标变化仍复用 thread 或 Review 引用失败时，Inspector 显示可解释的软异常和证据链接；提示本身不暂停 Runtime。
- 用户提交后输入区锁定，直到 Controller 接受或返回错误。
- 用户不提交而返回时，任务保持等待人工，串行队列继续冻结。
- 普通只读模式不展示运行控制 Composer；“介入当前运行”需要明确操作。completed 结果审查的验收问题 Composer 独立创建问题项，不改变旧运行；accepted 结果审查不显示 Composer。

## 弹窗/对话框

| 名称 | 触发 | data-kit | 内容 |
|------|------|----------|------|
| 停止当前运行 | 用户停止当前 Runtime | ConfirmationDialog | 停止影响、远端状态、确认与返回 |
| CLI 启动失败 | Runtime 已停止但终端或 Codex 无法启动 | Recovery Center | 重试切换、恢复自动执行或标记阻塞 |
| 多个进行中任务 | 启动恢复发现冲突 | Alert | 冲突任务、冻结原因、进入恢复中心 |
| 任务源会话失效 | 同步返回未认证 | Alert | 账号状态和设置入口 |
| 活动任务期间退出 | 用户在已登录设置中退出 | ConfirmationDialog | 当前任务、远端状态、队列冻结影响与取消/继续退出 |
| 项目列表拉取失败 | 无法确认当前用户的项目范围 | 恢复中心 | 冻结新任务领取并重试项目同步 |
| 单项目待办拉取失败 | 其他项目仍可确认 | 项目行与队列提示 | 排除该项目并重试，不影响已确认项目 |
| 任务缺少有效项目归属 | 无法建立工作区与状态写回边界 | 数据异常提示 | 排除任务并查看原始来源 |
| 停止当前运行 | 用户主动停止 Runtime | ConfirmationDialog | 安全停止影响、任务仍为进行中和恢复入口 |
| 外部状态变化 | 活动任务的服务器版本发生终止性变化 | Alert | 安全停止进度和事实对齐动作 |

## 错误处理

| 错误类型 | 展示方式 | 恢复操作 |
|---------|---------|---------|
| 未登录 | Login 全页门禁 | 登录成功后进入 Command Center 并同步 |
| 会话过期 | Command Center 状态条和设置入口 | 重新登录后同步 |
| 验证码发送失败 | 设置表单内联错误 | 修正目标地址或重试 |
| 验证码错误或过期 | 设置表单内联错误并保留目标地址 | 重新输入或重新发送验证码 |
| token 临时刷新失败 | 主页面同步恢复提示并保留旧快照 | 网络或服务恢复后重试，不要求重新登录 |
| token 已过期或被拒绝 | 主页面认证失效提示与只读快照 | 重新登录后全量同步 |
| 拉取任务失败 | 保留旧列表与数据时间 | 重试同步 |
| 更新为进行中失败 | 当前候选任务显示失败，不启动 Runtime | 重试状态更新 |
| 领取版本冲突 | 候选已被其他客户端修改 | 队列行提示 | 刷新并选择下一项，不启动 Runtime |
| Runtime 启动失败 | 任务已是进行中但没有活动进程 | Recovery Center | 重试同一启动意图或标记阻塞 |
| Codex CLI 启动失败 | Runtime 已安全停止但交互终端未启动 | 当前任务恢复提示 | 重试切换或从 fresh Case State 恢复 Runtime |
| Case 对账失败 | CLI 接管后无法读取对应 active/closed Case | 当前任务恢复提示 | 查看 Case 证据并重试，不从旧 run 推断完成 |
| 更新为已完成失败 | 显示本地完成、远端未确认，冻结下一任务 | 重试回写或查看证据 |
| Runtime 执行失败 | 当前运行展示失败阶段与责任方 | 重试、人工介入或标记阻塞 |
| 活动任务被外部修改 | Alert 与安全停止进度 | 对齐服务器事实后恢复队列 |
| 工作区未绑定 | 队列资格列显示不可执行 | 绑定本地工作区 |
| 项目未允许自动领取 | attention strip、队列空态和任务 Inspector 显示同一原因 | 允许此项目自动领取 |

## 加载策略

| 场景 | 策略 |
|------|------|
| 首次加载 | Login 先恢复账号；认证有效后再显示应用壳并恢复项目、各项目待办和 Runtime |
| 登录提交 | 保留设置覆盖层和表单内容，只锁定认证动作 |
| token 刷新 | 后台刷新，不替换当前内容；临时失败保留会话并进入同步恢复，凭据失效或超过七天无活动才进入认证失效态 |
| 后台刷新 | 保留内容，在命令栏显示同步状态和数据时间 |
| 项目切换 | 顶部产品集先更新全局范围标题，再刷新 Automation 的该项目指标、待办和历史 |
| 仅看验收问题 | 保留活动执行与恢复状态，就地切换普通待办投影和验收问题投影，不重新同步项目 |
| 状态更新 | 锁定当前任务动作，不阻塞查看其他内容 |
| Runtime 事件 | 在内存中合并高频 delta，并按有界刷新节奏更新当前 Agent 消息、非空 reasoning、结构化结果查看器、Loop 状态行、单行工具活动、命令等待与 Token 用量；同一 thread 的累计快照只取最新值聚合，避免重复计数 |
| CLI 接管同步 | 只读取绑定 Case 的 canonical active/closed 状态；不轮询或解析终端 transcript，不以终端进程退出推断完成 |
| 远端任务状态 | 活动任务持续核对版本，终止性变化立即进入恢复状态 |
| Workbench 对话 | 先确认当前待办的 task session，再载入该待办跨 Run、round、turn 和 thread 聚合后的消息流；主时间线只保留 Loop 状态、非空可折叠 reasoning、Agent 正式输出、专用结构化结果、用户输入和单行工具摘要，不读取项目默认会话，也不把原始 delta、文件正文或命令输出作为普通界面消息 |
| Workbench 用量 | 先显示当前 Run 的分项总览，再按需加载 lane、round 与 turn 明细和软异常证据 |
